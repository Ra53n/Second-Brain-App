# Тестовые запросы «День 10» — micro-model first (30 шт.)

Ручной прогон двухуровневого инференса в чате тюнинга (Тюнинг → «Встречи» → «Чат»).
Каждый блок — готовый запрос: скопируйте текст из код-блока в поле ввода и отправьте.

## Подготовка (пресет для видео)

1. «Очистить чат» — чистая статистика сессии.
2. База: `Qwen2.5-3B-Instruct-4bit`, вариант «Тюн» (micro-модель = тюн-3B).
3. Чип «Эскалация» включён; цель — «Тюн Qwen2.5-7B-Instruct-4bit (локально)».
4. Тумблеры пайплайна — на ваш выбор (система корректна при любых); для видео
   показательны «Проверки» + «Скоринг»: эскалация уходит по UNSURE/FAIL/битому JSON.
5. «Стадии» — по желанию (можно показать сравнение моно/мульти на паре запросов).

Где смотреть цифры задания: блок «Сессия» → строка **«Micro-first»** (micro закрыла
N из M, fallback K, вызовов сильной LLM X, latency micro → каскад) и строка
«Эскалация»; на каждом ответе — чип вердикта и бейдж эскалации/стадий.

Ожидания ниже — ориентир, не эталон: живые модели могут отвечать по-разному; смысл
теста — увидеть, что простые запросы закрывает micro, а сложные уходят в fallback.

## Простые (12) — явные поручения, ожидание: micro закрывает сама

### П1 — одно поручение, срок назван

```
Руководитель проекта: Подводим итог по прототипу. Промышленный дизайнер, подготовь, пожалуйста, обновлённую схему корпуса к пятнице.
Промышленный дизайнер: Хорошо, к пятнице сделаю.
```

### П2 — одно поручение без срока

```
Тимлид: Аналитик, собери статистику по ошибкам за последний релиз.
Аналитик: Принято, займусь.
```

### П3 — два поручения подряд

```
Руководитель проекта: Так, договорились. Дизайнер интерфейса готовит макет главного экрана. Маркетолог, с тебя список конкурентов к среде.
Дизайнер интерфейса: Ок.
Маркетолог: Сделаю к среде.
```

### П4 — поручение с уточнением

```
Тимлид: Нужно проверить, почему падает сборка на CI.
Аналитик: Это ко мне?
Тимлид: Да, посмотри логи и отпиши в чат.
Аналитик: Хорошо, посмотрю логи и отпишу.
```

### П5 — короткое, срок «завтра»

```
Руководитель проекта: Маркетолог, пришли завтра черновик пресс-релиза.
Маркетолог: Договорились, завтра пришлю.
```

### П6 — поручение после обсуждения

```
Дизайнер интерфейса: Мне кажется, кнопки слишком мелкие.
Промышленный дизайнер: Согласен, на пульте они будут неудобны.
Руководитель проекта: Ладно. Дизайнер интерфейса, увеличь кнопки в следующей версии макета.
Дизайнер интерфейса: Принято.
```

### П7 — исполнитель по имени роли, срок «к следующей встрече»

```
Руководитель проекта: Аналитик, к следующей встрече подготовь сравнение двух вариантов меню.
Аналитик: Сделаю к следующей встрече.
```

### П8 — самоназначение

```
Тимлид: Кто возьмёт настройку окружения?
Аналитик: Я возьму, сегодня настрою.
Тимлид: Отлично, зафиксировали.
```

### П9 — поручение в конце длинной реплики

```
Руководитель проекта: По бюджету мы укладываемся, по срокам тоже, презентацию заказчик согласовал без правок, так что двигаемся дальше. Промышленный дизайнер, закажи образцы пластика для корпуса.
Промышленный дизайнер: Закажу.
```

### П10 — два исполнителя, разные задачи

```
Тимлид: Распределим: Дизайнер интерфейса рисует экран настроек, Аналитик пишет сценарии приёмки.
Дизайнер интерфейса: Беру экран настроек.
Аналитик: Сценарии за мной.
```

### П11 — срок с датой

```
Руководитель проекта: Маркетолог, подготовь план запуска к 15 числу.
Маркетолог: К пятнадцатому будет.
```

### П12 — подтверждённое решение

```
Руководитель проекта: Решили: Тимлид разбивает проект на этапы и присылает всем план.
Тимлид: Да, разобью и пришлю.
```

## Пограничные (9) — поручений нет, ожидание: пустой список `{"action_items": []}`

### Г1 — обсуждение без решения

```
Маркетолог: Мне кажется, скроллер удобнее кнопок.
Промышленный дизайнер: Не уверен, кнопки надёжнее.
Дизайнер интерфейса: Давайте ещё подумаем, оба варианта имеют смысл.
```

### Г2 — вопросы без ответов

```
Руководитель проекта: Кто-нибудь смотрел отчёт по продажам? Когда у нас дедлайн по смете?
Тимлид: Надо уточнить у финансов.
```

### Г3 — идея без исполнителя

```
Аналитик: Было бы здорово добавить голосовое управление.
Дизайнер интерфейса: Интересная мысль, но это сильно усложнит проект.
Руководитель проекта: Запишем как идею на будущее.
```

### Г4 — «поручено всем» (assignee = null не делает это поручением каждого)

```
Руководитель проекта: Прошу всех до конца недели посмотреть черновик спецификации и оставить комментарии.
Тимлид: Посмотрим.
```

### Г5 — отчёт о сделанном (прошлое, не поручение)

```
Аналитик: Я вчера закончил разметку данных и выложил отчёт.
Тимлид: Отлично, спасибо.
```

### Г6 — отклонённое предложение

```
Маркетолог: Может, Дизайнер интерфейса сделает тёмную тему к релизу?
Дизайнер интерфейса: Не успею, давайте после релиза.
Руководитель проекта: Согласен, откладываем.
```

### Г7 — светская часть встречи

```
Руководитель проекта: Всем привет, начнём через пару минут, ждём Маркетолога.
Тимлид: Он написал, что задерживается на пять минут.
Аналитик: Хорошо, я пока налью кофе.
```

### Г8 — гипотетика

```
Тимлид: Если заказчик попросит локализацию, придётся кому-то заняться переводами.
Аналитик: Да, но пока таких запросов не было.
```

### Г9 — мнения о сроках без договорённости

```
Промышленный дизайнер: Думаю, на корпус уйдёт недели две.
Руководитель проекта: Посмотрим, пока не фиксируем.
```

## Сложные (9) — длинные/косвенные, ожидание: часть уйдёт в fallback

### С1 — поручения вперемешку с обсуждением, срок «до конца спринта»

```
Руководитель проекта: Начнём с открытых вопросов. По анимации заставки мы так и не решили, оставляем ли её.
Дизайнер интерфейса: Я бы оставил, она почти готова.
Тимлид: Она тормозит на слабых устройствах. Предлагаю так: Дизайнер интерфейса упрощает анимацию, а я до конца спринта профилирую производительность на старых моделях.
Руководитель проекта: Принято, так и делаем. И ещё: Аналитик, посмотри, сколько пользователей реально на старых устройствах.
Аналитик: Посмотрю.
Маркетолог: А по рекламной кампании когда поговорим?
Руководитель проекта: На следующей встрече.
```

### С2 — косвенный исполнитель («кто-то из…» — assignee null)

```
Тимлид: Тесты на оплату разъехались, надо чинить.
Руководитель проекта: Пусть кто-то из аналитиков возьмёт и починит до релиза.
Тимлид: Договорились, найдём человека.
```

### С3 — срок «к следующей планёрке», исполнитель назван позже задачи

```
Руководитель проекта: Нужно сравнение тарифных сеток конкурентов, без него не двинемся по цене. К следующей планёрке. Маркетолог, это твоё.
Маркетолог: Понял, подготовлю.
Тимлид: А по технической части у нас всё готово, могу показать хоть сейчас.
Руководитель проекта: Покажешь после.
```

### С4 — отменённое и заменённое поручение

```
Руководитель проекта: Дизайнер интерфейса, сделай две версии логотипа.
Дизайнер интерфейса: Хорошо.
Маркетолог: Стойте, заказчик вчера прислал утверждённый логотип, версии не нужны.
Руководитель проекта: Тогда отбой. Вместо этого, Дизайнер интерфейса, вставь утверждённый логотип во все макеты.
Дизайнер интерфейса: Сделаю.
```

### С5 — длинный многоспикерный, три поручения в разных местах

```
Руководитель проекта: Пробежимся по статусам. Промышленный дизайнер?
Промышленный дизайнер: Корпус в работе, жду образцы. Кстати, нужен кто-то, кто согласует цвета с брендбуком.
Маркетолог: Это я могу, согласую цвета с брендбуком на этой неделе.
Руководитель проекта: Отлично. Тимлид?
Тимлид: Прошивка стабильна. Но Аналитик, мне нужны от тебя граничные сценарии по датчику, без них не закрою тестирование.
Аналитик: Напишу граничные сценарии.
Руководитель проекта: И последнее: я подготовлю повестку финальной презентации, разошлю всем в четверг.
```

### С6 — вложенная цитата чужого поручения (не поручение этой встречи)

```
Аналитик: На прошлой встрече Руководитель проекта говорил, что Тимлид должен был обновить план-график, но я его так и не видел.
Тимлид: Обновил, просто забыл разослать. Сейчас пришлю.
Руководитель проекта: Хорошо. И раз уж вспомнили: Аналитик, сверь план-график с реальными сроками, когда Тимлид пришлёт.
Аналитик: Сверю.
```

### С7 — условное поручение

```
Руководитель проекта: Если завтра заказчик утвердит смету, Маркетолог сразу запускает предзаказы.
Маркетолог: Готов, жду утверждения.
Тимлид: А если не утвердит?
Руководитель проекта: Тогда соберёмся отдельно.
```

### С8 — срок в необычной формулировке, два поручения одному исполнителю

```
Тимлид: Аналитик, с тебя две вещи: во-первых, добей отчёт по нагрузочному тестированию — крайний срок, как договаривались, до демо; во-вторых, заведи задачи на все найденные дефекты.
Аналитик: Отчёт до демо, задачи заведу сегодня.
Маркетолог: Демо в этот четверг, я правильно помню?
Тимлид: Да.
```

### С9 — шумный фрагмент с перебиваниями

```
Промышленный дизайнер: …и тогда крепление будет — подождите, я закончу мысль — крепление будет на защёлках.
Маркетолог: Извините, у меня параллельно звонок был. О чём речь?
Промышленный дизайнер: О защёлках вместо винтов.
Руководитель проекта: Так, коллеги, давайте по делу. Промышленный дизайнер, проверь прочность защёлок на образцах, и вернёмся к этому.
Промышленный дизайнер: Проверю на образцах.
Тимлид: Логично.
```
