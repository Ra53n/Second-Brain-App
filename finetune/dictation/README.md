# dictation — пост-процессор голосового ввода

Задача типа «генерация»: на входе сырая расшифровка диктовки (ASR Wispr Flow),
на выходе готовый текст — расставлена пунктуация, исправлены ошибки
распознавания, убраны оговорки и повторы. Эталон — текст, каким он реально ушёл
в приложение после форматирования и правок автора.

Практический смысл: заменить облачный форматтер Wispr на локальную модель,
которая знает терминологию и манеру автора.

## Датасет

Источник — экспорт локальной базы Wispr Flow с рабочей машины: 3571 надиктовка,
~63 тыс. слов русской речи, апрель–июль 2026.

| Метрика | Значение |
|---|---|
| Отобрано пар | **1895** (train 1516 / valid 379 — 80/20) |
| Реальных | **100 %**, синтетики нет |
| С ручной правкой автора | 579 (31 %) — личный сигнал, а не форматтер Wispr |
| Дублей | 0 |
| Отброшено | 755 коротких (<8 слов), 0 длинных (>4000 символов), 395 без изменений |

Сплит по времени: eval — последние 20 % по дате. Так валидация показывает
качество на «будущих» диктовках, а не на случайной выборке.

## Обезличивание

Тексты рабочие. Названия компаний, продуктов, внутренних систем, имена коллег,
email, домены и номера тикетов заменены на вымышленные с сохранением падежей
(«в Авито» → «в Тривио», «Игорем» → «Сергеем», «Куапсом» → «QA»).

Контроль — grep по списку исходных маркеров в файлах датасета: **ноль
вхождений**. Скрипт сборки и карта замен намеренно **не в репозитории**: карта
содержит реальные названия и имена, лежит рядом с исходной выгрузкой на машине
владельца.

## Проверки и критерии

Автопроверки — `../dictation_checks.py`, критерии и правило приёмки —
[criteria.md](criteria.md). Главная ось не стиль, а точность относительно
эталона: похожесть по словам, сохранность чисел и терминов латиницей,
пунктуация, отсутствие преамбул и лишней разметки.

```bash
P=../.venv/bin/python
$P ../validate.py data/train.jsonl data/valid.jsonl \
   --system system_prompt.txt --min-assistant 30
$P ../dictation_calibrate.py     # пороги vs эталоны автора: 14222/14222
$P ../selftest.py                # проверки ловят дефекты
```

## Baseline

10 примеров из eval через `Qwen2.5-7B-Instruct-4bit` **без тюна**,
`temperature 0.3`. Ответы зафиксированы в [`baseline/`](baseline).

| Метрика | Значение |
|---|---|
| Автопроверки | **70/75** |
| Похожесть на эталон | среднее **0.915**, минимум 0.755 |
| Примеров с полным зачётом | 6 из 10 |

Все пять провалов предметные: термины латиницей (`MobArch` → «mubargh»,
`DS` → «дизайн системы») и нехватка пунктуации (0.10 знака на слово против
эталонных 0.40). Базовая модель неплохо чистит речь в целом — расти есть куда
именно в терминологии и знаках.

## Тюн

Не запускался — этап ограничен подготовкой. Команды и правило приёмки —
в [criteria.md](criteria.md) и корневом [README](../README.md). Для 1516
обучающих примеров ставить `--iters 600` и выбирать чекпоинт по val loss
(`train.py --workdir dictation best --install`).
