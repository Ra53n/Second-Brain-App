# Модуль LLM — правила

Протоколы провайдеров, реестр, роутинг «функция → провайдер → модель», ключи,
облачные клиенты в `Cloud/`.

## Что здесь живёт

- `ProviderProtocols` — `ChatProvider`, `TranscriptionProvider`, `EmbeddingProvider`,
  `LLMError`, DTO сообщений и метрик.
- `ProviderRegistry` — какие провайдеры настроены, какие модели реально доступны
  (`availableModels`, `preferredDefaultModel`, `isModelSelectable`).
- `FunctionRouting` — назначение «функция (чат/транскрипция/саммари/эмбеддинг) → модель»,
  `routing.json`, цепочка кандидатов для фолбэка (`resolveChatProviders`).
- `KeyStore` — Keychain + env-fallback. `MockProviders` — детерминированные моки.
- `Cloud/` — OpenAI, Gemini, Deepgram, AssemblyAI (+ OpenRouter и DeepSeek поверх
  OpenAI-совместимого клиента), `HTTPSupport`, `AudioChunker`, `AudioMIME`.

## Инварианты

1. **Ключи не показываются никогда** — ни целиком, ни частично, ни в логах, ни в URL.
   UI знает только статус «задан/не задан». Проверка ключа — дешёвый GET списочного
   эндпоинта, секрет только в заголовке (`KeyVerifier`).
2. **Выбор провайдера — всегда через `FunctionRouter`.** Прямое обращение к
   `OpenAIProvider` из фичи ломает пользовательские назначения и фолбэки.
3. **Провайдер без пригодной модели выпадает из авто-выбора.** Хардкод-дефолт модели,
   которая не скачана, — это HTTP 404 у пользователя вместо ответа (реальный баг).
4. **Клиенты — immutable structs без глобального состояния**, `baseURL` и транспорт
   инжектируются: так они тестируются на фикстурах.
5. Ошибки провайдера доходят до UI текстом `LLMError`, а не превращаются в пустой ответ.
6. Новый провайдер = новый файл в `Cloud/` + регистрация в `CloudProviders` + дескриптор
   с дефолтной моделью. Вызывающий код не меняется (P3).

## Как тестируем

- **Ноль сети.** Реальные ответы API лежат в `Tests/SecondBrainTests/Fixtures` (JSON и SSE),
  транспорт инжектируется. Тест, который ходит в интернет, здесь запрещён.
- Разбор ответов, стриминг, обработка ошибок и лимитов — `CloudProviderTests`.
- Роутинг и фолбэки — `LLMTests`; изоляция от пользовательского `routing.json`
  обязательна (урок задачи 33: тесты читали живой конфиг и падали у другого человека).
- Для функций, где нужен «какой-то» провайдер, используем `MockProviders`.

## Частые ошибки прошлых задач

- Модель по умолчанию берётся из дескриптора без проверки, что она установлена
  (Ollama) или доступна по ключу — см. фикс роутинга от 2026-07-20.
- MIME/расширение аудио подставляется наугад: у каждого провайдера свои требования,
  общее место — `AudioMIME`.
- Tool-use цикл реализуется заново под конкретного провайдера вместо общего `ToolUseLoop`
  из `MCP/`. У Gemini tool-use пока нет — это известный пункт бэклога, а не повод
  писать свой цикл здесь.

## Куда не лезть

Ollama и WhisperKit (локальные рантаймы) — модуль `LocalRuntime/`; сборка инструментов
и промптов — `Chat/`; MCP-протокол — `MCP/`.
