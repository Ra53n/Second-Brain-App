# Модуль GitSync — правила

Обёртка над git CLI, ручная и авто-синхронизация vault, история. Работает с рабочим
репозиторием пользователя — цена ошибки высокая.

## Что здесь живёт

- `GitClient` — actor с FIFO-очередью команд, чистые парсеры (porcelain v2, log, URL).
- `AutoBackup` — таймер авто-бэкапа, чистая решающая логика отдельно от Task-цикла.
- `SyncViewModel` / `GitSyncViews` — панель синхронизации в тулбаре.

## Инварианты

1. **FIFO-очередь обязательна.** Параллельные git-команды портят `index.lock` — поэтому
   `GitClient` actor и все вызовы сериализованы. Не обходи его «быстрым» `Process`.
2. **Vault никогда не остаётся полу-смердженным.** Автоматический merge не удался →
   `merge --abort`, дальше пользователь выбирает «принять свои» / «принять удалённые»
   (`pull -X ours/theirs`) или мержит руками.
3. **Auth — только системный credential helper (osxkeychain) или SSH.** Интерактивные
   запросы отключены. Токен в URL remote детектится и предлагается к удалению; приложение
   его не хранит и не пишет в конфиг.
4. **Неудачный push не дублирует коммиты** — следующий прогон видит `ahead > 0` и допушивает.
5. **Vault, вложенный в чужой репозиторий, репозиторием не считается** — защита от
   коммита родительского репо пользователя.
6. **Массовые откаты агенту запрещены** (решение задачи 40): `checkout`/`restore` пачкой
   не предлагаем и не выполняем, только точечный откат файла по кнопке пользователя.

## Как тестируем

- Парсеры вывода git — чисто, на зафиксированных строках вывода.
- Операции — на временных репозиториях, создаваемых в тесте (`GitSyncTests`);
  **репозиторий проекта и vault пользователя в тестах не участвуют**.
- Сеть (push/pull к настоящему remote) не тестируем.

## Частые ошибки прошлых задач

- Прямой вызов `git` мимо `GitClient` из другой подсистемы → гонка за `index.lock`.
- Коммит «всего подряд» вместо явного набора путей.
- Показ секрета из URL пользователю в логе: URL с токеном показываем только ему самому
  и только для того, чтобы он его убрал.

## Куда не лезть

Git-обзор для чата (ветка, diff, коммит из вкладки «Изменения») — модуль `Chat/`
через `ChatGitBridge`; git-инструменты для модели — `Tools/GitTools`. Здесь — только
синхронизация vault.
