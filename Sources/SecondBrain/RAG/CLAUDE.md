# Модуль RAG — правила

Чанкинг, эмбеддинги, векторный индекс, retriever, реестр баз знаний, инструмент
`rag_search`. Всё здесь — производные данные: их можно удалить и пересобрать.

## Что здесь живёт

- `RagChunker` — чанкинг по заголовкам с путём «H1 > H2» и диапазонами строк.
- `RagIndex` — SQLite (чанки + Float32-LE-векторы); **единственное место с SQL в модуле**.
- `RagIndexer` / `RagIndexManager` — инкрементальная индексация по mtime, статус для UI.
- `RagVector` — косинус и `topK` (brute-force, семантика FAISS Flat).
- `RagRetriever` / `RagRerank` — ретрив с rewrite/rerank/порогом для базы {vault}.
- `KnowledgeBase` / `KnowledgeBaseStore` / `KnowledgeBaseManager` — реестр баз и единая
  точка ретрива; `FolderIndexService` — произвольные папки; `KnowledgeMerge` — слияние.
- `RagSearchTool` — чистая логика инструмента для модели.

## Инварианты

1. **Индексы лежат вне vault** (`Application Support/<vault-id>/rag.sqlite`) и всегда
   пересоздаваемы. Ничего, что нельзя восстановить из .md, в них хранить нельзя.
2. **Коммит per-file транзакцией** — прерывание индексации не теряет готовое.
3. **Смена модели эмбеддинга ⇒ несовместимые векторы.** Тег «model|dim» в БД, при
   расхождении — предложение полной переиндексации, а не молчаливое смешивание.
4. **Автообновление только при уже построенном индексе.** Первая индексация — явная
   кнопка: эмбеддинги стоят денег и времени.
5. **`rag_search` — ОДИН инструмент** с параметром `base` (enum по именам включённых баз).
   Не плоди инструмент на базу: имена функций OpenAI не переваривают кириллицу, значения
   enum — переваривают.
6. Исключения индексации: dot-папки, `Meetings/_recordings/`, не-markdown, пользовательский
   ignore-список, служебные каталоги вроде `node_modules`. Лимиты папочных баз: 1 МБ на
   файл, 2000 файлов.
7. Встроенные базы (`vault`, `project`) нельзя удалить — только выключить.

## Как тестируем

- Эмбеддер в тестах — детерминированный `HashingEmbedder`, БД — SQLite `:memory:`.
  **Ни одного реального запроса за эмбеддингами.**
- Чанкинг — round-trip и граничные случаи: пустой файл, заголовки внутри код-блоков,
  документ без заголовков.
- Ретрив — на подготовленном наборе чанков с известными ожиданиями (`RagChatTests`).
- Реестр баз и слияние — `KnowledgeBaseTests`; инструмент — `RagToolTests`.
- Индексация — `RagIndexingTests` на temp-директориях.

## Частые ошибки прошлых задач

- Индексация папки без исключений вычищает `node_modules` в эмбеддинги (задача 39,
  дополнение 5) — проверяй список исключений при добавлении нового типа базы.
- Слияние баз без общей шкалы score: эмбеддер один, шкала общая — сортируй сквозной,
  а не по базам.
- Полная переиндексация «на всякий случай» вместо инкрементальной по mtime.

## Куда не лезть

Промпт и вставка `[RAG_CONTEXT]` — модуль `Chat/`; провайдер эмбеддингов и его выбор —
`LLM/`; FTS-поиск по заметкам (это другой индекс) — `Search/`.
