# Модуль Tools — правила

Встроенные инструменты чата: git-обзор, чтение и поиск по файлам, файловые операции,
запуск команд, слой разрешений. Всё здесь исполняется по решению LLM — значит,
недоверенный ввод и явные лимиты обязательны.

## Что здесь живёт

- `BuiltinTool` — контракт (name/description/parameters для модели + execute),
  `ToolSchemas` — хелперы JSON Schema.
- `ToolRegistry` — набор инструментов, `ToolExecutor` (actor) — поиск по имени и запуск.
- `GitTools`, `FileTools` (+ `FileOpsContext`), `RunCommandTool`, `ProjectDocs`,
  `ProjectDocsRag`, `ProjectToolsProvider`.
- `SafePath` — нормализация путей от модели; `UnifiedDiff` — свой LCS-диff без git.
- `ToolPermissions` — `ToolRiskClassifier` (чистый) и режимы разрешений.

## Инварианты

1. **Имена инструментов без «__»** — qualified-имена MCP всегда `slug__tool`,
   пространства имён не пересекаются по построению (закреплено тестом).
2. **Путь от модели — недоверенный ввод.** Только через `SafePath`: нормализация,
   разыменование симлинков, запрет выхода за корень. Ни одного `URL(fileURLWithPath:)`
   на аргументе модели напрямую.
3. **Лимиты не обсуждаются:** чтение 64 КБ, запись 256 КБ, вывод команды и поиска 32 КБ,
   поиск — 200 совпадений / 5000 файлов, таймаут команды ≤ 600 с. Бинарники отклоняются.
4. **Перезапись существующего файла — только после его полного чтения в этом чате и при
   неизменившемся mtime** (`FileOpsContext`). Обрезанное чтение не регистрируется.
5. **Удаление — в Корзину** (`trashItem`), не `removeItem`. Операция обязана быть обратимой.
6. **Каждый новый инструмент классифицируется в `ToolRiskClassifier`** (safe/write/dangerous)
   и получает тест. Незнакомое имя обязано попадать в более строгую категорию, а не в safe.
7. **Ошибка — это `ToolResult.error`** с текстом `ERROR: …`, а не брошенное исключение:
   модель должна увидеть проблему и отреагировать.
8. Любой запускаемый процесс регистрируется в `BackgroundProcessRegistry` (инвариант №2).

## Как тестируем

- Классификатор и матрица «режим × риск» — исчерпывающе, таблицами
  (`ToolPermissionsTests` — эталон теста для всего проекта).
- Файловые операции — на temp-директориях: mtime-guard, отказ без предварительного
  чтения, капы, бинарники (`FileToolsTests`).
- `run_command` — allowlist, составные команды через `&&`/`;`/`|`, редиректы, таймаут
  (`RunCommandToolTests`).
- Diff — `UnifiedDiffTests`; git-инструменты — на temp-репозиториях (`ProjectToolsTests`).

## Частые ошибки прошлых задач

- Новый инструмент добавлен, но не классифицирован → попадает в safe и исполняется без
  подтверждения. Классификация — часть определения инструмента, а не отдельная задача.
- Проверка пути «вручную» через `hasPrefix` вместо `SafePath` — симлинк выводит за корень.
- Массовый откат файлов агентом: запрещено (задача 40, дополнение) — откат только точечный
  и по кнопке пользователя.
