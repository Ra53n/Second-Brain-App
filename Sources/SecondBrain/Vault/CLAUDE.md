# Модуль Vault — правила

Дерево файлов, CRUD, наблюдение за диском, пути. Здесь живёт инвариант №1 в чистом виде:
это код, который трогает рабочие файлы пользователя.

## Что здесь живёт

- `VaultManager` — состояние vault: дерево, выбор, раскрытые папки, reveal, CRUD.
- `VaultScanner` / `VaultTree` / `VaultWatcher` — скан, модель узлов, FSEvents.
- `VaultFileOperations` — единственная точка создания/переименования/удаления/перемещения.
- `VaultPath` — чистые вычисления путей (breadcrumb, предки для раскрытия дерева).
- `NoteTemplate` — чистая подстановка `{{date}}`/`{{title}}` для «Новая заметка из
  шаблона» (`Templates/` в корне vault, зарезервированное имя как у `Meetings/`).
- `VaultViews`, `NoteBreadcrumbView` — дерево, breadcrumb, содержимое папки.

## Инварианты

1. **Инвариант №1 дословно.** Ни одна операция не теряет и не перезаписывает молча .md.
   Удаление — в Корзину. Конфликт — решает пользователь, а не код.
2. **Все файловые операции — через `VaultFileOperations`.** Прямой `FileManager` в
   ViewModel или View запрещён: там же живут проверки имён, коллизий и обновление индексов.
3. **Доступ к папке — через security-scoped bookmark**, переживающий перезапуск. Без
   него после рестарта приложение теряет права на vault.
4. **Внешнее открытие заметки — только через `VaultManager.open(_:)`** (не прямая правка
   selection): open раскрывает путь в дереве, скроллит к узлу и обновляет breadcrumb.
   Так ходят wikilinks, backlinks, поиск, quick switcher и результат CRUD.
5. **FSEvents дебаунсится** (2 с) и приводит к инкрементальному обновлению по mtime,
   а не к полному пересканированию и точно не к переиндексации всего RAG.
6. Производные данные внутри vault не создаём — ни БД, ни кэшей, ни служебных папок.

## Как тестируем

- Пути — чисто, без ФС (`VaultPathTests`): файл/папка/корень, кириллица,
  нестандартизованные URL, ловушка префикса имён (`/x/Notes` vs `/x/NotesBackup`).
- CRUD и сканер — на temp-директориях (`VaultTests`), **живой vault пользователя в тестах
  не участвует никогда**.
- Дерево и breadcrumb (UI) — смоуком через `/smoke-ui`.

## Частые ошибки прошлых задач

- Проверка «внутри ли vault» через `hasPrefix` без разделителя: `/x/NotesBackup` проходит
  проверку для `/x/Notes`. Режь строго по границе компонента (в `VaultPath` это сделано).
- Ручное раскрытие дерева вместо `reveal`/`open` → заметка открылась, но в дереве не видно.
- SwiftUI не отдаёт текст label `DisclosureGroup` в Accessibility — строки-папки выглядят
  пустыми для AX-смоука. Это поведение фреймворка, а не баг: проверяй по файлам.
