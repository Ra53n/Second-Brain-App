# Цикл прогона: тесты + смоук по импакту (задача 60)

Замыкает двухуровневое тестирование в петлю: после правки/PR прогнать затронутое (код-тесты
уровня 1 + UI-смоук уровня 2) одной командой, собрать единый отчёт, при падении указать место,
и держать смоук-каталог растущим под новые фичи.

## Когда

- После содержательной правки/PR — прогнать затронутое и приложить отчёт.
- «Задеплоил фичу — обнови смоук и прогони» (см. точку входа 5).
- Не для тривиальных правок доков — `smoke-all.sh` сам ответит «нет изменений в коде».

## Механика: `scripts/smoke-all.sh` (не переизобретай)

```bash
./scripts/smoke-all.sh [base-ref] [--full] [--dry-run] [--out <dir>]
```

Он: `git diff` → по `smoke/impact-map.tsv` выбирает тест-фильтры и сценарии → `scripts/test.sh`
(полный или `--filter`) + `scripts/ui.sh run smoke/<X> --html` → единый отчёт → при падении секция
«ГДЕ СМОТРЕТЬ». `App/**` или широкий diff → полный прогон; правки вне `Sources/` → «нечего гонять».
`--dry-run` показывает выбор без прогонов; `--out` — куда класть HTML (умолчание `smoke/out/`).

## Три точки входа

### (1-3) После правки — прогнать по импакту, при падении локализовать
1. `./scripts/smoke-all.sh` (по умолчанию diff к `main`).
2. Всё зелёное → короткий отчёт: сколько тестов, `ИТОГ:` по сценариям, пути HTML.
3. Красное → назови ЧТО упало (тест / сценарий / конкретный шаг) и вероятное место из секции
   «ГДЕ СМОТРЕТЬ» (обратная карта раздел→модули). Предложи причину — не «чини вслепую».

### (4) После PR — единый отчёт + дописать сценарий
- Прогнать `smoke-all.sh`, собрать единый отчёт.
- HTML показать пользователю: `SendUserFile` (display: render) на отчёт(ы) из `--out`.
- Если PR добавил/изменил экран или флоу — **дополни смоук-каталог** (см. «Как дописывать сценарий»).

### (5) «Задеплоил фичу — обнови смоук и прогони»
- Собери/установи свежую сборку (`./install.sh`) и перезапусти приложение сам (quit → open → `pgrep`).
- Дополни/поправь сценарий под фичу.
- Полный прогон: `./scripts/smoke-all.sh --full` → отчёт + HTML пользователю.

## Как дописывать сценарий (безопасно)

- Грамматика `open/check` (детали — `/smoke-ui`), ≤6 строк, подписи бери с живого `ui.sh list`.
- **Только неразрушающее.** Перед любым `click` по создающей/меняющей кнопке («Новая заметка/
  папка», «Новый чат/пайплайн» и т.п.) сперва закрой BACKLOG п.35 (расширить блок-лист
  `DESTRUCTIVE` в `ui.sh`), иначе клик создаст данные в живом vault (инвариант №1).
- Прогони новый сценарий: `./scripts/ui.sh run smoke/<X>.txt --html <out>` — добейся 0 провалено.
- Появился новый модуль/раздел — добавь строку в `smoke/impact-map.tsv`.

## Карта импакта (`smoke/impact-map.tsv`)

Строки `module_glob⇥section⇥scenario⇥test_filter`, совпадение по префиксу пути от
`Sources/SecondBrain/`. Меняешь модуль → правишь его строку; `test_filter` — по РЕАЛЬНЫМ именам
классов `XCTestCase` (не файлов: `swift test --filter` фильтрует по классу). `settings.txt` пока
достаёт только плейсхолдер (BACKLOG п.34) — правки в `Settings/LLM/LocalRuntime/GitSync` смоуком
покрыты мелко, полагайся на их код-тесты.

## Чего не делать

- Не гонять смоук на старой сборке (`preflight` это ловит — пересобери).
- Не вводить текст и не сохранять в живой vault; никакого CRUD.
- Не добавлять `click` по разрушающим/создающим кнопкам до BACKLOG п.35.
