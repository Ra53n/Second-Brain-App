# Новая задача: фазы Ф1 (интервью) и Ф3 (оформление)

Цель — файл, по которому другой агент сделает работу без единого уточняющего вопроса.
Пока задача не оформлена, код не пишем.

## 1. Разведка до вопросов

Прежде чем спрашивать пользователя, выясни сам:

```bash
grep -rn "<ключевое слово>" Sources --include='*.swift' | head -20
ls tasks/ | tail -5                      # текущий максимальный номер
grep -n "<тема>" tasks/BACKLOG.md        # возможно, пункт уже описан
```

Плюс `CLAUDE.md` модуля, к которому относится запрос. Не спрашивай о том, что видно в
репозитории, — это раздражает и тратит время пользователя. Если функция уже есть и
проблема лишь в том, что её не найти в UI, скажи об этом сразу: возможно, задача не нужна.

## 2. Интервью (Ф1)

Задай вопросы **одной пачкой** через AskUserQuestion, с вариантами и рекомендацией.
Чек-лист — пропускай нерелевантное осознанно, а не по забывчивости:

- сценарий: кто, когда, что происходит непосредственно до и после;
- пустой ввод / битый ввод / огромный ввод — что должно произойти;
- нет сети, нет ключа, не скачана модель, нет разрешения (микрофон, папка);
- краш или выход посреди операции — что пользователь увидит после перезапуска;
- два одновременных запуска (два окна, пайплайн параллельно с руками) — что выигрывает;
- уже сохранённые данные и настройки — нужна ли миграция, что со старыми файлами;
- что явно НЕ надо делать в этой задаче;
- как пользователь проверит результат руками.

Ответы, которые нельзя вывести из кода, переносятся в файл задачи **дословно**.

## 3. Оформление (Ф3)

Номер задачи = максимальный в `tasks/` + 1. Файл `tasks/NN-slug.md` по шаблону:

```markdown
# Задача NN: короткое название

## Цель
Что получает пользователь. Языком пользователя, не кода.

## Зависимости
Номера задач (или «нет») — проверяются по 00-INDEX.md перед стартом.

## Объём
1. Нумерованный список работ с конкретными файлами и типами.

## Вне объёма
- Что явно не трогаем, даже если руки чешутся.

## Критерии приёмки
- Проверяемые утверждения: что должно быть зелёным, что видно в UI, что покрыто тестами.
```

Требования к качеству:

- «Цель» описывает наблюдаемое поведение, а не реализацию;
- каждый пункт «Объёма» называет файлы (существующие — точными путями);
- «Вне объёма» не пустой: у любой задачи есть соблазн, который надо отсечь;
- каждый критерий приёмки можно проверить командой или глазами, «работает хорошо» — не критерий.

## 4. Регистрация

- строка в `tasks/00-INDEX.md` в формате
  `| NN | [название](NN-slug.md) | зависимости | [ ] |`;
- если задача выросла из пункта `tasks/BACKLOG.md` — пометь пункт `→ NN` (зачеркни его
  через `~~…~~`, как сделано с пунктами 8, 10, 16, 19).

## Чек-лист выхода

- [ ] Файл `tasks/NN-slug.md` создан и содержит все шесть секций.
- [ ] Ответы пользователя по corner-кейсам перенесены в текст, а не потеряны в чате.
- [ ] Строка в `00-INDEX.md` добавлена, зависимости проставлены честно.
- [ ] Пункт бэклога помечен, если задача выросла оттуда.
- [ ] Открытые вопросы, на которые пользователь не ответил, записаны в задаче явно.
