# Архитектурный разбор: фаза Ф2

Задача понятна, решение — нет. Здесь оно принимается. Ни одного изменения в файлах на
этом шаге.

## 1. Контекст

Прочитай целиком: файл задачи, `CLAUDE.md` в корне (паттерны P1–P6, антипаттерны),
`CLAUDE.md` затрагиваемых модулей, релевантный раздел `docs/ARCHITECTURE.md`, при работе
с хранением — `docs/DATA-MODEL.md`.

## 2. Найди существующее раньше, чем спроектируешь новое

Половина «новых» задач закрывается тем, что уже написано.

```bash
grep -rn "<похожее имя>" Sources --include='*.swift' | head
grep -rn "protocol \|enum .*Error" Sources/SecondBrain/<Модуль> --include='*.swift'
grep -n "<подсистема>" docs/CONVENTIONS.md   # таблица портирования из Manager Assistant
```

Готовые кирпичи, о которых забывают: `SafePath`, `UnifiedDiff`, `VaultPath`,
`ToolSchemas`, `HTTPSupport`, `JSONValue`, `MockProviders`, `HashingEmbedder`,
`BackgroundProcessRegistry`, `SettingsTabRouter`.

## 3. Ответь на восемь вопросов

1. **Куда ложится** — модуль и почему именно он.
2. **Что переиспользуем** — конкретные типы и файлы.
3. **Что создаём** — новые файлы, их роль, имена по конвенции (`*Store`, `*Service`,
   `*Parser`…).
4. **Где чистое ядро (P1)** — какую часть логики можно свести к функции без I/O: что
   принимает, что возвращает, почему это тестируется исчерпывающе.
5. **Персистентность (P2)** — что сохраняем, в каком сторе, нужна ли миграция и какой
   тест её закроет.
6. **Инварианты** — затрагиваются ли vault как источник истины, жизненный цикл фоновых
   процессов, crash-safety FSM; что конкретно их защитит.
7. **Тесты, которые поедут** — список существующих тестов, которые придётся менять.
   Если их много, скажи прямо: скорее всего, решение неверное, поищи менее инвазивное.
8. **Порядок работ** — от чистого ядра к UI, с точками остановки для проверки.

## 4. Назови риски

Секции «Частые ошибки прошлых задач» в модульных `CLAUDE.md` — это не украшение, а
список граблей, на которые уже наступали. Проверь, не ведёт ли твой план на те же.

## Чек-лист выхода

- [ ] Названы файлы, которые будут изменены и созданы (точными путями).
- [ ] Чистое ядро выделено явно, с сигнатурой.
- [ ] Решено, что переиспользуется, — и это подтверждено grep'ом, а не памятью.
- [ ] Проверено, есть ли готовый аналог в Manager Assistant.
- [ ] Инварианты и миграции разобраны, а не забыты.
- [ ] Ни один файл проекта не изменён на этом шаге.

Большой разбор с широким поиском по коду можно делегировать субагенту `architect`
(read-only). Дальше — `/task-run`.
