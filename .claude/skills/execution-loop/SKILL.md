# Execution Loop: автономная очередь задач

Ты — оркестратор. За пределами мелкой бухгалтерии (п.6–7) не читаешь и не правишь код сам —
каждую задачу выполняет отдельный субагент, чтобы твой собственный контекст не рос с каждой
итерацией. Это отличает `execution-loop` от одиночного `/task-run`, где малую задачу техлид
делает сам: там сессия на этом и заканчивается, здесь за одну сессию проходит очередь из N
задач, и накопление истории инструментов в ОДНОЙ сессии дороже, чем пересборка контекста в
отдельном субагенте на каждую задачу.

## 1. Перед стартом

- Рабочее дерево чистое (`git status`). Чужие незакоммиченные правки — стоп, скажи
  пользователю. Это единственная точка, где до начала цикла возможен диалог.
- Дальше — до исчерпания очереди или стоп-условия (п.9), без вопросов.

## 2. Выбор следующей задачи

```bash
grep -n "^| [0-9]" tasks/00-INDEX.md
```

Наименьший номер, для которого одновременно:
- статус `[ ]` (не `[x]`);
- строка не содержит маркер `⛔` (не заблокирована);
- все номера в колонке «Зависит от» — уже `[x]`.

Нет такой строки → сразу к «9. Стоп-условия» (финальный стоп).

## 3. Уровень, профиль, модель

- **Уровень** — по триггерам CLAUDE.md «Конвейер разработки» (новый модуль/персистентный
  тип/экран/инвариант/объём), как в обычном `/task-run`.
- **Профиль** — по полю `## Тип` файла задачи (таблица в CLAUDE.md «Сценарные профили»):
  `баг` → `bugfix`, `рефакторинг` → `refactor`, `фича`/`тест`/`документация` → `coder`.
  Нет поля `## Тип` (задача заведена до 63) — считай `фича`/`coder`.
- **Модель дев-субагента** — поле `## Модель` файла задачи (`haiku`/`sonnet`/`inherit`).
  Нет поля — `inherit` (не угадывай размер задачи, если это не зафиксировано).

## 4. Один субагент на «Разработку» — сам код не пишешь никогда

Даже на малом уровне (где обычный `/task-run` велит техлиду кодить самому) в цикле —
**всегда** спавни субагента выбранного профиля с моделью из п.3. Промпт — самодостаточный:

- открыть `tasks/NN-slug.md` целиком;
- дописать в файл компактные `## Допущения и corner-кейсы` и `## Архитектура` (малая —
  3–6 строк каждая; полная — полный формат) — автономно, без вопросов;
- реализовать по «Объёму»: чистое ядро → тесты на него → интеграция → UI;
- прогнать `./scripts/build.sh` и `./scripts/test.sh`, дописать `## Отчёт тестов`;
- вернуть короткий итог (файлы, результат build/test, готовность к ревью) — не пересказывать
  диф целиком, это лишний контекст тебе.

Субагент **не коммитит** — коммит делаешь ты сам, и только после `GO` (п.7).

## 5. Ревью — всегда отдельный субагент

Спавни `reviewer` (read-only, модель — **всегда** `inherit`, никогда не понижай — это
единственный гейт качества цикла) на текущий диф и файл задачи. Получи `GO`/`NO-GO`.

## 6. NO-GO: повтор с эскалацией модели, не третий круг

- Первый `NO-GO` → тот же профиль, свежий субагент, с замечаниями ревьюера в промпте; если
  на первом заходе была `haiku` — на повторе используй `sonnet` (эскалация: не тот же
  слабый исполнитель на то же самое замечание).
- Второй `NO-GO` по тому же замечанию → задача блокируется (п.8), не третий круг вслепую.
- `GO` → закрой задачу (п.7).

## 7. Закрытие задачи (после `GO`)

Делаешь сам — маленькое, ограниченное действие, не растит контекст ощутимо: допиши
`## Результат` в файл задачи, поставь `[x]` в `00-INDEX.md`, закоммить (`git add` + `git
commit` по конвенции проекта). **Коммит только локальный** — не пушь, не создавай PR, это
отдельное решение пользователя после проверки результатов цикла.

## 8. Блокировка (замена «стоп, спроси пользователя»)

Три места обычного флоу требуют человека без fallback — в цикле человека спросить некого:
- зависимости задачи внезапно не выполнены (рассинхрон `00-INDEX.md` с реальностью);
- два круга `NO-GO` по одному и тому же замечанию (п.6);
- `bugfix`-профиль не смог воспроизвести баг.

Действие одинаковое во всех трёх случаях: допиши в файл задачи `## Заблокировано: <причина>`
(коротко — что попробовано, почему не закрыто), в строке `00-INDEX.md` добавь `⛔` перед
названием задачи (чекбокс остаётся `[ ]` — не выполнено, но и повторно не выбирается),
закоммить эту документацию отдельным маленьким коммитом, перейти к следующей задаче (п.2).

## 9. Стоп-условия

- **Предохранитель**: 3 заблокированные подряд без успешного закрытия между ними → стоп,
  отчёт. Не крутиться вхолостую, если что-то системно сломано (например, build красный).
- **Финальный стоп**: подходящих задач в очереди не осталось (п.2) → стоп, отчёт.

Отчёт в обоих случаях: закрыто (номера), заблокировано (номера + короткая причина каждой),
что осталось в очереди и почему не взято (зависимости/нет подходящей).

## Никогда

- `AskUserQuestion`, `ExitPlanMode` — цикл не может ждать ответа после старта (п.1).
- push, создание PR, работа с задачами вне пула/очереди `00-INDEX.md`.
- чтение/правка кода напрямую в своём контексте — только через субагента (п.4). Правки
  `00-INDEX.md`, `## Результат`, `## Заблокировано` — исключение (п.7–8), они малы сами по
  себе и не накапливаются в проблему за счёт своего размера.
