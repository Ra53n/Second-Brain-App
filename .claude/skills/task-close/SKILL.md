# Закрытие задачи: фаза Ф6

Закрывается только задача, прошедшая `/task-verify`. Незакрытые хвосты не прячем —
записываем.

## 1. Секция «Результат» в файле задачи

Дописывается в конец `tasks/NN-slug.md`. Три обязательных блока:

```markdown
## Результат

<Одна строка: сделано по плану / с отклонениями.>

- Новые файлы: пути + одна строка «что там».
- Изменены: файл (что именно изменилось).
- Отклонения от плана: что сделали иначе и почему. Нет отклонений — так и напиши.
- Что не проверено: пункты, требующие живого железа, встречи, сети провайдера.

Важно для следующих задач:

- Неочевидные решения, грабли и инварианты, которые новый агент иначе выяснит заново.
```

Последний блок — самое ценное в файле. Пиши туда то, что сам хотел бы прочитать перед
началом: «список папок vault берите через `MeetingsViewModel.vaultFolderPaths()`»,
«AX-хэндл окна протухает при перестроении дерева». Общие слова («код стал чище») не пиши.

Если по ходу задачи всплыло что-то за её пределами — пункт в `tasks/BACKLOG.md` с датой
и происхождением.

## 2. Индекс и документация

- чекбокс задачи в `tasks/00-INDEX.md` → `[x]`;
- существенное отклонение от описания → строка в «Журнале отклонений» внизу индекса;
- менялось архитектурное решение → обновлён `docs/ARCHITECTURE.md` (он живой документ);
- новое место хранения → `docs/DATA-MODEL.md`.

## 3. Коммит

```bash
git status                      # убедись, что в индекс не заехало лишнее
git add -A
git commit
```

Сообщение: первая строка `Задача NN: суть человеческим языком` (до ~72 символов), пустая
строка, тело — **что изменилось и почему**, а не пересказ дифа. Хороший тон проекта:
называть симптом, который чинили, и решение (см. `git log` — коммиты 6b1c485, fb6079b,
282241e как эталон).

Заканчивай тело строкой:

```
Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>
```

Пуш — только если пользователь просил. Ветка: работаем в `main`, как принято в проекте.
