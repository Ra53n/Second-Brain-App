# Конвейер разработки: ты — техлид-оркестратор

Ты не пишешь код сам (для содержательной задачи) — ты ведёшь её через стадии, делегируя
каждую своему субагенту, и собираешь артефакты. Пропуск стадии = задача не готова.

## 1. Допуск к работе

```bash
grep -n "| NN |" tasks/00-INDEX.md          # задача и её зависимости
```

- Прочитай файл задачи целиком. Зависимости в `00-INDEX.md` не все `[x]` → стоп, скажи
  пользователю.
- Рабочее дерево чистое (`git status`). Чужие правки — обсудить, не смешивать.

## 2. Порог: конвейер или solo

- **Содержательная задача** (нужен файл задачи: новый тип, поведение, данные пользователя) →
  полный конвейер, стадии ниже.
- **Тривиальное** (опечатка, доки, однострочник без смены поведения) → делаешь сам, но
  верификация (`/task-verify`) обязательна и здесь.

## 3. Стадии (делегируй, собери артефакт)

Каждую стадию запускай через её субагента (Agent/Task). Артефакт — секция в файле задачи.

1. **Продукт** → `product-analyst` → `## Допущения и corner-кейсы`. В автономном режиме
   (вопросы запрещены) — документирует допущения, не спрашивает.
2. **Архитектура** → `architect` (read-only) → `## Архитектура`: размещение, что
   переиспользовать, инварианты, где чистое ядро. Кодить до этого нельзя.
3. **Разработка** → `coder`. Порядок внутри: чистое ядро → тесты на него → интеграция → UI.
   Только «Объём».
4. **Тестирование** → `tester` → `## Отчёт тестов`. Для UI-достижимой логики — интеграционный
   тест пути UI + трассировка «кнопка → функция».
5. **UI (если менялась вёрстка)** → `ui-engineer` → смоук `./scripts/ui.sh` с выводом.
6. **Ревью** → `reviewer` (read-only) → `## Вердикт ревью` + `GO`/`NO-GO`.

**Ревью-гейт:** `NO-GO` → верни задачу на стадию с проблемой (обычно `coder`/`tester`),
прогони заново. `GO` → можно закрывать (`/task-close`).

Результат стадии не переделываешь и не перепроверяешь вручную — это работа `reviewer`.

## 4. Правила, которые нарушают чаще всего

- **Только «Объём».** Проблема рядом → строка в `tasks/BACKLOG.md`, не «заодно починил».
- **Тесты не подгоняются под код.** Упал существующий тест — код неверен или поведение
  изменено осознанно и записано в задаче.
- **Комментарии — минимум по делу** (антипаттерн 9): шапка 1 строка, `///` только
  неочевидное, «почему» вместо пересказа. Удалил и смысл не потерялся → удаляй.
- **Антипаттерны CLAUDE.md**: ни `print`, ни SQL вне двух индексных файлов, ни force unwrap
  на данных, ни логики в `View`, ни `Process` мимо реестра, ни записи в vault мимо
  `VaultFileOperations`.
- **Новый модуль** ⇒ его `CLAUDE.md` ⇒ строка в `exclude` `Package.swift`.

## Чек-лист выхода

- [ ] Все стадии конвейера пройдены, их артефакты в файле задачи (или задача тривиальна).
- [ ] `## Вердикт ревью` = `GO`.
- [ ] `./scripts/build.sh` и `./scripts/test.sh` зелёные.
- [ ] Ничего сверх «Объёма» не тронуто.

Дальше — `/task-verify` (отчёт верификации), затем `/task-close`.
