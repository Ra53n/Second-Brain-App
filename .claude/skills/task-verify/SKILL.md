# Проверка задачи: фаза Ф5

Цель — доказательства, а не ощущение. Каждый критерий приёмки подтверждается выводом
команды, тестом или AX-дампом.

## 1. Сборка и тесты

Если `coder`/`tester` уже дали свежий зелёный прогон на текущем дифе в этом же конвейере —
не гоняй заново, приведи их вывод. Иначе (solo или диф менялся после их прогона) — прогони:

```bash
./scripts/build.sh
./scripts/test.sh
```

Оба зелёные. Отдельно убедись, что **новых варнингов не появилось** — сравни с тем, что
было до задачи (известные существующие: три `no 'async' operations` в
`Chat/ChatToolAssembly.swift`).

## 2. Критерии приёмки по пунктам

Выпиши критерии из файла задачи списком и на каждый дай доказательство: имя теста,
вывод команды, строку AX-дампа. Критерий без доказательства считается невыполненным.
Если что-то проверить невозможно (реальное железо, живая встреча, сеть провайдера) —
так и напиши: «проверяется вручную, не проверено».

## 3. Антипаттерны на дифе

```bash
git diff --stat
git diff | grep -nE "^\+.*(print\(|NSLog\()"                     # диагностика в консоль
git diff | grep -nE "^\+.*sqlite3_"                              # SQL вне индексов
git diff | grep -nE "^\+.*(try!|as! )"                           # force unwrap на данных
git diff | grep -nE "^\+.*(URLSession|https://)" -- Tests        # сеть в тестах
git diff | grep -nE "^\+.*Process\(\)"                           # процесс мимо реестра
```

Каждое совпадение — либо объяснимое исключение (статическая регулярка, литеральный URL),
либо замечание. Полный чек-лист — в разделе «Антипаттерны» CLAUDE.md.

Отдельно: файлы в дифе, которых нет в «Объёме» задачи, — это замечание.

## 4. Секреты

```bash
git grep -I --cached -e 'sk-' -e 'ghp_' -e 'AIza'
```

Совпадения допустимы только в тестовых фикстурах с заведомо фейковыми значениями и в
тексте самих правил. Реальный ключ — стоп, коммита не будет.

## 5. Смоук UI (для задач, менявших интерфейс)

Если `ui-engineer` уже прогнал смоук в этом конвейере на актуальном дифе — не гоняй заново,
приведи его вывод. Иначе (solo-задача с UI) — обязателен, а не «если останется время»:
процедура и команды `./scripts/ui.sh` — в скилле `/smoke-ui`, не переизобретай.

Пройди по всем кнопкам затронутого экрана и убедись, что каждая делает обещанное. Приложение
перезапускаешь сам, пользователя не просишь.

## 6. Документация

- Менялось архитектурное решение → обновлён `docs/ARCHITECTURE.md`?
- Появился новый модуль → есть `CLAUDE.md` и строка в `exclude` `Package.swift`?
- Появилось новое место хранения → обновлён `docs/DATA-MODEL.md`?

## Чек-лист выхода

- [ ] `./scripts/build.sh` зелёный, новых варнингов нет.
- [ ] `./scripts/test.sh` зелёный, число тестов не уменьшилось.
- [ ] Каждый критерий приёмки подтверждён доказательством или честно помечен как
      непроверенный.
- [ ] Диф не содержит антипаттернов и лишних файлов.
- [ ] Секретов нет.
- [ ] UI-смоук пройден и его вывод приведён (для UI-задач).
- [ ] Документация обновлена там, где решение изменилось.

Глубокую проверку дифа можно делегировать субагенту `reviewer` (read-only).
Дальше — `/task-close`.
