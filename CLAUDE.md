# Second Brain — контекст для кодовых агентов

macOS-приложение «второй мозг»: аналог Obsidian с записью встреч, транскрипцией через выбираемые LLM (локальные и облачные), чатом по базе знаний (RAG), MCP-интеграциями (Jira, Confluence) и git-синхронизацией vault.

Обязательно прочитай перед работой:
- [docs/VISION.md](docs/VISION.md) — что строим и зачем, сценарии использования.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — стек, модули, схема данных, принятые решения.
- [docs/CONVENTIONS.md](docs/CONVENTIONS.md) — стиль кода, комментарии, тесты, персистентность.

## Workflow: одна сессия = одна задача

Проект разрабатывается атомарными задачами из папки `tasks/`. Правила:

1. Открой [tasks/00-INDEX.md](tasks/00-INDEX.md) — там порядок задач, зависимости и статусы.
2. Возьми задачу, которую попросил пользователь (или первую невыполненную, если не сказано). Прочитай её файл **целиком**.
3. Проверь, что все зависимости задачи отмечены выполненными в 00-INDEX.md. Если нет — остановись и сообщи пользователю, не начинай работу.
4. Выполняй **только эту задачу**. Всё, что в секции «Вне объёма» — не трогай, даже если очень хочется.
5. Перед реализацией модуля посмотри аналог в эталонном проекте (см. ниже) и портируй паттерн, а не изобретай свой.
6. Прогони `swift build` и `swift test` — оба должны быть зелёными.
7. По завершении:
   - отметь чекбокс задачи в `tasks/00-INDEX.md`;
   - допиши в конец файла задачи секцию `## Результат` — что сделано, отклонения от плана, что важно знать агентам следующих задач;
   - если менял архитектурное решение — обнови `docs/ARCHITECTURE.md`;
   - сделай коммит с осмысленным сообщением.

## Сборка и тесты

```bash
swift build                # debug-сборка
swift run                  # запуск для разработки (без .app)
./run.sh                   # release + сборка SecondBrain.app
./install.sh               # run.sh + установка в /Applications

# Тесты требуют полный Xcode toolchain (не Command Line Tools)
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift test
```

## Жёсткие правила

- **Секреты**: API-ключи и токены никогда не попадают в код и в git. Хранение — Keychain, fallback — env. Перед коммитом: `git grep -I --cached -e 'sk-' -e 'ghp_' -e 'AIza'` — должно быть пусто.
- **Vault пользователя — источник истины**: приложение не должно терять или молча перезаписывать .md файлы. SQLite-индексы всегда пересоздаваемы.
- **Фоновые процессы** (Ollama и т.п.): каждый запущенный процесс регистрируется в менеджере и гарантированно гасится при `applicationWillTerminate`.
- **Тесты обязательны**: задача не считается выполненной без тестов на новую core-логику (критерии приёмки в каждой задаче).
- Реальный vault для ручной проверки: `/Users/kostyanikitin/Documents/Obsidian Vault/Second_Brain` (только чтение при проверках; ничего не ломать).
