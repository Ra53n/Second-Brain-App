# Chat — веб-чат с execution loop (`/chat/`)

Адрес: **`https://<VPS_HOST>/chat/`**

## Что это

Веб-чат как в Claude Code, но с личными аккаунтами и «умным» циклом под капотом. Каждое
сообщение может проходить **execution loop**: ассистент генерирует ответ, сам проверяет
его на корректность, затем на безопасность, при провале переделывает — и показывает весь
цикл. Все обращения к модели идут через **LLM Gateway** (маскирует секреты/PII, чистит
эксфильтрацию, ведёт аудит). Чат может писать код, но **не исполняет** его — только
проверяет.

## Как авторизоваться

1. Открой `https://<VPS_HOST>/chat/` — появится окно входа.
2. **Регистрация**: нажми «Нет аккаунта? Регистрация», введи логин и пароль (пароль ≥6
   символов), нажми «Зарегистрироваться». Сразу окажешься внутри — сессия живёт 30 дней.
3. **Вход**: логин + пароль → «Войти».
4. **Выход**: кнопка «Выйти» внизу сайдбара.

Пароли хранятся только в виде scrypt-хеша; сессия — в httpOnly-cookie, в БД лежит лишь её
хеш. **Первый зарегистрированный пользователь становится администратором** (у него в
сайдбаре появляется ссылка «админка»).

## Что можно делать

- **Несколько чатов**: «＋ Новый чат» слева, переключение кликом, удаление крестиком.
  Заголовок берётся из первого сообщения. Чаты у каждого пользователя **свои** — чужие не
  видны.
- **Переписка с накоплением контекста**: ассистент помнит предыдущие сообщения чата.
- **Два режима** (переключатель над полём ввода, на каждый чат):
  - **Обычный** — прямой ответ одним вызовом модели, с учётом истории.
  - **Execution Loop** — каждое сообщение проходит `генерация → проверка корректности →
    security review`; при провале корректности или находке Critical/High цикл возвращается
    на генерацию (до 4 кругов). Под ответом — компактный сворачиваемый трейс: чипы фаз
    (генерация / корректность / security), находки, перехваты gateway, число токенов и
    время генерации.
- **Веб-поиск и ссылки**: тумблер **«🔍 Веб-поиск»** рядом с режимом — при включении агент
  ищет в интернете по твоему сообщению. Любую вставленную `http(s)://`-ссылку он читает
  автоматически (парсинг). Использованные источники показываются под ответом (🔗).
- **Отправка**: Cmd/Ctrl+Enter или кнопка «Отправить».

## Админка (только для администратора)

`https://<VPS_HOST>/chat/admin` (ссылка «админка» в сайдбаре у админа):

- **Статистика** — пользователи, чаты, сообщения, алерты, PWNED, стоимость.
- **Пользователи** — список с ролями.
- **Журнал сообщений всех пользователей** с фильтром **«Только алерты»** и автообновлением
  (5 с). Алерт — сообщение, где сработал слой безопасности: утечка канарейки (**PWNED**),
  находка security review Critical/High, перехват gateway (маскировка секрета/PII или
  вырезание на выходе), блокировка или отказ модели.

## Безопасность (что тут защищено)

- Санитизация ввода, правила безопасности в системном промпте, egress-guard на ответах.
- **Канарейка**: в системный промпт зашита секретная фраза; если ассистент её выдаст —
  сообщение помечается **PWNED**. Вытащить её — цель для проверок на прочность.
- Gateway на входе маскирует ключи/токены/карты/email, на выходе ловит утечку системного
  промпта и эксфильтрацию.

## Примечания

- Сгенерированный код **не исполняется** — «проверка» это вызов модели, не запуск.
- Под пиковой параллельной нагрузкой gateway может отдать 502 — чат переживает: показывает
  частичный результат с пометкой, работа не теряется. Для чистого прогона шли сообщения по
  очереди.
- Реальный адрес VPS подставь вместо `<VPS_HOST>` (в git он не хранится).
