# Бенчмарк качества конфигов

Измеряем, что правила проекта, субагенты и скиллы (задачи 44–50) реально повышают качество
работы агента, а не просто занимают контекст. Метод: одна боевая задача, два прогона от
одинакового базового коммита, разные версии конфигов, сравнение диффов по рубрике.

## Что здесь лежит

| Файл | Назначение |
|---|---|
| [PROMPT.md](PROMPT.md) | точный промпт прогона — **вставляется байт-в-байт**, одинаковый для всех генераций |
| [EXPECTED.md](EXPECTED.md) | ключ оценки: что обязано быть закрыто. **Агенту не показывать** |
| [RUBRIC.md](RUBRIC.md) | 10 измерений по 0–3 балла; дельта между генерациями = драйверы качества |
| [RESULTS.md](RESULTS.md) | итог сравнения: таблица, ранжированная дельта, выводы |
| [capture.sh](capture.sh) | захват диффа генерации: `.patch` + self-contained `.html` для скриншота + статистика |
| `out/` | результаты захвата (в git не хранятся) |

## Боевая задача

Переименование заметки не обновляет `[[wikilinks]]` — после переименования все ссылки на
заметку становятся битыми (`VaultManager.rename` → `VaultFileOperations.rename` просто
перемещает файл). Реальный баг, пункт 4 [бэклога](../tasks/BACKLOG.md).

Почему именно он: данные уже есть (`LinkIndex.backlinks`, `WikilinkParser`), затрагивается
самый опасный инвариант (массовая правка файлов пользователя), богат corner-кейсами, имеет
чистое ядро, тесты и UI. То есть задействует ровно то, что описывают конфиги.

**Файл задачи `tasks/NN-*.md` для неё заранее НЕ создаём** — его создание входит в то, что мы
измеряем (агент сам проходит фазы Ф1–Ф3).

## Протокол

Воспроизводимость держится на трёх вещах: одинаковый базовый коммит, байт-в-байт одинаковый
промпт, отсутствие переписки в ходе прогона (промпт запрещает вопросы).

```bash
# 0. База: чистый коммит с конфигами v1
git tag bench-base                      # один раз

# 1. Генерация 1 — ОТДЕЛЬНАЯ сессия агента
#    Вставить содержимое PROMPT.md как единственное сообщение. Дальше не вмешиваться:
#    ни подсказок, ни уточнений — иначе сравнение испорчено.

# 2. Захват и откат
./bench/capture.sh gen1 bench-base
git reset --hard bench-base && git clean -fd

# 3. Доработка конфигов по слабым местам gen1 (CLAUDE.md, скиллы, агенты)
git commit -am "Конфиги v2: ..."
git tag bench-base-v2

# 4. Генерация 2 — ОТДЕЛЬНАЯ сессия, тот же промпт, база bench-base-v2
./bench/capture.sh gen2 bench-base-v2
git reset --hard bench-base-v2 && git clean -fd

# 5. Оценка обеих по RUBRIC.md → заполнить RESULTS.md
```

## Правила чистоты эксперимента

- **Ни одного сообщения агенту сверх промпта.** Промпт запрещает вопросы; если агент всё же
  спросил — это данные для оценки (измерение 9), а не повод отвечать.
- **Обе генерации стартуют с чистого дерева** от своего тега. Незакоммиченные хвосты
  предыдущего прогона искажают дифф.
- **Меняем ровно одну переменную** — версию конфигов. Модель, режим разрешений и содержимое
  vault одинаковы.
- **Работа генераций в `main` не остаётся:** после захвата всегда откат. Понравившуюся
  реализацию можно позже применить из `out/<label>.patch` отдельной задачей.
