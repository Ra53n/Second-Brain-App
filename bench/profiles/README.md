# Промпты для проверки сценарных профилей

По одной реальной задаче на профиль (задача 56). Каждый прогон — в свежей сессии Claude Code:
выбрать профиль, вставить его `PROMPT.md` единственным сообщением, дальше не вмешиваться.
Каждый промпт сам велит агенту работать в отдельной ветке своей итерации (`bugfix-1`,
`research-1`, `refactor-1`) — main не трогается.

| Профиль | Промпт | Задача |
|---|---|---|
| `bugfix` | [bugfix/PROMPT.md](bugfix/PROMPT.md) | реальный баг: переименование заметки ломает [[ссылки]] (пункт 4 бэклога) |
| `research` | [research/PROMPT.md](research/PROMPT.md) | реальный вопрос: как устроен слой разрешений инструментов |
| `refactor` | [refactor/PROMPT.md](refactor/PROMPT.md) | реальная область: модуль GitSync против текущих правил проекта |

Ответ research (он read-only) сохрани руками в `research/answer.md` в его ветке.

Оценка — по формату отчёта профиля: bugfix обязан показать «что нашёл / что починил / что
проверил» с зелёными `build.sh`/`test.sh`; research — ответ со ссылками `файл:строка` и ноль
правок; refactor — конкретные расхождения или честное «не требуется», поведение не изменено.

Примечание: баг переименования — тот же, что в корневом `bench/` (бенчмарк конфигов). Прогон
в ветке `bugfix-1` его не портит: в main баг остаётся, фикс живёт только в ветке.
