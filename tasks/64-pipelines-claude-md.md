# Задача 64: `CLAUDE.md` для модуля `Pipelines/`

## Тип

документация

## Модель

haiku

## Цель

`Sources/SecondBrain/Pipelines/` (движок автоматизаций: cron, PR-watch, code review) —
самый крупный модуль без своего `CLAUDE.md`. Следующему агенту, который трогает пайплайны,
не нужно каждый раз перечитывать `docs/ARCHITECTURE.md` целиком или гадать по коду.

## Зависимости

Нет.

## Объём

1. Создать `Sources/SecondBrain/Pipelines/CLAUDE.md` по шаблону существующих модульных
   CLAUDE.md (пример — `Sources/SecondBrain/RAG/CLAUDE.md`): «Что здесь живёт», «Инварианты»,
   «Как тестируем», «Частые ошибки прошлых задач» (если есть, иначе секцию не выдумывать —
   можно опустить или написать «пока нет»), «Куда не лезть».
2. Разделы «Что здесь живёт» покрывают минимум: `PipelineEngine`, `PipelineScheduler`,
   `PipelineStore`, `CronExpression`, `PRWatcher`, `PipelineModels`, `PipelineViews`,
   подпапку `CodeReview/` (GitHub-клиент, сборка ревью-инпута, раннер).
3. «Инварианты» — из инварианта №2 проекта (жизненный цикл фоновых процессов) в приложении
   к пайплайнам: как регистрируются/гасятся процессы, если пайплайн их запускает.

## Вне объёма

Правка самого кода `Pipelines/`, `docs/ARCHITECTURE.md` (если там уже есть описание —
сослаться на него, а не дублировать/переписывать).

## Критерии приёмки

- [ ] `Sources/SecondBrain/Pipelines/CLAUDE.md` создан, все обязательные секции на месте.
- [ ] Файл соответствует стилю остальных модульных CLAUDE.md (см. `RAG/CLAUDE.md`,
      `Chat/CLAUDE.md`) — комментарии по делу, без пересказа кода.
- [ ] `./scripts/build.sh` зелёный (документация не должна ничего сломать по определению,
      но прогнать для чистоты, раз того требует правило верификации).
