# Задача 48: экономия контекста и токенов

## Цель

Работа агента над задачей стоит заметно дешевле при том же результате: вывод команд не
забивает контекст, файлы-гиганты не читаются целиком, механические субагенты работают на
дешёвой модели. Пользователь получает короткий ответ по сути вместо пересказа дифа.

## Зависимости

44 (правила проекта), 45 (субагенты), 46 (скиллы) — все выполнены.

## Объём

1. `scripts/test.sh` — тихий прогон тестов: только падения (с `файл:строка`) и итоговая
   строка; сам выставляет `DEVELOPER_DIR`, пробрасывает аргументы (`--filter`), возвращает
   код возврата `swift test`.
2. `scripts/build.sh` — тихая сборка: ошибки, уникальные варнинги (дедуп — один варнинг
   печатается на каждый модуль компиляции), итоговая строка.
3. Секция «Экономия контекста» в `CLAUDE.md`: сборка и тесты только через `scripts/`;
   файлы >600 строк не читать целиком (явный список шести гигантов); ARCHITECTURE.md не
   читать целиком; git — сводками; не перечитывать файл после своей правки; субагент — на
   объёмную работу; ответ пользователю — 3–5 строк по сути.
4. `model: sonnet` для механических агентов (`coder`, `tester`, `ui-engineer`);
   аналитические (`architect`, `reviewer`, `product-analyst`) остаются на модели сессии.
5. Скиллы `/task-run` и `/task-verify` и агенты `coder`/`tester` переведены на скрипты
   вместо голых `swift build` / `swift test`.

## Вне объёма

- Сжатие CLAUDE.md и модульных конфигов (пользователь отклонил: правила должны быть
  всегда перед глазами агента).
- Реструктуризация `docs/ARCHITECTURE.md` — вместо неё правило «грепать, а не читать».
- Хуки в `.claude/settings.json`, кеширование, ограничения на размер вывода на уровне
  харнесса.

## Критерии приёмки

- `./scripts/test.sh` на зелёном прогоне печатает ≤ 2 строк вместо ~2000.
- `./scripts/test.sh` на падающем тесте печатает `файл:строка` с сообщением и возвращает
  ненулевой код — проверено намеренно сломанным тестом.
- `./scripts/build.sh` печатает уникальные варнинги без дублей по модулям.
- В `.claude/agents/` у трёх механических агентов `model: sonnet`, у трёх аналитических —
  `inherit`.
- Ни в скиллах, ни в агентах не осталось инструкций гонять голый `swift test` (кроме
  явной оговорки «когда нужен полный вывод»).

## Результат

Сделано по плану.

- `scripts/test.sh` и `scripts/build.sh` — тихие обёртки. Проверено: зелёный прогон
  1028 тестов даёт одну строку итога; намеренно сломанный тест даёт
  `ConfigTests.swift:30: error: … XCTAssertEqual failed` + код 1 (канал падений не
  проглатывает ошибки — это была главная опасность такой обёртки).
- Секция «Экономия контекста» в CLAUDE.md, 7 правил. Список файлов-гигантов явный:
  ChatViews (1212), MarkdownEditorView (1036), ChatViewModel (886), SettingsViews (830),
  MeetingsPane (661), GitClient (594).
- `coder`, `tester`, `ui-engineer` → `model: sonnet`; `architect`, `reviewer`,
  `product-analyst` → `inherit` (аналитика на модели сессии).
- Скиллы и агенты переведены на `./scripts/*.sh`.

Отклонения: пользователь отклонил сжатие конфигов — правила остаются в полном виде.

Важно для следующих задач:

- Правило «ответ 3–5 строк» — часть проектных правил, а не разовая просьба: что сделано,
  что проверено, что требует решения. Подробности только по запросу.
- Если добавляешь скрипт-обёртку над командой, обязательно проверь канал ошибок
  намеренной поломкой: тихая обёртка, глотающая падения, хуже шумной.
