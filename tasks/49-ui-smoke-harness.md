# Задача 49: смоук-гарнесс UI — ассерты, таймауты, сценарии

## Цель

Проверка интерфейса перестаёт быть самой дорогой и самой ненадёжной частью работы:
агент не виснет на `osascript`, не читает дерево целиком ради одной проверки, не врёт
«OK» там, где приложение проигнорировало клик, и не втягивает пользователя в ручные
действия посреди сессии.

## Зависимости

46 (скилл `/smoke-ui` и первые AX-рецепты), 48 (экономия контекста).

## Объём

1. `scripts/ax.applescript` — AX-примитивы: `list` (только интерактивное с подписями),
   `check <текст>` (PASS/FAIL), `click <текст>`, `dump` (аварийный), `window`.
   Поиск подписей пакетный (три Apple Event на контейнер вместо трёх на элемент) и
   в глубину — совпадение отдаёт самый конкретный элемент.
2. `scripts/ui.sh` — обёртка: жёсткий таймаут на каждый вызов (`perl alarm`),
   `preflight` (процесс, свежесть установленной сборки, окно), авто-восстановление
   закрытого окна, `restart`, запретный список необратимых кнопок
   (`SMOKE_ALLOW_DESTRUCTIVE=1` для тестового vault), `run <сценарий>`.
3. `open <Раздел>` подтверждает результат маркером раздела; не сработало — один
   авто-перезапуск приложения, затем честный FAIL с инструкцией не зацикливаться.
4. Сценарии `smoke/*.txt`: шаги `open|click|check`, один прогон — один компактный отчёт.
5. Правила в `CLAUDE.md` и скилле `/smoke-ui`: смоук только через `ui.sh`; скриншоты
   для этого приложения невозможны в принципе; где можно — проверять состояние в
   `settings.json` / `chats.json` / SQLite, а не глазами.

## Вне объёма

- Изменения в коде приложения (навигация по URL-схеме — отдельная задача).
- Автоматическое переключение vault: bookmark создаётся только через NSOpenPanel,
  тестовый vault выбирается пользователем один раз и дальше живёт в «недавних».
- Полноценный UI-тест-раннер (XCUITest): проект SPM-only, без .xcodeproj.

## Критерии приёмки

- Ни один вызов не может висеть дольше `UI_TIMEOUT` (по умолчанию 15 с).
- `check` даёт одну строку вместо дампа дерева.
- `open` не сообщает успех, если раздел фактически не открылся.
- Закрытое окно приложения восстанавливается автоматически, без вмешательства пользователя.
- Сценарий печатает построчный результат и итоговую строку, код возврата ненулевой при
  провале.

## Результат

Сделано по плану. Главное — **найдена и зафиксирована причина зависаний и ложных
результатов**, а не только уменьшен вывод.

Что подтверждено экспериментально на живом приложении:

1. **Окно появляется в Accessibility не мгновенно после `activate`.** Фиксированная
   задержка давала ложное «окно не открыто» (-1719) и уводила агента в ретраи. Теперь —
   опрос до 5 с, затем ещё 0.4 с на то, чтобы окно стало key: клик, отправленный раньше,
   принимается без ошибки и молча игнорируется SwiftUI.
2. **Полный рекурсивный обход дерева стоит десятки секунд** (три Apple Event на элемент).
   Пакетная выборка подписей (`name of every UI element of el`) уронила поиск до ~3 с.
3. **Клик по строке сайдбара переключает раздел ненадёжно.** Работал в начале сессии,
   затем перестал — причём и у старой версии скрипта, и при клике по координатам
   (`click at {x,y}`), и после перезапуска приложения. Значит, дело в самом приложении,
   а не в скрипте. Пунктов меню и горячих клавиш для разделов нет — надёжного способа
   навигации из скрипта сейчас не существует.

Поэтому гарнесс сделан **честным**: `open` подтверждает переключение маркером раздела,
делает один авто-перезапуск и, если не вышло, пишет «навигация недоступна, проверь
вручную, не зацикливайся». Прогон `smoke/meetings.txt` в текущем состоянии приложения
даёт `ИТОГ: 0 пройдено, 3 провалено` и код 1 — то есть проблема видна сразу и не съедает
сессию.

Важно для следующих задач:

- **Настоящее лекарство — навигация командой, а не кликом**: URL-схема
  `secondbrain://section/<id>` в приложении (заведено отдельной задачей). До неё смоук
  ограничен тем разделом, который открыт, и проверками по файлам данных.
- Не пытайся чинить навигацию перебором способов AX: перепробованы клик по тексту, по
  строке, по координатам, перезапуск — не работает ни один.
- Любая новая команда гарнесса обязана подтверждать результат действия. «OK» без
  проверки хуже отсутствия проверки.
