# 05 — Поиск по vault

## Цель
Мгновенный полнотекстовый поиск по заметкам и быстрый переход к файлу по имени (quick switcher).

## Зависимости
02.

## Контекст
Индекс — производные данные: живёт в `~/Library/Application Support/SecondBrain/<vault-id>/search.sqlite`, пересоздаваем. Эталон работы с system SQLite без внешних зависимостей — `RagSQLiteIndex.swift` в MA (модуль SQLite3, prepared statements, `:memory:` в тестах).

## Объём работ
- [ ] `Search/SearchIndex.swift`: SQLite FTS5 (таблица: путь, заголовок, тело, mtime); полная индексация при первом открытии vault, инкрементальная — по FSEvents (сравнение mtime); токенизатор `unicode61` (кириллица!).
- [ ] `Search/SearchViewModel.swift` + UI: поле поиска в sidebar, результаты со сниппетами (`snippet()` FTS5), клик открывает заметку.
- [ ] Quick switcher по Cmd+O (или Cmd+P): fuzzy-поиск по именам файлов, Enter открывает.
- [ ] Команда «Пересоздать индекс» (на случай рассинхрона).

## Вне объёма
Семантический поиск (это RAG, задачи 13–14), поиск по не-markdown файлам.

## Критерии приёмки
- Тесты на `:memory:`-базе: индексация temp-vault, поиск кириллицы и латиницы, инкрементальное обновление (изменён/удалён/добавлен файл), пересоздание.
- Ручная проверка: на vault пользователя (сотни заметок) поиск отзывается «мгновенно», находит слова из тела заметок.

## Подсказки
- FTS5 в системном libsqlite3 macOS доступен — проверь `sqlite3_compileoption_used("ENABLE_FTS5")` в тесте и зафиксируй.
- Для fuzzy quick-switcher FTS не нужен — фильтруй список имён в памяти (их немного).
- Все записи в индекс — вне main-потока; UI получает результаты через async.
