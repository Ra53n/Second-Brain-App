# Задача 74: тесты на `VaultWatcher.swift`

## Тип

тест

## Модель

haiku

## Цель

`Sources/SecondBrain/Vault/VaultWatcher.swift` (FSEvents/DispatchSource-обвязка) — ноль
тестов, при том что соседние `VaultScanner`/`VaultFileOperations` хоть как-то покрыты в
`VaultTests`. Файловые вотчеры — типичное место для гонок и задвоенных событий.

## Зависимости

Нет.

## Объём

1. Изучить `VaultWatcher.swift`: что именно можно протестировать без реальных FSEvents на
   диске — дебаунс/дедупликация событий, если они реализованы в проверяемой без реального
   диска форме (чистая функция «поток сырых событий → нормализованный список»).
2. Написать `Tests/SecondBrainTests/VaultWatcherTests.swift`, либо если вся логика
   неразрывно завязана на реальный FSEvents API — тест на temp-директории (по паттерну
   `VaultTests`, если он использует temp-директории) с реальными файловыми операциями и
   проверкой, что события долетают и не дублируются в разумных пределах (с таймаутом).

## Вне объёма

Рефакторинг `VaultWatcher` ради тестируемости сверх необходимого минимума.

## Критерии приёмки

- [ ] `Tests/SecondBrainTests/VaultWatcherTests.swift` существует, покрывает минимум:
      одиночное событие долетает, быстрые повторные изменения одного файла не плодят явно
      избыточные дубли (или явно задокументировано текущее поведение, если это не баг).
- [ ] Тест не флейкует (даёт стабильный результат при повторном запуске) — таймауты вместо
      `sleep` на глазок.
- [ ] `./scripts/build.sh` и `./scripts/test.sh` зелёные, число тестов не уменьшилось.
