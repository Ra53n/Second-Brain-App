# 11 — Пайплайн встречи

## Цель
Главная фича: запись превращается в оформленную заметку. Транскрипция выбранным провайдером → summary → заметка в логичной папке с датой и названием (LLM-предложенным либо заданным заранее), с настраиваемым промптом раскладки. Пайплайн переживает краш и рестарт.

## Зависимости
06 (записи), 08 (облачная транскрипция и чат). Желательно после 09/10, чтобы работали и локальные провайдеры — но не обязательно: роутинг из 07 абстрагирует.

## Контекст
Требование пользователя: встреча не должна потеряться — если название не задано до записи, после транскрипции его предлагает LLM и пользователь подтверждает/правит. Как ИИ раскладывает транскрипцию (папка, оформление) — конфигурируется промптом пользователя. Эталон FSM: `TaskFSM`/`TaskState`/`TaskContext` в `Models.swift` MA + `FSMTests.swift` (таблица переходов, guarded transitions, precondition); crash-safety: `persistNow()` после каждого шага, `normalize*()` на старте, идемпотентный resume (см. CONVENTIONS.md).

## Объём работ
- [ ] `Meetings/MeetingFSM.swift` (порт паттерна TaskFSM): состояния `recorded → transcribing → transcribed → summarizing → awaitingTitle → filing → done` (+ `failed` с причиной; из failed можно ретраить шаг). Таблица переходов — единственный источник истины, guarded `transitioned(to:)`.
- [ ] `Meetings/MeetingContext.swift` (аналог TaskContext): id, путь к аудио, назначенное заранее название (опционально), транскрипт, summary, предложенное название, целевой путь заметки, ошибки/ретраи. Codable, снисходительный `init(from:)`.
- [ ] `Meetings/MeetingStore.swift`: персистентность контекстов (паттерн ChatStore + `persistNow()` после каждого перехода); на старте приложения зависшие «в работе» → paused, кнопка «Продолжить».
- [ ] `Meetings/MeetingPipeline.swift`: оркестрация — транскрипция через роутер (функция `.transcription`), summary + предложение названия/папки через `.meetingSummary` (структурный промпт в стиле PipelinePrompts MA: `[TRANSCRIPT]`, `[VAULT_FOLDERS]`, `[USER_RULES]` → маркеры `TITLE:`, `FOLDER:`, `SUMMARY:` + парсер с тестами).
- [ ] **Конфигурируемый промпт раскладки**: пользовательский текст-инструкция (например «встречи 1:1 клади в Управление командой/1на1») хранится в настройках, подставляется в `[USER_RULES]`; дефолт — `Meetings/YYYY-MM/`.
- [ ] Итоговая заметка: `<vault>/<папка>/YYYY-MM-DD <Название>.md` — frontmatter (дата, длительность, провайдер транскрипции, ссылка на аудио) + summary + полный транскрипт (секции с таймкодами). Коллизия имён — суффикс, не перезапись.
- [ ] UI: у записи из списка (06) — кнопка «Транскрибировать»; прогресс по стадиям FSM; диалог подтверждения названия/папки (редактируемые), если название не было задано заранее; поле «название встречи» можно заполнить ДО записи — тогда пайплайн после summary идёт в filing без остановки.
- [ ] Ретраи шага при сбое провайдера (счётчики с лимитом — как maxExecutionRetries в MA).

## Вне объёма
Автозапуск записи по календарю, диаризация (19), правка транскрипта.

## Критерии приёмки
- Тесты: таблица переходов исчерпывающе по всем парам (порт FSMTests), парсер ответа LLM (TITLE/FOLDER/SUMMARY: полный, частичный, мусорный ответ), генерация пути заметки (кириллица, коллизии), resume после «краша» (контекст из JSON середины пайплайна продолжает с нужного шага), миграция контекста.
- Ручная проверка: записать голосом фейковую «встречу» → транскрибировать Deepgram/OpenAI → подтвердить предложенное название → заметка в правильной папке, открывается, ссылка на аудио работает; убить приложение во время транскрипции → после запуска «Продолжить» доводит до конца.

## Подсказки
- LLM может вернуть несуществующую папку — валидируй против реального дерева vault, фолбэк в дефолтную, но покажи пользователю.
- Название от LLM чисти для файловой системы (`/`, `:` и т.п.).
- Summary длинной встречи может не влезть в контекст маленькой модели — чанкуй транскрипт с промежуточными summary (map-reduce), задокументируй лимиты.
