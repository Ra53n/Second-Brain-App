# 13 — RAG: индексация vault

## Цель
Векторный индекс по заметкам vault: чанкинг, эмбеддинги, SQLite-хранилище, инкрементальная переиндексация при изменении файлов.

## Зависимости
02, 07 (эмбеддинги; локальные эмбеддинги появляются с 09).

## Контекст
В MA есть **готовый проверенный RAG-пайплайн** — это задача портирования, не изобретения: `RagChunking.swift` (FixedSize/Structure чанкеры), `RagEmbedding.swift` (протокол Embedder, HashingEmbedder для тестов, OllamaEmbedder), `RagVectorIndex.swift`, `RagSQLiteIndex.swift`, `RagPipeline.swift` (индексация с прогрессом и crash-safety), `RagTests.swift`. Главная адаптация: у MA источник — выбранные файлы, у нас — весь vault с автообновлением.

## Объём работ
- [ ] Портировать в `RAG/`: чанкеры (структурный по заголовкам markdown — основной), протокол эмбеддера, SQLite-индекс, пайплайн индексации. Эмбеддинги — через наш `EmbeddingProvider` (роутер, функция `.embedding`) вместо прямого OllamaEmbedder.
- [ ] Хранилище: `~/Library/Application Support/SecondBrain/<vault-id>/rag.sqlite`; метаданные чанка: путь файла, заголовочный путь (H1>H2), диапазон строк, mtime, модель эмбеддинга.
- [ ] Полная индексация vault с прогрессом (фоново, отменяемо); **инкрементальность**: FSEvents + mtime — переиндексация только изменённых файлов, удаление чанков удалённых файлов.
- [ ] Смена модели эмбеддинга инвалидирует индекс (несовместимые векторы) — детект и предложение переиндексации.
- [ ] Исключения: dot-папки, `Meetings/_recordings/`, не-markdown; настраиваемый ignore-список.
- [ ] UI: статус индекса (сколько заметок/чанков, когда обновлён), кнопки «Переиндексировать», прогресс.

## Вне объёма
Retrieval и чат (14), rerank (14).

## Критерии приёмки
- Тесты (порт RagTests + новые): чанкер по заголовкам (кириллица, код-блоки, пустые файлы), round-trip SQLite-индекса на `:memory:`, инкрементальное обновление (изменение/удаление/добавление на temp-vault), инвалидация при смене модели — всё с HashingEmbedder (без сети).
- Ручная проверка: полная индексация vault пользователя проходит, повторный запуск мгновенен (ничего не изменилось), правка одной заметки переиндексирует только её.

## Подсказки
- Косинусная близость перебором по всем векторам (как FlatVectorIndex MA) — для личного vault (тысячи чанков) этого достаточно, sqlite-vec не нужен; зафиксируй решение в ARCHITECTURE.md.
- Эмбеддинги батчами (провайдеры это умеют), не по одному чанку.
- Пайплайн должен переживать прерывание на середине: уже посчитанные чанки не пересчитывать (смотри, как RagPipeline MA делает crash-safety).

## Результат

Выполнено; `swift build` и `swift test` зелёные (470 тестов, +18 новых).

**Что сделано** (порт RAG-пайплайна MA с адаптацией «весь vault + инкрементальность»):

- `RAG/RagVector.swift` — порт Vector из MA (dot/norm/normalize/cosine/topK, brute-force как FAISS Flat; решение про «без sqlite-vec» зафиксировано в ARCHITECTURE.md).
- `RAG/RagChunker.swift` — структурный чанкер: путь заголовков «H1 > H2» (не только ближайший, как в MA), 1-based диапазоны строк, заголовки в ``` код-блоках игнорируются, длинные разделы дорезаются по строкам с сохранением пути; пустые файлы → 0 чанков.
- `RAG/RagIndex.swift` — SQLite (системный SQLite3, самописные обёртки как в MA): meta/files/chunks в одной БД `<vault-id>/rag.sqlite`, векторы Float32-LE BLOB, `replaceFile` — одна транзакция (delete+insert+mtime), `:memory:` для тестов. Отличие от MA: чанки+векторы вместе с пофайловой инкрементальностью (у MA — JSON и полная переиндексация).
- `RAG/RagIndexer.swift` — чистый пайплайн вне MainActor: скан vault (исключения: скрытое, Meetings/_recordings, не-md, ignore-префиксы; resolvingSymlinksInPath против /var-/private-мисматча), `plan()` по mtime (точность 1 мс), эмбеддинги батчами по 16 через `EmbeddingProvider`, **crash-safety: каждый файл коммитится своей транзакцией** — прерывание/отмена не теряет готовое, повтор не пересчитывает. Инвалидация: тег «model|dim» в БД ≠ текущему → `RagError.embeddingModelChanged`.
- `RAG/RagIndexManager.swift` — @MainActor владелец: индекс per-vault, фоновый Task с прогрессом/отменой, **FSEvents-автообновление (debounce 2 с) только когда индекс уже построен** (первая индексация — явная кнопка: эмбеддинги стоят денег), needsFullReindex при смене модели, ignore-список в UserDefaults.
- UI `RAG/RagStatusSection.swift` в «Настройках»: N заметок/чанков, когда обновлён, каким тегом; «Переиндексировать»/«Заново», прогресс с текущим файлом и отменой, предупреждение о смене модели, ignore-редактор.

**Тесты**: MarkdownChunkerTests (кириллица, стек заголовков, код-блоки, преамбула, диапазоны строк, дорезка длинного, без заголовков), RagIndexTests (:memory: round-trip бит-в-бит, перезапись файла, удаление, тег+clearAll, пустой файл фиксируется), RagIndexerTests (скан с исключениями, полный→инкрементальный цикл: повтор не дёргает эмбеддер, правка → только она, удаление, добавление; инвалидация тега; смоук-поиск topK; plan по mtime).

**Ручная проверка не выполнялась** (нужен ключ эмбеддингов/Ollama): полная индексация живого vault, мгновенный повторный запуск, правка одной заметки.

**Агентам следующих задач**: 14 — `ragIndexManager.currentIndex.loadAll()` + `Vector.topK` + `currentEmbeddingTag()` (проверять тег перед поиском); heading/lineStart в StoredRagChunk — для подписей источников.
