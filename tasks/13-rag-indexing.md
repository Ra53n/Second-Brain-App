# 13 — RAG: индексация vault

## Цель
Векторный индекс по заметкам vault: чанкинг, эмбеддинги, SQLite-хранилище, инкрементальная переиндексация при изменении файлов.

## Зависимости
02, 07 (эмбеддинги; локальные эмбеддинги появляются с 09).

## Контекст
В MA есть **готовый проверенный RAG-пайплайн** — это задача портирования, не изобретения: `RagChunking.swift` (FixedSize/Structure чанкеры), `RagEmbedding.swift` (протокол Embedder, HashingEmbedder для тестов, OllamaEmbedder), `RagVectorIndex.swift`, `RagSQLiteIndex.swift`, `RagPipeline.swift` (индексация с прогрессом и crash-safety), `RagTests.swift`. Главная адаптация: у MA источник — выбранные файлы, у нас — весь vault с автообновлением.

## Объём работ
- [ ] Портировать в `RAG/`: чанкеры (структурный по заголовкам markdown — основной), протокол эмбеддера, SQLite-индекс, пайплайн индексации. Эмбеддинги — через наш `EmbeddingProvider` (роутер, функция `.embedding`) вместо прямого OllamaEmbedder.
- [ ] Хранилище: `~/Library/Application Support/SecondBrain/<vault-id>/rag.sqlite`; метаданные чанка: путь файла, заголовочный путь (H1>H2), диапазон строк, mtime, модель эмбеддинга.
- [ ] Полная индексация vault с прогрессом (фоново, отменяемо); **инкрементальность**: FSEvents + mtime — переиндексация только изменённых файлов, удаление чанков удалённых файлов.
- [ ] Смена модели эмбеддинга инвалидирует индекс (несовместимые векторы) — детект и предложение переиндексации.
- [ ] Исключения: dot-папки, `Meetings/_recordings/`, не-markdown; настраиваемый ignore-список.
- [ ] UI: статус индекса (сколько заметок/чанков, когда обновлён), кнопки «Переиндексировать», прогресс.

## Вне объёма
Retrieval и чат (14), rerank (14).

## Критерии приёмки
- Тесты (порт RagTests + новые): чанкер по заголовкам (кириллица, код-блоки, пустые файлы), round-trip SQLite-индекса на `:memory:`, инкрементальное обновление (изменение/удаление/добавление на temp-vault), инвалидация при смене модели — всё с HashingEmbedder (без сети).
- Ручная проверка: полная индексация vault пользователя проходит, повторный запуск мгновенен (ничего не изменилось), правка одной заметки переиндексирует только её.

## Подсказки
- Косинусная близость перебором по всем векторам (как FlatVectorIndex MA) — для личного vault (тысячи чанков) этого достаточно, sqlite-vec не нужен; зафиксируй решение в ARCHITECTURE.md.
- Эмбеддинги батчами (провайдеры это умеют), не по одному чанку.
- Пайплайн должен переживать прерывание на середине: уже посчитанные чанки не пересчитывать (смотри, как RagPipeline MA делает crash-safety).
