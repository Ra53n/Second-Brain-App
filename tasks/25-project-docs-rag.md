# 25 — RAG-индексация документации проекта + git_diff

## Цель
Закрыть исходное требование пользователя буквально: «README + папка docs в RAG». Документация выбранного репозитория индексируется в отдельный RAG-индекс; `/help` отвечает ретривом top-K чанков (а не полным контекстом). Дополнительно — инструмент `git_diff` («по желанию — список файлов или diff»).

## Зависимости
13 (RAG-механика), 21 (инструменты и выбор репозитория), 22 (/help).

## Контекст
Сейчас /help кладёт README+docs целиком (с бюджетом 32k символов) в [PROJECT_DOCS]. Это работает, но не масштабируется на большие доки и не является RAG. Вся механика уже есть: MarkdownChunker, RagIndex (SQLite), Vector/косинус, роутер `.embedding`.

## Объём работ
- [ ] `Tools/ProjectDocsIndex.swift`: отдельный RAG-индекс доков репозитория — файл `Application Support/SecondBrain/<repo-id>/project-docs.sqlite` (repo-id — VaultID.make от пути репо), инкрементальная синхронизация по mtime (README.md + docs/*.md, чанкинг MarkdownChunker, эмбеддинги батчами через роутер), тег модели эмбеддинга как в RagIndex.
- [ ] /help-ретрив: вопрос → эмбеддинг → top-K чанков доков → блок [PROJECT_DOCS] с указанием источников (имя файла + заголовок). Фолбэк на полный контекст (текущее поведение), если эмбеддер недоступен или индекс пуст; фолбэк обязан работать без единого ключа.
- [ ] `projectDocsProvider` меняет сигнатуру на `(question) async -> String?`; синхронизация индекса лениво при /help.
- [ ] `GitClient.diff(path:)` + инструмент `GitDiffTool` (`git_diff`, `{path?: string}`, только чтение, кап 64 КБ) — в реестр projectTools.
- [ ] Тесты: индексация доков на temp-репо с мок-эмбеддером (инкрементальность по mtime, смена тега → полная переиндексация), ретрив top-K с источниками, фолбэк без эмбеддера, git_diff (изменённый файл виден, кап, пустой diff).

## Вне объёма
- Автопереиндексация по FSEvents для репозитория (доки синкаются лениво при /help).
- Индексация всего репозитория (кода) — только README и docs/*.md.
- UI управления этим индексом (кнопки/статус) — бэклог.

## Критерии приёмки
- `swift build` и `swift test` зелёные.
- С мок-эмбеддером: /help получает top-K чанков, а не всю документацию; без эмбеддера — прежний полный контекст.
- `git_diff` в чате показывает непокоммиченные изменения выбранного репозитория.
