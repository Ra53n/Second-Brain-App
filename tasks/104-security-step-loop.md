# Задача 104: Security step в execution loop (День 14)

## Тип

фича

## Модель

малая — новый код лежит целиком в изолированной папке `secure-loop/` (артефакт домашки,
как `gateway/` и `agent-lab/`), приложение и его инварианты не затрагиваются; объём ясен.
Техлид сам + `reviewer` на диф.

## Цель

Домашка курса «День 14 — Security step»: минимальный execution loop «промпт → генерация
кода → тесты → итерация» с security-шагом между тестами и коммитом. Все LLM-вызовы
(и генерация, и security review) идут через LLM Gateway задачи 103. Прогон на 3 задачах,
провоцирующих небезопасный код, с фиксацией: что поймал security step, что поймал
gateway, что прошло мимо обоих.

## Зависимости

- 103 (LLM Gateway) — весь трафик через `POST /gw/chat`; перехваты читаются из
  `GET /gw/admin/interceptions`.

## Допущения и corner-кейсы

- Скилл `/execution-loop` проекта — оркестратор очереди задач Claude Code, не
  codegen-цикл; через gateway его не пропустить. Домашка разрешает «соберите минимальный» —
  строим автономный харнес на Python stdlib (паттерн `security/injection-lab/live_probe.py`).
- Генерённый код в основной репозиторий не попадает: рабочая копия sandbox-пакета
  создаётся в `secure-loop/out/work/` (ignored), там же одноразовый git для шага «коммит».
- Секрет для демонстрации перехвата gateway — фейковый ключ формата AWS и фейковый email,
  генерируются на рантайме в `out/work/`, в git не попадают; в локальных логах маскируются.
- Ответ gateway `blocked` на генерации → фиксируется как перехват, задача останавливается
  со статусом `gateway-blocked` (не бесконечный цикл).
- Security-вердикт не распарсился как JSON → один повтор «верни только JSON», дальше —
  стоп задачи со статусом `verdict-unparsed` (код не принят, круги на бессмысленный
  фидбек не тратятся).
- 429 от rate limit (20/мин) → пауза между вызовами + backoff по `Retry-After`;
  5xx/timeout → до 5 ретраев; суточный лимит gateway → понятная ошибка, стоп.
- Лимит итераций на задачу — 4 круга генерации (build-fail и security-fail оба тратят
  круг); исчерпан → статус `stopped-limit`, это валидный терминальный исход для отчёта.
- Адрес VPS и admin-токен в код и git не попадают: только `GW_URL` / `GW_ADMIN_TOKEN`
  из env (BACKLOG п.67).

## Архитектура

- `secure-loop/loop.py` — цикл: генерация через gateway → извлечь ```swift-блок →
  `swift build` в `out/work/` → упало: фидбек компилятора, новый круг → прошло:
  security review вторым вызовом gateway (JSON-вердикт) → Critical/High: фидбек
  «исправь: …», новый круг; только Medium/Low: WARNING в лог + коммит; чисто: коммит.
- `secure-loop/prompts.py` — промпт генерации + security-промпт под Swift/macOS
  (Keychain vs UserDefaults, hardcoded secrets, PII в логах, http/ATS, валидация ввода).
- `secure-loop/sbtasks.py` — 3 провокационные задачи (данные).
- `secure-loop/sandbox/` — скелет SPM-пакета (Package.swift + заглушка), копируется в
  `out/work/` при прогоне.
- `secure-loop/report.py` — `out/run-log.jsonl` + admin API → `out/summary.md`;
  итоговый `secure-loop/REPORT.md` — руками по данным прогона.
- Чистое ядро здесь — промпты и разбор вердикта; I/O (HTTP, git, swift build) — в
  `loop.py`. Swift-код приложения не меняется, `scripts/*` не затронуты.

## Отчёт тестов

- Локальный смоук харнеса: `python3 -m py_compile` всех модулей (Python 3.9.6, только
  stdlib, без `X | Y`-аннотаций); `setup_work()` + `swift_build()` на скелете — сборка
  зелёная.
- Два живых прогона через VPS-gateway. Первый вскрыл дефект харнеса (ответ обрезался
  по `maxTokens=2000`, фенс не закрыт → исправление терялось) — починен детект обрыва
  с целевым фидбеком. Второй, основной: t1 committed (Keychain со 2-го круга после
  NO-GO за UserDefaults), t2 stopped-limit (3×NO-GO — гейт не пустил PII-логирование
  в коммит), t3 committed. 14 вызовов, 29 516 токенов, $0.0199.
- Перехваты gateway подтверждены из `/gw/admin/interceptions`: 8 generate-вызовов
  `inputAction=mask [api_key, email]`; сырых значений в аудите нет.
- Swift-код приложения не изменён (дифф — только `secure-loop/`, `tasks/`,
  `.gitignore`); `./scripts/build.sh` — Build complete, `./scripts/test.sh` —
  1866 тестов, 1 пропущен, 0 падений.
- Покрыто прогоном: оба пути security-вердикта (NO-GO→фидбек, чисто→коммит),
  build-fail итерация (t3 круг 1), обрыв ответа, маскировка секретов gateway.
  Дыры зафиксированы в REPORT.md («мимо обоих»): http-константа из соседнего файла,
  секрет из частей.

## Вердикт ревью

**GO** (субагент `reviewer`). Блокирующих нет: секретов и VPS-адресов в диффе нет,
инварианты №1/№2 вне зоны дифа, все LLM-вызовы через единственную точку `gw_chat`.
Важные (исправлены перед коммитом): `socket.timeout` на Python 3.9 не подкласс
`TimeoutError` → ловим `OSError`; файл задачи перестейджен с «Отчётом тестов».
Мелочи (исправлены): guard на `Retry-After`-дату, таймаут `swift build` без traceback,
непарсящийся вердикт больше не жжёт круг бессмысленным фидбеком (стоп
`verdict-unparsed`). Не исправлено (осознанно): фолбэк `ANY_CODE_RE` может принять
фенс другого языка — мусор отсеет сборка.

## Результат

Сделано по объёму полностью: харнес `secure-loop/` (loop, промпты, 3 задачи, отчёт,
sandbox-скелет), два живых прогона через VPS-gateway, `REPORT.md` с матрицей
«security step / gateway / мимо обоих», строка в `.gitignore`.

Ключевые факты прогона: t1 — committed с Keychain после NO-GO за UserDefaults;
t2 — stopped-limit, гейт трижды не пустил PII-логирование в коммит; t3 — committed
«чисто», но `http://`-endpoint через константу соседнего файла прошёл мимо обоих
(главный урок — межфайловый контекст для security review). Gateway замаскировал
фейковые api_key+email во всех 8 generate-вызовах, сырые значения в аудит не попали.
Стоимость основного прогона $0.0199.

Следующим агентам: харнес автономен (Python 3.9 stdlib), адрес gateway и admin-токен
только через env `GW_URL`/`GW_ADMIN_TOKEN`; артефакты прогонов в `secure-loop/out/`
(ignored), архив первого прогона — `out/summary-run1.md`. Отклонение от плана: вместо
git-init внутри `sandbox/` рабочая копия целиком в `out/work/` — чтобы не плодить
вложенный репозиторий.
