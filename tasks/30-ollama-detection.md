# 30 — Детекция Ollama: внешний сервер и нестандартные пути

## Цель
Ollama, запущенный пользователем вручную (в т.ч. из распакованного дистрибутива в домашней папке), виден приложению сразу — без «странно работает, плохо коннектится».

## Зависимости
09 (менеджер Ollama), 28 (RAG-доступность).

## Контекст (диагноз на машине пользователя)
Сервер жил в `~/ollama-dist/ollama serve` и отвечал на 11434, но: (1) `findBinary()` искал только PATH/brew/Ollama.app → `isInstalled == false`; (2) `refreshStatus()` умел распознать внешний сервер, но вызывался только при открытии вкладки «Локальные модели». Итог: `isAvailable == false` на старте — пикеры и роутер считали Ollama недоступным при живом сервере.

## Объём работ
- [ ] `refreshStatus()` при создании менеджера (внешний сервер виден сразу).
- [ ] Периодическая актуализация статуса в 30-секундном таймере (сервер запустили/погасили после старта приложения).
- [ ] Кандидаты бинаря: `~/ollama-dist/ollama`, `~/bin/ollama`, `~/.local/bin/ollama`.
- [ ] Тест: живой сервер → `.runningExternal` сразу после init.

## Вне объёма
- Настраиваемый путь к бинарю Ollama в UI (бэклог при необходимости).

## Критерии приёмки
- `swift build` и `swift test` зелёные; вживую при работающем `~/ollama-dist/ollama serve` Ollama доступен в пикере модели и для эмбеддингов сразу после запуска приложения.

## Результат

Сделано (2026-07-17): все три пункта объёма + тест `testExternalServerDetectedAtInit`. 650 тестов зелёные. Дополнительно настроен роутинг пользователя: «Эмбеддинги» → Ollama · **bge-m3** (мультиязычная, лучше для русского; у пользователя уже скачана) — записано в routing.json при перезапуске приложения. Примечание: в теге индекса размерность пишется от дефолта провайдера (768), фактические векторы bge-m3 — 1024-мерные и согласованы между индексацией и поиском; инвалидацию покрывает имя модели (см. комментарий в currentEmbeddingTag, задача 28).
