# Задача 61: смоук — одно окно, один запуск, один сводный HTML

## Цель

Замечания пользователя по итогам 59/60: (1) прогон смоука накапливает окна приложения вместо
работы в одном; (2) прогон выглядит «набором скриптовых команд» — нет одного мэйна: отчёт
рассыпан на HTML-по-сценарию. Нужно: `./scripts/smoke-all.sh` как единственная точка входа,
которая гоняет все выбранные сценарии в ОДНОМ окне приложения и отдаёт ОДИН сводный HTML
(тесты + все сценарии + дампы падений в одном файле).

## Зависимости

59, 60 (выполнены).

## Допущения и corner-кейсы (малая — техлид)

- Окна копятся из-за повторных `open -a` (`ensure_window`/`restart` на каждый AX-вызов и
  сценарий) — фикс: активировать существующий процесс вместо `open -a`, когда окно уже есть;
  один `restart` в начале прогона, а не между сценариями. Причину подтвердить эмпирически.
- Один HTML: `smoke_report.py` учится принимать несколько сценариев (TSV с колонкой сценария
  или несколько `--steps`) + блок итога тестов → единый `smoke/out/report.html`.
- Пер-сценарные HTML больше не нужны (не плодить файлы); `ui.sh run --html` для одиночного
  сценария оставить — им пользуются вручную.
- Пустой выбор/dry-run — как раньше; отчёт при 0 сценариев не создаётся.

## Архитектура (малая — техлид)

Только `scripts/` (`smoke-all.sh`, `smoke_report.py`, точечно `ui.sh`), `Sources/` не трогаем.
Чистое ядро — рендер сводного HTML в `smoke_report.py`; `smoke-all.sh` собирает все TSV/дампы
и зовёт рендер один раз. Инварианты №1/№2 не затрагиваются.

## Объём

1. `scripts/smoke_report.py` — мульти-сценарный режим: секция на сценарий (заголовок,
   счётчики, таблица шагов, `<details>`-дамп при падении), общая шапка «N сценариев,
   пройдено/провалено, итог тестов».
2. `scripts/smoke-all.sh` — собирает TSV всех сценариев + вывод тестов → один
   `smoke/out/report.html`; печатает один путь; в начале прогона приводит приложение к
   одному окну.
3. `scripts/ui.sh` — не плодить окна: активация вместо повторного `open -a`, когда процесс
   жив и окно есть; способ прогнать сценарий с выдачей TSV без генерации HTML (для smoke-all).

## Вне объёма

Sources/; новые сценарии; BACKLOG п.34/35; CI.

## Критерии приёмки

1. Полный прогон `./scripts/smoke-all.sh --full`: по завершении у приложения ровно ОДНО окно
   (проверка числом окон до/после), все 5 сценариев прогнаны.
2. Результат — ОДИН файл `smoke/out/report.html`: шапка с общими счётчиками и итогом тестов,
   5 секций-сценариев; пер-сценарных HTML прогон не оставляет.
3. Красный шаг (синтетический TSV) в сводном отчёте виден с дампом в своей секции.
4. `bash -n` / `py_compile` чисты; секретов нет; `GO` от `reviewer`.

## Отчёт тестов (верификация техлида + coder)

- Причина размножения окон — НЕ `open -a` (гипотеза), а **deep-link**: каждый
  `open "secondbrain://section/<slug>"` создаёт новое окно (SwiftUI-сцена на `onOpenURL`).
  Фикс — `close_extra_windows` после навигации в `cmd_open` + `ensure_window` активирует
  вместо `open -a` при живом окне. Попутно исправлен баг `perl exec @ARGV` (не-shift-нутый
  таймаут → подсчёт окон всегда молча падал).
- Полный прогон `./scripts/smoke-all.sh --full`: окон ДО = 1, ПОСЛЕ = 1; `Executed 1089 tests,
  0 failures`; все 5 сценариев 0 провалено; exit 0.
- `smoke/out/` — только `report.html`; в нём 5 секций `<h2>` + шапка «5 сценариев · 18 шагов»
  + строка итога тестов. Пер-сценарные HTML не создаются, старые чистятся перед прогоном.
- Синтетика: 2 группы (одна FAIL+dump) → две секции, дамп в секции упавшего, внешних ссылок нет.
- Одиночный `ui.sh run smoke/meetings.txt --html /tmp/x.html` — работает как раньше.

## Вердикт ревью

`GO`. Блокирующих нет. Важные закрыты до коммита: exit-код `smoke_report.py` теперь
проверяется (провал рендера не маскируется устаревшим файлом), артефакт полного прогона с
числом окон — выше. Мелочи (контракт `--dump-to` только с `--tsv`; last-wins в повторном
`--steps`) — приняты как есть.

## Результат

Сделано по плану: одна точка входа `smoke-all.sh` → один `smoke/out/report.html` (тесты +
5 секций-сценариев + дампы падений), прогон держит ровно одно окно приложения.

**Важно для следующих задач:**
- Deep-link `secondbrain://` открывает НОВОЕ окно на каждый вызов — это поведение приложения
  (кандидат на фикс в `Sources/App`, см. BACKLOG п.36); харнесс компенсирует
  `close_extra_windows`.
- `ui.sh run --dump-to` работает только вместе с `--tsv` (контракт smoke-all).
- Изменены: `scripts/ui.sh`, `scripts/smoke_report.py`, `scripts/smoke-all.sh`.
