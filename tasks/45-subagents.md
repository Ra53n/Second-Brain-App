# Задача 45: субагенты с разделением ответственности

## Цель

Шесть проектных субагентов с непересекающимися ролями и контекстом: продукт,
архитектор, кодер, тестировщик, UI-инженер, ревьюер. Каждый знает, что делает,
чего НЕ делает, что обязан прочитать перед работой и в каком формате
отчитывается. Накопленное знание о специфике проекта (в первую очередь —
проверка UI только через Accessibility) зашито в агента, а не теряется между
сессиями.

## Зависимости

44 (правила проекта — агенты ссылаются на CLAUDE.md и модульные конфиги).

## Объём

1. `.claude/agents/product-analyst.md` — Ф1: интервью пользователя по чек-листу
   corner-кейсов, оформление `tasks/NN-slug.md`. Не проектирует, не пишет код.
2. `.claude/agents/architect.md` — Ф2: наложение задачи на карту модулей, поиск
   переиспользуемого, точки изменения, инварианты под угрозой. Read-only.
3. `.claude/agents/coder.md` — Ф4: реализация строго по «Объёму», чистое ядро
   вперёд UI, конвенции комментариев. Не расширяет объём, не правит тесты под
   свой код.
4. `.claude/agents/tester.md` — Ф5: тесты на новую core-логику, `swift test`,
   поиск непокрытых corner-кейсов. Не правит продовый код ради зелёных тестов.
5. `.claude/agents/ui-engineer.md` — SwiftUI-слой и смоук через AX. Зашить три
   факта: окно исключено из захвата экрана (`kCGWindowSharingState = 0`,
   скриншоты дают обои); SwiftUI не отдаёт label `DisclosureGroup` в AX;
   AX-хэндл окна протухает при перестроении дерева (перезапрашивать `window 1`).
6. `.claude/agents/reviewer.md` — проверка дифа против конвенций, антипаттернов
   и инвариантов перед коммитом. Read-only, выдаёт список замечаний.
7. Секция «Субагенты» в CLAUDE.md: таблица «кто / когда звать / когда НЕ звать»
   + правило экономии (субагент — на объёмную независимую работу, не на
   «прочитать три файла»; результат субагента не перепроверяется вручную).

## Вне объёма

- Автоматический вызов агентов из скиллов (задача 46 решает сама, кого звать).
- Агенты для задач вне цикла разработки (документация, релизы).

## Критерии приёмки

- Шесть файлов с валидным frontmatter (`name`, `description`, `tools`, `model`),
  имена совпадают с именами файлов.
- У каждого агента явные секции «Делает» и «Не делает», ответственности не
  пересекаются: ни одна фраза «Делает» одного агента не встречается у другого.
- Read-only агенты (`architect`, `reviewer`) не имеют в `tools` Edit/Write.
- Агенты обязаны читать корневой CLAUDE.md и модульный конфиг своей области.
- `swift build` и `swift test` зелёные (изменения только в `.claude/` и доках).

## Результат

Сделано по плану, все шесть агентов созданы в `.claude/agents/`.

- `product-analyst` — Ф1+Ф3: разведка по коду ДО вопросов (не спрашивать то, что
  видно в репозитории), интервью пачкой через AskUserQuestion, файл задачи.
  Инструменты: Read/Grep/Glob/Bash/Write/Edit/AskUserQuestion, правит только `tasks/*.md`.
- `architect` — Ф2, read-only (без Edit/Write намеренно): куда ложится, что
  переиспользовать, где чистое ядро, персистентность и миграция, инварианты под
  угрозой, порядок работ, риски. Формат отчёта из 8 пунктов.
- `coder` — Ф4: порядок «чистое ядро → тесты → интеграция → UI», поиск
  существующего до создания нового, комментарии по ходу, запрет выхода за «Объём»
  и правки тестов ради зелёного прогона.
- `tester` — Ф5: цель «найденный баг», а не зелёный прогон; список граничных
  случаев (лимит, лимит+1, UTF-16, миграции, «значение из будущего»); изоляция от
  машины разработчика; найденный дефект описывает, но не чинит.
- `ui-engineer` — вёрстка + AX-смоук. Зашиты три факта, стоившие времени в задачах
  41–42: скриншоты окна не работают (`kCGWindowSharingState = 0`), SwiftUI не
  отдаёт label `DisclosureGroup` в AX, AX-хэндл окна протухает при перестроении
  дерева. Плюс принятые решения по UI (статус-строка вместо тулбара, явная ширина
  средней колонки) и обязанность самому перезапускать приложение после install.sh.
- `reviewer` — read-only чек-лист из 7 групп (объём, антипаттерны, паттерны,
  комментарии, нейминг, тесты, документация), вердикт одной строкой.

Отклонений от плана нет. Проверено скриптом: `name` каждого агента совпадает с
именем файла, у read-only агентов в `tools` нет Edit/Write, у всех `model: inherit`
(агент работает на модели, выбранной пользователем в сессии).

Важно для следующих задач:

- Ответственности не пересекаются намеренно: находит проблему `tester`/`reviewer`,
  чинит `coder`. Не давай read-only агентам права записи «чтобы было удобнее» —
  на этом разделении держится весь смысл.
- Правило экономии в CLAUDE.md: субагент — на объёмную независимую работу.
  Прочитать три файла дешевле самому.
