# Задача 47: статус индекса доков проекта и кнопка переиндексации

## Цель

Пользователь видит в Настройках → «Инструменты», в каком состоянии индекс документации
репозитория проекта (тот, по которому отвечает `/help`), и может перестроить его одной
кнопкой, не дожидаясь ленивой индексации при следующем вызове `/help`. Сейчас индекс
`project-docs.sqlite` полностью невидим: понять, построен ли он, устарел ли после правки
доков и на какой модели эмбеддинга собран, нельзя никак.

Выросла из пункта 21 [BACKLOG.md](BACKLOG.md) (по итогам smoke-теста 2026-07-17).

## Зависимости

25 (индексация доков проекта), 27 (вкладка «Инструменты» в настройках), 28 (секция
статуса RAG как образец UI). Все выполнены.

## Объём

1. Секция «Документация проекта» в `ToolsSettingsTab`
   (`Sources/SecondBrain/Settings/SettingsViews.swift`), по образцу `RagStatusSection`:
   строка статуса «N файлов · M чанков · <модель эмбеддинга> · обновлён <дата>» —
   данные берутся из существующего `ProjectDocsIndexService.stats(repoRoot:)`
   (`DocsIndexStats` уже содержит нужное; если какого-то поля нет — добавить в него,
   а не считать в UI).
2. Состояние «индекс не построен» — отдельный текст вместо цифр, без пугающих ошибок.
3. Кнопка «Перестроить индекс»: `reset(repoRoot:)` + немедленная полная индексация с
   индикатором прогресса (как в секции RAG), по завершении — обновлённые цифры статуса.
4. Условия недоступности: кнопка `.disabled` + причина текстом под ней —
   «репозиторий проекта не выбран» или «нет провайдера эмбеддингов: запустите Ollama или
   добавьте ключ», с переходом на нужную вкладку настроек через `SettingsTabRouter`.
5. Чистая логика подписи статуса (что показать при каждом сочетании «репо есть/нет,
   индекс есть/нет, эмбеддер есть/нет») — отдельной функцией рядом с моделью, покрытой
   тестами; в `View` только отображение.

## Вне объёма

- Автоматическая переиндексация доков по FSEvents: индексация доков остаётся ленивой
  (решение задачи 25), кнопка — единственный явный триггер.
- Настройка бюджета контекста `/help` (пункт 18 бэклога) — отдельная задача.
- Статусы индексов других баз знаний: реестр баз (задача 34) имеет свой UI.
- Изменение самой логики индексации и ретрива в `ProjectDocsIndexService`, кроме
  возможного расширения `DocsIndexStats`.

## Критерии приёмки

- `swift build` и `swift test` зелёные; новая чистая логика подписи покрыта тестами на
  все сочетания «репо / индекс / эмбеддер».
- В Настройках → «Инструменты» видно: число файлов, число чанков, модель эмбеддинга и
  дату последнего обновления индекса.
- Кнопка «Перестроить индекс» сбрасывает базу, строит заново с прогрессом и обновляет
  цифры без перезапуска приложения.
- Без выбранного репозитория и без эмбеддера кнопка неактивна, а причина написана
  текстом; клик по причине ведёт на соответствующую вкладку настроек.
- Смоук через `/smoke-ui`: раздел «Настройки» → вкладка «Инструменты», все кнопки секции
  нажимаются и делают обещанное; вывод AX-дампа приложен к «Результату».

## Ответы пользователя по corner-кейсам (интервью 2026-07-22)

- Состав статуса: файлы, чанки, модель, дата — «как в секции RAG для vault».
- Кнопка: сброс + сразу перестроить с прогрессом; стоимость эмбеддингов для доков репо
  признана незначительной.
- Недоступность: кнопка дизейблится, причина пишется текстом, рядом — переход в нужные
  настройки.
