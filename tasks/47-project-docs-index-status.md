# Задача 47: статус индекса доков проекта и кнопка переиндексации

## Цель

Пользователь видит в Настройках → «Инструменты», в каком состоянии индекс документации
репозитория проекта (тот, по которому отвечает `/help`), и может перестроить его одной
кнопкой, не дожидаясь ленивой индексации при следующем вызове `/help`. Сейчас индекс
`project-docs.sqlite` полностью невидим: понять, построен ли он, устарел ли после правки
доков и на какой модели эмбеддинга собран, нельзя никак.

Выросла из пункта 21 [BACKLOG.md](BACKLOG.md) (по итогам smoke-теста 2026-07-17).

## Зависимости

25 (индексация доков проекта), 27 (вкладка «Инструменты» в настройках), 28 (секция
статуса RAG как образец UI). Все выполнены.

## Объём

1. Секция «Документация проекта» в `ToolsSettingsTab`
   (`Sources/SecondBrain/Settings/SettingsViews.swift`), по образцу `RagStatusSection`:
   строка статуса «N файлов · M чанков · <модель эмбеддинга> · обновлён <дата>» —
   данные берутся из существующего `ProjectDocsIndexService.stats(repoRoot:)`
   (`DocsIndexStats` уже содержит нужное; если какого-то поля нет — добавить в него,
   а не считать в UI).
2. Состояние «индекс не построен» — отдельный текст вместо цифр, без пугающих ошибок.
3. Кнопка «Перестроить индекс»: `reset(repoRoot:)` + немедленная полная индексация с
   индикатором прогресса (как в секции RAG), по завершении — обновлённые цифры статуса.
4. Условия недоступности: кнопка `.disabled` + причина текстом под ней —
   «репозиторий проекта не выбран» или «нет провайдера эмбеддингов: запустите Ollama или
   добавьте ключ», с переходом на нужную вкладку настроек через `SettingsTabRouter`.
5. Чистая логика подписи статуса (что показать при каждом сочетании «репо есть/нет,
   индекс есть/нет, эмбеддер есть/нет») — отдельной функцией рядом с моделью, покрытой
   тестами; в `View` только отображение.

## Вне объёма

- Автоматическая переиндексация доков по FSEvents: индексация доков остаётся ленивой
  (решение задачи 25), кнопка — единственный явный триггер.
- Настройка бюджета контекста `/help` (пункт 18 бэклога) — отдельная задача.
- Статусы индексов других баз знаний: реестр баз (задача 34) имеет свой UI.
- Изменение самой логики индексации и ретрива в `ProjectDocsIndexService`, кроме
  возможного расширения `DocsIndexStats`.

## Критерии приёмки

- `swift build` и `swift test` зелёные; новая чистая логика подписи покрыта тестами на
  все сочетания «репо / индекс / эмбеддер».
- В Настройках → «Инструменты» видно: число файлов, число чанков, модель эмбеддинга и
  дату последнего обновления индекса.
- Кнопка «Перестроить индекс» сбрасывает базу, строит заново с прогрессом и обновляет
  цифры без перезапуска приложения.
- Без выбранного репозитория и без эмбеддера кнопка неактивна, а причина написана
  текстом; клик по причине ведёт на соответствующую вкладку настроек.
- Смоук через `/smoke-ui`: раздел «Настройки» → вкладка «Инструменты», все кнопки секции
  нажимаются и делают обещанное; вывод AX-дампа приложен к «Результату».

## Ответы пользователя по corner-кейсам (интервью 2026-07-22)

- Состав статуса: файлы, чанки, модель, дата — «как в секции RAG для vault».
- Кнопка: сброс + сразу перестроить с прогрессом; стоимость эмбеддингов для доков репо
  признана незначительной.
- Недоступность: кнопка дизейблится, причина пишется текстом, рядом — переход в нужные
  настройки.

## Допущения и corner-кейсы

- Прогресс переиндексации доков — индикатор без числовой доли (спиннер + «Переиндексация…»):
  `ProjectDocsIndexService.sync` не отдаёт колбэк прогресса (в отличие от `RagIndexer`), а
  добавлять его — не входит в объём («Изменение самой логики индексации… кроме
  `DocsIndexStats`»). Доки обычно немногочисленны, индетерминированного индикатора хватает.
- «Эмбеддер пропал, но старый индекс уже построен» — цифры и кнопка скрываются под общей
  причиной «нет эмбеддера», а не показываются отдельно как «устаревший, но валидный»: так
  матрица состояний остаётся из 4 UI-веток вместо 8, и пользователь не решает, доверять ли
  непроверяемым цифрам.
- Целевая вкладка при недоступности: «репозиторий не выбран» → «Инструменты» (репозиторий
  выбирается там же), «нет эмбеддера» → «Провайдеры» — по аналогии с шагом «Модель» в
  `ProjectWizardCard` (хотя причина может быть и в Ollama/«Локальные модели»); выбрана одна
  цель без развилки текста, чтобы не плодить два линка под одну фразу.
- Ошибки `rebuild` (сеть, эмбеддер упал на середине) проглатываются актором (`try?`), как во
  всех остальных методах `ProjectDocsIndexService` (`helpBlock`/`retrievalOutcome` тоже
  глотают ошибку) — UI покажет то, что успело проиндексироваться, без текста ошибки.

## Архитектура

- Чистое ядро — `ProjectDocsIndexUIStatus` (`Tools/ProjectDocsRag.swift`): классификатор
  «репо + эмбеддер + `DocsIndexStats?` → что показать / доступность кнопки», без I/O;
  исчерпывающе покрыт тестами на все 8 сочетаний (`ProjectDocsIndexUIStatusTests`).
- `DocsIndexStats` расширен полем `embeddingTag` (существующий тег «model|dim» из
  `RagIndex.embeddingTag`) — переиспользуем, ничего не считаем в View.
- Новый метод актора `ProjectDocsIndexService.rebuild(repoRoot:embedder:model:tag:)` —
  тонкая композиция уже существующих `reset()` + `sync()`; `ProjectToolsProvider` получил
  `hasEmbeddingProvider()` и `rebuildDocsIndex()` — `@MainActor`-обвязка (текущий репо +
  роутер эмбеддингов), по образцу соседних методов провайдера.
- UI — новый `ProjectDocsStatusSection` (`Tools/ProjectDocsStatusSection.swift`, по образцу
  `RagStatusSection` из `RAG/`): отдельная секция в `ToolsSettingsTab`, `.task(id: repoPath)`
  подгружает `stats`+`hasEmbedder`, кнопка триггерит `rebuild` с локальным
  `@State isRebuilding`; переход по причине недоступности — через существующий
  `SettingsTabRouter` (тот же канал, что у `ProjectWizardCard`).

## Отчёт тестов

- Новое чистое ядро: `ProjectDocsIndexUIStatusTests` (4 теста) — все 8 сочетаний
  «репо/эмбеддер/индекс» таблицей, `rebuildDisabled`, `unavailableReason` (включая
  `.built(_, embedderAvailable: false)`), строка статуса без даты обновления
  (граничный случай).
- `ProjectDocsRagTests`: +3 — `embeddingTag` в `stats()` после индексации,
  `testRebuildResetsThenReindexesFully` (rebuild реально переэмбеддивает файлы заново, а не
  пропускает их как неизменённые), `testRebuildPropagatesEmbeddingError` (ошибка эмбеддера
  по кнопке доходит до вызывающего, а не глотается — правка после ревью, важное 1).
- Правка по ревью (важное 1, P6): `ProjectDocsIndexService.rebuild` и
  `ProjectToolsProvider.rebuildDocsIndex` теперь `throws` вместо проглатывания через `try?`;
  `ProjectDocsStatusSection` показывает текст ошибки под кнопкой (по образцу
  `RagStatusSection.lastError`). Подтверждено живьём в разделе «Смоук UI» — реальный таймаут
  Ollama на переиндексации показал текст ошибки вместо молчания.
- Не покрыто тестами: сам `ProjectDocsStatusSection` (SwiftUI) — по конвенции модуля вёрстка
  не юнит-тестируется; проверено `/smoke-ui`, вывод — в разделе «Смоук UI».
- `./scripts/build.sh` — `Build complete!`, без новых предупреждений.
- `./scripts/test.sh` — `Executed 1095 tests, with 0 failures (0 unexpected)`.

## Смоук UI

Прогон `./scripts/ui.sh` на собранном `/Applications/SecondBrain.app` (`./install.sh` +
перезапуск), раздел Настройки → «Инструменты», секция «Документация проекта».

Известное ограничение инфраструктуры `ui.sh` (не специфично для этой задачи): обычные
`Button()` внутри `Form`/`Section` не отдают AX `name` (сравнил с `RagStatusSection` —
её кнопки «Переиндексировать»/«Заново» тоже видны только как `AXButton | button`,
`./scripts/ui.sh check` их не находит по подписи). Клик по кнопке «Перестроить индекс»
сделан точечным `osascript`, целящимся в единственную `AXButton` внутри `AXGroup`, где
лежит строка статуса — остальные шаги (`check`, `dump`) через штатный `ui.sh`.

1. **Статус-строка построенного индекса** (репо и эмбеддер есть) —
   `./scripts/ui.sh dump` в секции:
   ```
   AXStaticText | 5 файлов · 57 чанков · bge-m3|768 · обновлён 18.07.2026, 17:44
   AXButton | button
   ```
   Число файлов/чанков/модель/дата видны — критерий приёмки 2.

2. **Клик «Перестроить индекс» → прогресс:** сразу после клика
   `./scripts/ui.sh check "Переиндексация"` → `PASS  Переиндексация` (спиннер +
   «Переиндексация…» вместо кнопки, кнопка временно скрыта — критерий приёмки 3).

3. **Ошибка по ходу переиндексации доходит до UI** (живое подтверждение правки по важному
   1): локальный Ollama на машине прогона держал реальный таймаут запроса на
   эмбеддинг — `rebuild` частично прошёл (1 файл, 6 чанков) и показал ошибку вместо
   молчания:
   ```
   AXStaticText | 1 файлов · 6 чанков · bge-m3:latest|768
   AXButton | button
   AXStaticText | Error Domain=NSURLErrorDomain Code=-1001 "The request timed out." …
   ```
   До правки (`try?`) это был бы тот же экран без строки ошибки — пользователь не понял бы,
   почему цифры неполные. Кнопка после ошибки не залипла — доступна для повтора.

4. **Повторный клик → успешное завершение, цифры обновлены, ошибка снята:**
   ```
   AXStaticText | 5 файлов · 63 чанков · bge-m3:latest|768 · обновлён 26.07.2026, 23:25
   AXButton | button
   ```
   Строки ошибки нет — критерий приёмки 3 подтверждён полностью (сброс + переиндексация
   без перезапуска приложения).

5. **Недоступность кнопки без репо/эмбеддера + переход по причине** (критерий приёмки 4) —
   не воспроизведено живым кликом: на машине прогона `projectRepoPath` и провайдер
   эмбеддингов — часть реальной конфигурации разработчика в установленном
   `/Applications/SecondBrain.app`, временный сброс ради теста рискует задеть текущую
   работу. Проверено иначе: `ProjectDocsIndexUIStatusTests.testUnavailableReasonText` и
   `testAllCombinations` исчерпывающе покрывают все 8 сочетаний «репо/эмбеддер/индекс» и обе
   формулировки причины; переход по причине — тот же `SettingsTabRouter.open`, что уже
   используют `ProjectWizardCard` и чипы чата (общий, ранее проверенный путь), вызывается
   из `onOpenSettingsTab` в `ToolsSettingsTab` (`SettingsViews.swift:495-497`) без
   собственной логики.

После прогона: `./scripts/ui.sh restart` — вернул приложение в чистое однооконное
состояние.

## Результат

Секция «Документация проекта» в Настройки → «Инструменты»: статус (файлы/чанки/модель/дата),
состояние «индекс не построен», кнопка «Перестроить индекс» с индетерминированным прогрессом
и текстом ошибки при сбое, дизейбл + переход на нужную вкладку при отсутствии репо/эмбеддера.
Чистый классификатор `ProjectDocsIndexUIStatus` покрыт тестами на все 8 сочетаний.

Два круга ревью: первый NO-GO — не был прогнан AX-смоук, `rebuild` глотал ошибки через `try?`
(P6), неполный тест на `unavailableReason`. Правки: `rebuild`/`rebuildDocsIndex` стали
`throws`, ошибка доходит до UI; добавлен тест на `.built(_, embedderAvailable: false)`;
прогнан `/smoke-ui` — AX-дамп в разделе «Смоук UI» выше. Второй круг — `GO`.

Изменённые файлы: `Sources/SecondBrain/Tools/ProjectDocsRag.swift`,
`Sources/SecondBrain/Tools/ProjectToolsProvider.swift`,
`Sources/SecondBrain/Tools/ProjectDocsStatusSection.swift` (новый),
`Sources/SecondBrain/Settings/SettingsViews.swift`,
`Tests/SecondBrainTests/ProjectDocsRagTests.swift`.

Следующим агентам: недоступность кнопки без репо/эмбеддера проверена юнит-тестами и
переиспользованием `SettingsTabRouter.open`, не живым AX-кликом (риск задеть рабочую
конфигурацию машины прогона) — если понадобится живая проверка, тестовый vault/провайдер
нужно готовить отдельно.
