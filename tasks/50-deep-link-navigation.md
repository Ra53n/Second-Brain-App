# Задача 50: навигация по URL-схеме `secondbrain://`

## Цель

Раздел приложения открывается одной командой из терминала, а не кликом по сайдбару:
`open "secondbrain://section/meetings"`. Это делает смоук UI детерминированным — сейчас
AX-клик по строке сайдбара срабатывает через раз, из-за чего проверка интерфейса
съедает сессию (см. «Результат» задачи 49).

## Зависимости

17 (окно настроек и `SettingsTabRouter`), 49 (смоук-гарнесс, который этим воспользуется).

## Объём

1. `Sources/SecondBrain/App/DeepLink.swift` — чистый разбор URL → маршрут:
   `secondbrain://section/<slug>` (notes, meetings, chat, pipelines, settings) и
   `secondbrain://settings/<tab>` (вкладки `SettingsTab`). Неизвестный хост, слаг или
   схема → `nil`, приложение молчит.
2. `AppSection.slug` + `init?(slug:)` — стабильные английские идентификаторы (rawValue
   русский и служит подписью в UI, в контракт ссылок его тащить нельзя).
3. Нотификация `.openSection` (object — `AppSection`); `ContentView` слушает и
   переключает `selection`, для маршрута настроек — `SettingsTabRouter.open`.
4. `.onOpenURL` в `ContentView` — единственная точка входа ссылок.
5. `run.sh`: `CFBundleURLTypes` со схемой `secondbrain` в генерируемом Info.plist.
6. `scripts/ui.sh`: `open <Раздел>` сначала пробует deep link, AX-клик остаётся
   фолбэком для старых сборок.
7. Тесты `DeepLinkTests`: все валидные маршруты, мусор, чужая схема, регистр, лишние
   компоненты пути, пустой путь.

## Вне объёма

- Ссылки на конкретную заметку/чат/встречу (`secondbrain://note?path=…`) — отдельная
  задача, если понадобится.
- Любые маршруты с побочными эффектами: URL может открыть кто угодно (веб-страница,
  другое приложение), поэтому схема умеет **только навигацию** — ни записи, ни удаления,
  ни запуска пайплайнов.
- Регистрация схемы в системе для незапущенного приложения через LaunchServices сверх
  того, что даёт установка `.app`.

## Критерии приёмки

- `open "secondbrain://section/meetings"` на установленном приложении открывает раздел
  «Встречи»; то же для остальных разделов.
- `open "secondbrain://settings/tools"` открывает окно настроек на вкладке «Инструменты».
- Мусорный URL ничего не ломает и не меняет экран.
- `./scripts/ui.sh open Встречи` использует deep link и подтверждает открытие маркером.
- `./scripts/test.sh` зелёный, разбор покрыт тестами на все маршруты и на мусор.

## Результат

Сделано по плану.

- `App/DeepLink.swift` — чистый `DeepLinkParser` (URL → `DeepLink`), `AppSection.slug`
  и `init?(slug:)`, нотификация `.openSection`. Разбор без побочных эффектов и без
  SwiftUI, поэтому тестируется исчерпывающе.
- `ContentView`: `.onOpenURL` → переключение раздела или `SettingsTabRouter.open`.
- `run.sh`: `CFBundleURLTypes` со схемой `secondbrain`.
- `scripts/ui.sh`: `open` сначала пробует `open "secondbrain://section/<slug>"`,
  проверяет маркер раздела и только при неудаче падает на AX-клик.
- 7 тестов в `DeepLinkTests` таблицами: все разделы, все вкладки настроек, регистр,
  8 видов мусора, лишние компоненты пути, обратимость slug ↔ AppSection.

Дополнительно всплыло и учтено: при повторных `open -a` окна приложения
накапливаются (насчитал восемь), и `window 1` может указывать не на то окно,
которое видит пользователь, — вероятная причина части прежних флейков AX. `check`
теперь при неудаче ищет во всех окнах процесса, а `restart` их вычищает. Поиск
разделён: `check` идёт «сверху вниз» (подпись почти всегда на верхних уровнях,
3 с вместо таймаута), `click` — вглубь, чтобы нажать самый конкретный элемент.

Проверено на установленном приложении: `open "secondbrain://section/meetings"` и
остальные разделы открываются мгновенно и стабильно — то, чего не удалось добиться
кликами; `./scripts/ui.sh run smoke/meetings.txt` даёт зелёный отчёт.

Важно для следующих задач:

- **Навигация в смоуке — только через deep link.** AX-клик по сайдбару остался
  фолбэком, но полагаться на него нельзя.
- URL — недоверенный ввод: любое приложение или веб-страница может открыть ссылку.
  Добавляя маршрут, оставляй его чисто навигационным; всё, что меняет данные, должно
  требовать явного действия пользователя в UI.
- Схема регистрируется в LaunchServices при установке `.app`. После правки `run.sh`
  нужен `./install.sh`, иначе система не знает о схеме.
