# Backlog проекта

Единый бэклог: сюда записываются **все** будущие задачи проекта. Правила:

- Новая идея/задача → запись здесь (название, абзац описания, зависимости, дата и происхождение).
- Когда задача берётся в работу, она «вырастает» в нумерованный файл `tasks/NN-slug.md` в стандартном формате (Цель/Зависимости/Объём работ/Вне объёма/Критерии приёмки) и добавляется строкой в [00-INDEX.md](00-INDEX.md). Здесь пункт помечается `→ NN`.
- Приоритет финально выбирает пользователь; порядок ниже — рекомендация.
- История: до 2026-07-16 бэклог жил в [19-polish-backlog.md](19-polish-backlog.md).

## Добавлено по итогам задачи 58 (2026-07-25)

Расхождения поведения, найденные при написании тестов (задокументированы тестом как факт, продовый код не менялся — вне объёма tests-only задачи 58). Каждое — потенциальный багфикс-профиль.

30. **`RagVector.cosine` возвращает NaN на Infinity-компоненте** (`RAG/RagVector.swift:30-34`): `guard na > 0` ложен для NaN, но проходит для `Infinity`, и до деления доходит `∞/∞ = NaN`. Комментарий обещает диапазон `[-1, 1]`. NaN-score способен исказить порядок `topK`. Решить, клампить ли Infinity или явно возвращать 0.
31. **`CodeRegionDetector`: незакрытый код-блок не защищает содержимое** (`Editor/CodeRegionDetector.swift:20-23`): ` ``` ` без закрывающей тройки → `excludedRanges` пуст, весь текст после неё открыт для inline-парсеров (wikilinks/чеклисты и т.п.). Смежно: ` ```code``` ` в середине строки случайно ловится инлайн-регексом. Детектор приблизительный — оценить, нужна ли защита «до конца документа» при незакрытой тройке.
32. **`FrontmatterParser`: пустой frontmatter-блок теряется при сериализации** (`Links/FrontmatterParser.swift:64`): `"---\n---\nтело"` парсится в `entries=[]`, а `serialized()` при пустых entries отдаёт только body, срезая маркеры `---\n---`. Нарушает заявленный в шапке модуля byte-exact round-trip (единственный найденный случай).
