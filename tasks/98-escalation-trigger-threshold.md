# Задача 98: настраиваемый порог эскалации (дефолт — только FAIL)

## Тип

фича (полная: новое персистентное поле треда)

## Модель

Fable 5

## Цель

Порог вызова сильной модели настраивается и по умолчанию понижен: эскалация — только
при FAIL (битый формат, hard-fail проверок, расхождение повторов, самооценка < 40);
UNSURE остаётся ответом micro с жёлтым чипом. Сейчас эскалация уходит почти на каждый
запрос (UNSURE|FAIL при плохо откалиброванной самооценке 3B), и по статистике
непонятно, справляется ли маленькая модель.

## Зависимости

91 (эскалация), 95–97. Выполнены.

## Допущения и corner-кейсы

- Требование пользователя: «сейчас она практически всегда вызывается… порог будет
  понижен» — дефолт меняется на «только FAIL» осознанно, в том числе для
  существующих тредов (отсутствующее поле → новый дефолт). Прежнее поведение
  возвращается пикером «UNSURE или FAIL».
- `EscalationTrigger: String, Codable` = `failOnly` (дефолт) | `unsureOrFail`;
  снисходительный декодер: незнакомое значение «из будущего» → `.failOnly`.
- Поле per-thread (`TuningChatThread.escalationTrigger`, рядом с `escalationEnabled`) —
  сравнение режимов между тредами осмысленно.
- `shouldEscalate(enabled:verdict:trigger:)`: failOnly → только `.fail`;
  unsureOrFail → как раньше. OK не эскалирует никогда.
- UI: пикер «Порог» в строке цели эскалации (виден при включённом чипе «Эскалация»);
  AX-value; disabled при isGenerating.
- Снимок trigger до Task в `send()` (P5, как остальные снапшоты эскалации).
- Вердикт-осознанная композиция (95), нормализация (97), батч — не меняются.

## Критерии приёмки

1. Дефолт: UNSURE-ответ micro НЕ эскалируется (остаётся с жёлтым чипом), FAIL —
   эскалируется; в режиме «UNSURE или FAIL» — прежнее поведение (тест VM обоих).
2. Пикер порога виден при включённой эскалации, выбор per-thread и переживает
   перезапуск; миграция старых тредов → `.failOnly` (тест).
3. `./scripts/build.sh`, `./scripts/test.sh` зелёные; ревью GO.

## Результат

Порог вызова сильной модели настраивается пикером «Порог» рядом с целью эскалации:
дефолт — «только FAIL» (эскалация лишь на явный провал: битый формат, hard-fail
проверок, расхождение повторов, самооценка < 40), «UNSURE или FAIL» возвращает прежнее
поведение. Дефолт сознательно распространён и на существующие треды. UNSURE-ответы
micro остаются в чате с жёлтым чипом — строка «Micro-first» теперь показывает реальную
долю запросов, закрытых маленькой моделью.

Важно следующим агентам: поле тредовое (`TuningChatThread.escalationTrigger`);
`shouldEscalate` имеет дефолт-параметр `.failOnly` — прод-вызовы обязаны передавать
снимок явно; VM-тесты механики эскалации требуют явного `.unsureOrFail`.
