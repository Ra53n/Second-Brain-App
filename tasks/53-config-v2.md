# Задача 53: конфиги v2 — зашитый конвейер ролей, верификация, сжатые комментарии

## Цель

Правила проекта заставляют агента вести содержательную задачу через явный конвейер ролей
(как SDLC в компании), доказывать корректность верификацией и писать комментарии по делу —
и всё это срабатывает даже на автономном промпте, без вызова скиллов. Основано на разборе
первого прогона бенчмарка (gen1, задача 52), где ничего из этого не запустилось.

## Зависимости

44 (правила), 45 (субагенты), 46 (скиллы), 48 (экономия токенов), 51 (бенчмарк) — все есть.

## Объём

1. **Конвейер разработки** — новая секция в `CLAUDE.md` (always-on) + пункт в «Жёстких
   правилах». Главный агент — техлид-оркестратор, для содержательной задачи ОБЯЗАН провести
   её через стадии и **сам не кодит**. Стадии и обязательные артефакты в файле задачи:
   Продукт (`product-analyst` → `## Допущения и corner-кейсы`), Архитектура (`architect` →
   `## Архитектура`), Разработка (`coder` → код), Тестирование (`tester` → `## Отчёт тестов`),
   UI при наличии (`ui-engineer` → смоук `./scripts/ui.sh`), Ревью (`reviewer` →
   `## Вердикт ревью`, гейт GO/NO-GO перед коммитом). Порог: полный конвейер на всё, что
   требует файла задачи; тривиальное — solo + верификация. Автономный режим совместим:
   `product-analyst` документирует допущения вместо вопросов.
2. Переписать секцию **«Субагенты»** в `CLAUDE.md` (опционально → обязательно для
   содержательных, solo для тривиальных); привести флоу **Ф1–Ф6** в соответствие ролям.
3. `.claude/skills/task-run/SKILL.md` — сделать оркестратором конвейера (делегирование стадий
   + сбор артефактов).
4. Каждому `.claude/agents/*.md` — контракт: вход и **обязательный артефакт**.
5. **Верификация в «Жёстких правилах»**: «Готовность = проверено» (build/test прогнаны и
   результат приведён, финальный отчёт верификации 3–5 строк); лазейку «UI не менялся»
   закрыть — для UI-достижимой логики интеграционный тест пути + трассировка «кнопка → функция».
6. **Сжать комментарии** синхронно: `docs/CONVENTIONS.md` (секция «Комментарии»),
   `CLAUDE.md` (шаблон файла ≤3 строк шапки, антипаттерн «комментарий-пересказ»),
   `.claude/agents/coder.md`, `.claude/skills/task-run/SKILL.md`. Минимум по делу, ~10–15%.
7. Оформление: строка в `00-INDEX.md`, запись в «Журнал отклонений», коммит на `main`,
   тег `bench-base-v2`.

## Вне объёма

- Реализация rename (gen2 сделает её от `bench-base-v2`).
- Переписывание существующего кода под новую конвенцию комментариев — правило вперёд.
- Реструктуризация модульных `CLAUDE.md` по содержанию (кроме упоминаний плотности).

## Критерии приёмки

- `grep -rn "3–10\|плотн\|/// на каждый\|опциональн" CLAUDE.md docs/CONVENTIONS.md .claude/`
  пусто — старые формулировки не остались.
- `CLAUDE.md` содержит секцию «Конвейер разработки» с таблицей стадия→агент→артефакт, порогом
  и ревью-гейтом; «Жёсткие правила» — «Готовность = проверено» + отчёт верификации.
- Шаблон файла в `CLAUDE.md` — шапка ≤3 строк, без «Здесь живут:».
- `./scripts/build.sh` и `./scripts/test.sh` зелёные (код не тронут).
- Тег `bench-base-v2` на коммите задачи 53; строка 53 в `00-INDEX.md`.

## Результат

Сделано по плану. Задача — конфиги/доки (кода нет), поэтому стадии `coder`/`tester`/
`ui-engineer` неприменимы; верификация — grep-проверки + build/test.

**Блок 1 — конвейер.** В `CLAUDE.md` секция «Субагенты» заменена на «Конвейер разработки»:
таблица стадия→агент→артефакт (Продукт→Архитект→Кодер→Тестер→UI→Ревью), ревью-гейт GO/NO-GO,
порог «конвейер для содержательного / solo для тривиального», техлид сам не кодит. Флоу Ф1–Ф6
привязан к стадиям. `/task-run` переписан в оркестратора конвейера. Каждому агенту дописан
контракт «обязательный артефакт»: product-analyst → `## Допущения и corner-кейсы` (автономно —
документирует, не спрашивает), architect → `## Архитектура`, tester → `## Отчёт тестов`,
ui-engineer → вывод `./scripts/ui.sh`, reviewer → `## Вердикт ревью` + GO/NO-GO.

**Блок 2 — верификация.** В «Жёсткие правила» добавлены «Готовность = проверено» (build/test
прогнаны + отчёт верификации 3–5 строк) и закрытие лазейки «вёрстка не менялась» (для
UI-достижимой логики — интеграционный тест пути + трассировка «кнопка → функция»).

**Блок 3 — комментарии.** `CONVENTIONS.md` секция «Комментарии» переписана на «минимум по
делу, ~10–15%», шаблон файла в `CLAUDE.md` сжат (шапка ≤3 строк, без «Здесь живут:»),
антипаттерн 9 «комментарий-пересказ» добавлен, coder.md / task-run / port-from-ma
синхронизированы. Расхождение с MA по объёму комментариев оговорено осознанно.

**Проверка:** `grep` старых формулировок («3–10», «плотн», «/// на каждый», «опциональн»)
пусто (кроме оговорки про MA); `./scripts/build.sh` зелёный без новых варнингов;
`./scripts/test.sh` — 1035 тестов, 0 падений (код не тронут).

**Важно для следующих:**
- Дисциплина теперь в always-on `CLAUDE.md`, а не в опт-ин скиллах — срабатывает и на голом
  промпте (урок gen1). Скиллы остались детальными процедурами.
- Артефакт-секции в файле задачи — механизм контроля: нет секции стадии → задача не готова,
  скип виден в диффе.
- Тег `bench-base-v2` = этот коммит: точка старта gen2 тем же `bench/PROMPT.md`.
