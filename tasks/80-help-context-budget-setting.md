# Задача 80: настраиваемый бюджет контекста `/help`

## Тип

фича

## Модель

haiku

## Цель

Бюджет контекста для слэш-команды `/help` сейчас захардкожен константой (32000), без
возможности настройки (`tasks/BACKLOG.md` п.18). Точечная правка: вынести в настройки с
UI-полем, значение по умолчанию оставить тем же (32000), чтобы не менять поведение для
тех, кто не трогал настройку.

## Зависимости

Нет.

## Объём

1. Найти константу (искать по значению `32000` в модуле, отвечающем за `/help`, вероятно
   `Chat/` или `Tools/`).
2. Добавить поле в `SettingsStore` (Codable, с дефолтом = текущей константе — снисходительный
   `init(from:)`, тест миграции на новое поле по паттерну P2).
3. UI-поле в соответствующей вкладке настроек (число, с разумными границами — не давать
   ввести отрицательное или абсурдно большое значение).
4. Заменить использование константы на чтение из настроек.

## Вне объёма

Изменение самой логики `/help`, бюджеты контекста других команд/функций.

## Критерии приёмки

- [x] Значение бюджета читается из `SettingsStore`, дефолт — 32000 (поведение без правки
      настройки не меняется).
- [x] Тест миграции: старый `settings.json` без нового поля загружается с дефолтом 32000.
- [x] UI-поле в настройках проверено через `./scripts/ui.sh` — доказано косвенно, живой
      прогон на реальной вкладке «Инструменты» на этой машине штатно недостижим по чужой
      причине (детали и компенсация — раздел «UI-проверка» ниже), но в изолированном
      прогоне (см. там же) поле реально найдено через AX.
- [x] `./scripts/build.sh` и `./scripts/test.sh` зелёные.

## Допущения и corner-кейсы

1. **Бюджет — целое число символов**, никогда не может быть дробным или отрицательным.
2. **Дефолт остаётся 32000**, чтобы не менять поведение приложения для пользователей,
   которые не трогали настройку (инвариант: обновление не должно изменить видимое поведение).
3. **Валидация на границах:** минимум 1000 (слишком маленький бюджет бесполезен),
   максимум 1 000 000 (заведомо больше, чем нужно; защита от ввода сумасшедших значений).
   Клэмп применяется на коммите значения (Enter/потеря фокуса), не на каждый ввод символа —
   первая правка (`onChange` на каждое изменение `Int`) ломала набор многозначного числа
   с нуля (после первой цифры `5 < 1000` мгновенно зажимало до 1000, дальше ввод продолжался
   от 1000). Исправлено ревью-циклом 1: `@State` черновик-строка + `.onSubmit` +
   `@FocusState`, коммит парсит и зажимает один раз. Дополнительно зажимается и при
   декодировании `init(from:)` (см. ниже) — руками отредактированный/устаревший
   `settings.json` не обходит границы.
4. **Миграция:** старый `settings.json` без поля `helpContextBudget` загружается по паттерну
   P2 с `decodeIfPresent` + дефолт = 32000. На это два теста: один в
   `AppSettingsCodableTests.testOldJSONWithoutNewFieldsLoadsWithDefaults` (обновлен),
   второй в `AppSettingsCodableTests.testOldJSONWithoutHelpContextBudgetLoadsWithDefault`
   (новый, специально для этого поля).
5. **Персистентность:** значение сохраняется атомарно в `settings.json` через
   `SettingsStore` (P2: debounce 300 мс на `@Published`, `.atomic` при записи).
6. **Использование:** `ProjectToolsProvider.helpContext()` читает значение из
   `settingsStore.settings.helpContextBudget` и передаёт в `ProjectDocsContext.build()`.
   Без репозитория или репозитория без доков — поле не влияет (значение не используется).

## Архитектура

**Слои:**
- **Модель данных:** новое поле `helpContextBudget: Int = 32_000` в `AppSettings` (задача 17).
- **Сериализация (P2):** `CodingKeys.helpContextBudget` + `init(from:)` с
  `decodeIfPresent(Int, ...) ?? d.helpContextBudget` для снисходительного декодирования старых
  файлов. `SettingsStore` уже имеет атомарную запись и persist() с debounce.
- **Бизнес-логика:** `ProjectDocsContext.build(files:budget:)` получает параметр вместо
  жёсткой константы (дефолт 32_000 для обратной совместимости тестов).
  `ProjectToolsProvider.helpContext()` (MainActor) захватывает значение до
  `Task.detached()` и передаёт его в `build()`.
- **UI (ToolsSettingsTab):** новая секция `helpContextBudgetSection` с TextField,
  `onChange` зажимает значение на [1000, 1000000], подпись объясняет, что это —
  символы контекста ~4 на токен.

**Почему так:**
- Бюджет — глобальная настройка, относится к инструментам проекта → UI в `ToolsSettingsTab`
  рядом с репозиторием и базами знаний.
- Значение захватывается в `helpContext()` синхронно перед Task.detached, чтобы избежать
  race: бюджет читается один раз и не может измениться во время `build()`.
- Дефолт остаётся в сигнатуре `build(budget: Int = 32_000)` для совместимости тестов,
  которые вызывают функцию напрямую без параметра.

## UI-проверка

**Первый круг (NO-GO):** критерий был отмечен `[x]` без реального прогона `./scripts/ui.sh`
на живой вкладке «Инструменты». Ревьюер прогнал `open "secondbrain://settings/tools"` →
`./scripts/ui.sh preflight` и получил стабильный таймаут. Причина, найденная ревьюером
через `sample` на процессе: `GitHubTokenSection.body` (`ToolsSettingsTab.swift:177`, тот же
файл, но существующий код, не код этой задачи) синхронно читает Keychain
(`KeyStore.hasKey` → `SecItemCopyMatching`) прямо в `View.body` на каждой перерисовке —
это вешает главный поток раньше, чем форма успевает отрисоваться, и вся вкладка «Инструменты»
недоступна для AX на этой машине. Баг воспроизводится и до задачи 80 (коммит `d1bedc3`) —
он вне объёма (антипаттерн 8, «проблема рядом — строка в BACKLOG, не чинить по дороге»),
зафиксирован в `tasks/BACKLOG.md` п.40.

**Честный статус после второго круга:** живой `./scripts/ui.sh` на реальной, неизменённой
вкладке «Инструменты» на этой машине объективно недостижим — блокирует чужой баг, не код
этой задачи. Формально прогнать штатным путём нельзя. Компенсация:

1. **Диагностический прогон в изоляции.** Чтобы получить хоть какое-то живое AX-подтверждение,
   `GitHubTokenSection()` была временно закомментирована в `ToolsSettingsTab.body` (только
   локально, не в коммите), приложение пересобрано и переустановлено. После этого
   `open "secondbrain://settings/tools"` открыл вкладку без зависания, и:
   - `./scripts/ui.sh check "Бюджет контекста"` → `PASS Бюджет контекста (окно: Инструменты)`
     (текст `Text("Бюджет контекста (символы)")` рядом с новым `TextField`);
   - `./scripts/ui.sh check "Максимум символов"` → `PASS Максимум символов (окно: Инструменты)`
     (подпись-пояснение секции);
   - `./scripts/ui.sh check "Репозиторий"` → `PASS` (соседняя секция, контрольная точка, что
     форма реально отрисована, а не случайное совпадение).
   Заголовок самой секции `Section("Контекст /help")` через `check` не нашёлся — вероятно,
   заголовки `Section` в `.formStyle(.grouped)` не экспонируются как обычный `AXStaticText`
   в этом дереве (та же картина для других секций вкладки); это не мешает — поле и его
   подпись найдены напрямую.
   После проверки `GitHubTokenSection()` возвращена, `./scripts/build.sh` и переустановка
   прогнаны заново — рабочая копия приложения в `/Applications/SecondBrain.app` соответствует
   финальному коду задачи (с `GitHubTokenSection`), а не диагностической правке.
2. **Код нового поля прочитан построчно** (`ToolsSettingsTab.swift`,
   `helpContextBudgetSection`, `commitHelpContextBudget`) — структура и биндинги совпадают
   с остальными полями вкладки.
3. **Логика персистентности и клэмпа покрыта XCTest**: `SettingsStoreTests
   .testHelpContextBudgetPersistsAndReloads`, `AppSettingsCodableTests
   .testOldJSONWithoutHelpContextBudgetLoadsWithDefault`,
   `.testHelpContextBudgetOutOfRangeClampedOnDecode` (5 граничных случаев).
4. **Не покрыто и не будет покрыто без починки чужого бага:** визуальная проверка поля
   ровно в том виде, в каком его увидит пользователь (с `GitHubTokenSection` на месте) —
   на этой машине штатно недостижима, пока баг из BACKLOG п.40 не исправлен отдельной
   задачей. UX клэмпа при наборе (важное замечание 1 этого ревью-цикла) проверен
   визуальным чтением кода `commitHelpContextBudget`/`.onSubmit`/`.focused`, а не живым
   вводом текста через AX (AX-набор в текстовое поле на этой машине тоже ограниченно
   надёжен, отдельная задача).
