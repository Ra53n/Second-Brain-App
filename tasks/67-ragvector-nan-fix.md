# Задача 67: `RagVector.cosine` возвращает NaN при Infinity-компоненте

## Тип

баг

## Модель

haiku

## Цель

`RagVector.cosine` (`Sources/SecondBrain/RAG/RagVector.swift:30-34`) даёт `NaN` вместо
осмысленного числа, если один из векторов содержит `Infinity`-компоненту (найдено тестами
задачи 58, зафиксировано в `tasks/BACKLOG.md` п.30). `NaN` в скоринге ретрива ломает
сортировку `topK` (NaN непредсказуемо ведёт себя в сравнениях) — пользователь получает
испорченный порядок результатов RAG без единой ошибки в логах.

## Зависимости

Нет.

## Объём

1. `Sources/SecondBrain/RAG/RagVector.swift:30-34` — `cosine`: защититься от `Infinity`/
   `NaN` во входных компонентах. Решение — на выбор исполнителя: либо явный `guard` с
   возвратом `0` (семантика «нет сходства» для дефектного вектора), либо клампинг
   компонентов перед вычислением; главное — не отдавать `NaN` наружу.
2. Тест на этот граничный случай (если реальный embedding никогда физически не может дать
   Infinity — тест всё равно нужен: это защита от мусора на входе, а не от гипотетики).

## Вне объёма

Изменение алгоритма `topK`, пересчёт существующих индексов.

## Критерии приёмки

- [ ] `cosine` с вектором, содержащим `Float.infinity`, не возвращает `NaN`.
- [ ] Новый тест в `Tests/SecondBrainTests/RAG*Tests.swift` (или отдельный файл, если такого
      ещё нет для `RagVector`) воспроизводит кейс и проверяет исправление.
- [ ] `./scripts/build.sh` и `./scripts/test.sh` зелёные, число тестов не уменьшилось.
