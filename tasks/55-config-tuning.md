# Задача 55: тюнинг конфигов — три уровня конвейера вместо двух, убраны чистые потери токенов

## Цель

Задача 53 сделала 6-стадийный конвейер ролей обязательным для любой содержательной задачи
без промежуточного режима. На практике небольшая задача через полный конвейер тратит ~360k
токенов — в 4–5 раз больше, чем без конвейера. Разведка нашла источники: (1) двойное чтение
корневого `CLAUDE.md` — субагенты и так получают его автоматически при старте (кроме
Explore/Plan), а `.claude/agents/*.md` дополнительно просят прочитать его через `Read`;
(2) дублирование build/test/UI-смоука между стадиями конвейера и `/task-verify`, плюс битый
путь к AX-скрипту в `task-verify`; (3) бинарный порог «конвейер / solo» без промежуточного
уровня — любая не-тривиальная задача получает все 6 стадий целиком, даже когда объём и так
понятен техлиду из собственной разведки. Решение о полной обязательности (задача 53) принято
без замера цены: `bench/RESULTS.md` остался незаполненным шаблоном.

Цель — убрать чистые потери без риска для качества и ввести уровень «малая задача» между
solo и полным конвейером, оставив независимую проверку (`coder`/`tester`/`reviewer`) там, где
она ловит реальные проблемы.

## Зависимости

53 (конфиги v2, конвейер и верификация) — есть.

## Объём

1. `CLAUDE.md`:
   - раздел «Экономия контекста» — пункт о том, что корневой и модульные `CLAUDE.md` уже в
     контексте субагента автоматически, не просить их читать заново;
   - раздел «Конвейер разработки» — порог из двух уровней заменить на три (тривиальная /
     малая / полная) таблицей с критериями; для малой — техлид сам делает Продукт+Архитектуру
     компактно, без спавна `product-analyst`/`architect`; лимит на NO-GO (2 круга — стоп,
     вопрос пользователю);
   - раздел «Флоу работы» (Ф1/Ф2) и «Жёсткие правила» — синхронизировать формулировку с
     новым порогом.
2. `.claude/agents/{product-analyst,architect,coder,tester,ui-engineer,reviewer}.md` — убрать
   из «Читай перед началом» явное упоминание чтения корневого `CLAUDE.md` (модульный оставить).
3. `.claude/agents/architect.md` — проверку таблицы портирования Manager Assistant в
   `docs/CONVENTIONS.md` сделать условной («если задача создаёт подсистему с нуля»).
4. `.claude/skills/task-run/SKILL.md` — раздел «Порог» синхронизировать с таблицей из
   `CLAUDE.md` (три уровня, кто что делает на «малой»). `.claude/skills/task-plan/SKILL.md` —
   убрать из «Контекста» чтение корневого `CLAUDE.md` (тот же дефект, что в агентах).
5. `.claude/skills/task-verify/SKILL.md`:
   - шаг 5 (UI-смоук) — заменить битый путь `.claude/skills/smoke-ui/ax.applescript` на
     `./scripts/ui.sh`; добавить условие «не гонять заново, если `ui-engineer` уже прогнал
     смоук в этом конвейере на актуальном дифе»;
   - шаг 1 (build/test) — то же условие для `coder`/`tester`.
6. Строка 55 в `tasks/00-INDEX.md`, запись в «Журнал отклонений».

## Вне объёма

- Повторный прогон бенчмарка (gen3) для количественного подтверждения экономии.
- Состав `tools:`/`model:` у агентов — уже разумный, не трогаем.
- Параллелизация независимых стадий — снижает задержку, не токены; не по теме жалобы.

## Критерии приёмки

- `grep -rn "Читай.*CLAUDE.md.*в корне\|(CLAUDE.md в корне)" .claude/agents/*.md` — пусто.
- `grep -n "ax.applescript" .claude/skills/task-verify/SKILL.md` — либо отсутствует, либо
  указывает на `scripts/ax.applescript`/`./scripts/ui.sh`, не на несуществующий путь.
- `CLAUDE.md` содержит таблицу из трёх уровней порога (тривиальная/малая/полная) в разделе
  «Конвейер разработки»; `task-run/SKILL.md` синхронизирован.
- `grep -n "среднего нет" CLAUDE.md` — пусто (старая формулировка бинарного порога снята).
- `./scripts/build.sh` и `./scripts/test.sh` зелёные, без изменений (код не тронут).

## Результат

Сделано по плану. Задача — конфиги/доки (кода нет), по прецеденту задачи 53 стадии
`coder`/`tester`/`ui-engineer` неприменимы; верификация — grep-проверки критериев + build/test.

**Блок A (чистые потери).** Убрано явное «читай `CLAUDE.md` в корне» из всех шести
`.claude/agents/*.md` и из `task-plan/SKILL.md` (модульный `CLAUDE.md` оставлен) —
контекст-подсказка вместо задачи, что корневой файл и так уже в контексте. В `CLAUDE.md`
(«Экономия контекста») добавлен пункт 7, фиксирующий это правило явно. `architect.md` — проверка таблицы
портирования Manager Assistant стала условной («если задача создаёт подсистему с нуля»).
`task-verify/SKILL.md`: битый путь `.claude/skills/smoke-ui/ax.applescript` заменён ссылкой
на процедуру `/smoke-ui`; шаги 1 (build/test) и 5 (UI-смоук) получили условие «не гоняй
заново, если стадия конвейера уже дала свежий результат на актуальном дифе».

**Блок B (три уровня конвейера).** `CLAUDE.md` («Конвейер разработки», «Флоу работы»,
«Жёсткие правила») и `task-run/SKILL.md` («Порог», «Стадии») синхронизированы: бинарный
порог (солo / полный конвейер) заменён таблицей из трёх уровней (тривиальная / малая /
полная). На малой задаче техлид сам ведёт Продукт и Архитектуру компактно (3–6 строк на
секцию), без спавна `product-analyst`/`architect`; `coder`/`tester`/`reviewer` остаются
делегированными на обоих не-тривиальных уровнях. Добавлено правило безопасности «не уверен —
считай полной» и лимит на `NO-GO` (2 круга — стоп, вопрос пользователю).

**Проверка:** все grep-критерии из «Критериев приёмки» подтверждены (пусто там, где
ожидалось пусто; таблица уровней и её формулировки на месте). `./scripts/build.sh` —
зелёный, три известных существующих варнинга в `ChatToolAssembly.swift`, новых нет.
`./scripts/test.sh` — 1035 тестов, 0 падений (код не тронут).

**Важно для следующих:**
- Формальное количественное подтверждение экономии токенов (gen3 бенчмарка) не проводилось —
  это отдельная сессия, см. «Вне объёма». `bench/RESULTS.md` по-прежнему пустой шаблон.
- Критерий «малой» задачи субъективен по конструкции («техлид уверенно называет») — это
  осознанный выбор: чек-лист вместо формулы, с явным откатом к полной задаче при сомнении.
