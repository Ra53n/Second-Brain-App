# 27 — Хаб инструментов, индикация в чате, мастер настройки

## Цель
Туллинг ассистента становится видимым и настраиваемым из одного места: единая вкладка настроек «Инструменты» (встроенные + MCP), чипы включённых источников инструментов над полем ввода чата (со статусами и поповерами), карточка-мастер «Ассистент проекта — 3 шага» в пустом чате, пункт «Добавить инструменты…» в меню инструментов с переходом сразу на нужную вкладку.

## Зависимости
15 (MCP), 17 (настройки), 21 (git-инструменты), 22 (/help), 24 (openSettings-паттерн).

## Контекст (жалоба пользователя)
«Нет индикации, что туллинг включён; как добавлять новый туллинг непонятно; очень плохой UI туллинга у агентов». Настройка размазана: репозиторий проекта — в «Общих», MCP — своя вкладка, включение — в меню чата; живость MCP-сервера из чата не видна вообще.

## Объём работ
- [ ] Чистая логика: `ToolingStatus.swift` (ProjectRepoState.evaluate, ToolSourceSummary.make, ProjectWizardState.make), `ToolRegistry.projectToolCatalog()`, `ChatViewModel.chatProviderAvailable`.
- [ ] Настройки: enum SettingsTab + SettingsTabRouter (pending + нотификация), TabView(selection:), вкладка «Инструменты» (repo-picker из «Общих» + каталог 6 инструментов + секция MCP), чистка GeneralSettingsTab, общий ProjectRepoPicker.
- [ ] Чат: плумбинг SettingsStore/MCPServersViewModel в ChatDetailView, чипы над полем ввода (поповер: статус, «Выключить для этого чата», «Настроить…»), карточка мастера в пустом чате, «Добавить инструменты…» в меню, меню видно всегда.
- [ ] Строки-указатели «Настройки → Общие» → «Настройки → Инструменты» (ошибки /help, мост, каталог команд, ARCHITECTURE).
- [ ] Тесты: ToolingUxTests (repo-state, сводки чипов, шаги мастера, роутер вкладок, доступность провайдера, стабильность каталога).

## Вне объёма
- Статус-точки у пунктов MCP в меню тулбара; периодический авто-тест MCP-соединений.
- Вычистка «осиротевших» serverID из конфигов чатов (чипы и бейдж их просто игнорируют).
- Изменения ToolUseLoop/MCPManager.

## Критерии приёмки
- `swift build` и `swift test` зелёные.
- Вкладка «Инструменты»: repo-picker, каталог 6 инструментов с описаниями, секция MCP; в «Общих» секции проекта больше нет.
- В чате при включённых источниках видны чипы со статусами; клик — поповер с выключением и переходом в настройки.
- Пустой чат показывает мастер с живыми ✓/○; «Настроить…»/«Добавить инструменты…» открывают настройки сразу на «Инструментах».

## Результат

Сделано (2026-07-17):
- **Chat/ToolingStatus.swift** (новый, без SwiftUI) — чистые билдеры: `ProjectRepoState.evaluate` (пустой путь/битая папка/ок), `ToolSourceSummary.make` (чипы: проект при projectToolsEnabled со светофором по состоянию репо; MCP по фильтру меню со статусом из statuses — nil→серый «не проверялся», connected→зелёный с числом, иначе→оранжевый с ошибкой; порядок проект→серверы), `ProjectWizardState.make` (3 шага: репозиторий/модель/инструменты).
- **Вкладка «Инструменты»** (`ToolsSettingsTab` вместо MCPSettingsTab): repo-picker перенесён из «Общих» (Выбрать…/Текущий vault/Сбросить + async git-warning), строка готовности, каталог 6 встроенных инструментов (`ToolRegistry.projectToolCatalog()` — имена моноширинно + описания), секция MCP без изменений. «Общие» очищены. Общий `ProjectRepoPicker` (NSOpenPanel) для вкладки и мастера.
- **Переключение вкладок**: `enum SettingsTab` + `Notification.Name.openSettingsTab` + `SettingsTabRouter` (pending покрывает первое открытие окна — onAppear забирает; нотификация — уже открытое), `TabView(selection:)` с тегами.
- **Чипы** (`Chat/ChatToolingViews.swift`): ряд над полем ввода, capsule со светофором/иконкой/«Название · N», клик → поповер (якорь — чип в inputBar, НЕ тулбар — урок задачи 24): статус, «Выключить для этого чата», «Настроить…» → настройки сразу на «Инструментах».
- **Мастер** `ProjectWizardCard` в пустом чате: живые ✓/○, кнопки «Выбрать…»/«Настройки…»/«Открыть настройки…»/«Включить» (disabled без репо), футер-подсказка `/help`. Исчезает с первым сообщением.
- **Меню инструментов**: видно всегда, новый пункт «Добавить инструменты…»; бейдж считает по правилам чипов — «осиротевшие» serverID удалённых серверов больше не учитываются (побочный фикс).
- **Плумбинг**: ChatDetailView наблюдает SettingsStore (живое обновление после выбора репо) и MCPServersViewModel (statuses); `availabilityTick` по NSWindow.didBecomeKeyNotification перечитывает доступность провайдера после возврата из настроек (KeyStore не Combine-наблюдаем). `ChatViewModel.chatProviderAvailable`.
- **Строки-указатели** «Настройки → Общие» → «Настройки → Инструменты» (ошибка /help, мост, каталог команд, ARCHITECTURE).
- **Тесты** (ToolingUxTests.swift, 5 сьютов + правка CloudProviderTests): repo-state, все состояния чипов (проект ok/notConfigured/broken, MCP unknown/ok/error, осиротевшие/выключенные, порядок), шаги мастера, роутер вкладок (rawValues-контракт, pending, нотификация), доступность провайдера, стабильность каталога. Тест keyID переписан без обращения к реальному Keychain (падал после того, как пользователь сохранил ключ DeepSeek). Всего 634 теста зелёные.

By design: MCP-чип серый до первого «Тест»/tool-вызова (честный статус, авто-тестов нет — вне объёма).
