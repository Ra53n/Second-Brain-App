# 03b — Переработка Live Preview редактора: плавность + типографика + удобства

## Цель
Редактирование заметки плавное, без «дёрганья» текста на каждый символ и «прыжка» при открытии; вид и удобства редактора близки к Obsidian.

## Зависимости
03, 04.

## Контекст
Live Preview из задачи 03 работал, но подсветка (`Coordinator.highlight`) на **каждое** нажатие сбрасывала атрибуты и перепарсивала регэкспами **весь** документ, а `beginEditing/endEditing` со сменой шрифтов по всему тексту вызывал полный релэйаут O(N) — отсюда «весь текст дёргается». При открытии сырые маркеры показывались полным размером, затем сворачивались — видимый релэйаут («прыжок»).

Исследование (CodeMirror 6 / Obsidian, Runestone, CodeEdit, Neon, TextKit-доки) подтвердило подход: остаёмся на TextKit 1 + `NSTextView` + `ConcealingLayoutDelegate` (механика нуллификации глифов — правильный аналог `Decoration.replace`; TextKit 2 нестабилен по прокрутке, tree-sitter избыточен для заметок), но делаем подсветку **инкрементальной и блочно-ограниченной**.

## Объём работ
- [x] Инкрементальная подсветка: правка перекрашивает только блок вокруг неё (`BlockRange.enclosingBlock`), остальные маркеры лишь сдвигаются на изменение длины. `NSTextStorageDelegate` записывает диапазон правки (`pendingEdit`), применяет `textDidChange`.
- [x] Структурный fallback: код-фенсы ` ``` ` и `%%`-комментарии (многоблочные) → полный проход (`needsFullRehighlight`).
- [x] Плавное открытие: стилизованная строка + `concealedRanges` ставятся до первого лэйаута (`buildStyledAttributedString` + `primeConcealment`).
- [x] Сохранение позиции курсора/прокрутки при тихой перезагрузке того же файла (`reloadDisposition`, идентичность через `fileURL`).
- [x] Мягкий кап на гигантский одно-блочный абзац (строчный охват вместо абзацного).
- [x] Типографика ближе к Obsidian: база 15pt, «обсидиановская» шкала заголовков (множители), комфортные интерлиньяж/межабзацные отступы, отступы списков/цитат.
- [x] Удобства: авто-продолжение списков по Enter (буллет/номер+1/`[ ] `, выход из пустого пункта), ⌘B/⌘I (обернуть/снять), авто-парность (`*`/`` ` ``/`_` вокруг выделения, `[[`→`]]`) — всё через `shouldChangeText`/`didChangeText` (undo + автосейв + инкремент).

## Вне объёма
TextKit 2 / Core Text / tree-sitter / swift-markdown-ui / Neon; полноценный WYSIWYG (виджеты таблиц, рендер картинок, callouts); изменение формата файлов на диске.

## Критерии приёмки
- Тесты: расширение блока (`BlockRangeTests`), эквивалентность инкрементального кэша полному парсу (`IncrementalHighlightTests`), структурный fallback (`StructuralEditDetectionTests`), позиция при перезагрузке (`CursorScrollPreservationTests`), сквозной путь на NSTextView (`IncrementalHighlightTextViewTests`), команды редактирования (`MarkdownEditingCommandsTests`) — зелёные; все прежние тесты сохранены.
- Ручная проверка: набор в большом документе не дёргает текст и прокрутку, открытие без «прыжка», Enter продолжает списки, ⌘B/⌘I работают.

## Результат

Выполнено. `swift build` и `swift test` зелёные — **312 тестов** (264 прежних + 48 новых), 0 падений. Ручная проверка в живом приложении — отдельным шагом на vault пользователя.

Что сделано (`Sources/SecondBrain/Editor/`):
- **`BlockRange.swift`** (новый) — `enclosingBlock` расширяет правку до блока (границы — пустые строки) локально, O(размера блока); `shifted` — маппинг координат подстроки в абсолютные.
- **`MarkdownEditorView.swift`** — переписан `Coordinator`:
  - `NSTextStorageDelegate.didProcessEditing` только ЗАПИСЫВАет правку в `pendingEdit` (атрибуты внутри processEditing не трогаем — иначе прыгает каретка); применяет `textDidChange`.
  - `highlight` (полный) разбит на range-scoped `styleRegion` + `style*` (парсинг региона ОДИН раз — устранён двойной парс `MarkdownHighlighter`/`WikilinkParser`); `highlightIncrementally` красит/парсит только блок; `rebuiltConcealables`/`rebuiltLinks` пересобирают кэш (дроп в блоке, сдвиг после) — доказанно равно полному парсу (тесты эквивалентности).
  - `needsFullRehighlight` — структурная правка (```/%%) уходит в полный проход (правило: маркеры `revealStyle == .codeBlock` — это ровно фенсы и %%; их пересечение с правкой или новый ```/%% в блоке → полный).
  - `buildStyledAttributedString` + `primeConcealment` — плавное открытие без «прыжка»; `reloadDisposition` — сохранение курсора/прокрутки при перезагрузке того же файла (идентичность через новый параметр `fileURL`, прокинут из `EditorPane`).
  - `MarkdownTextView`: авто-продолжение списков (`insertNewline`), ⌘B/⌘I (`keyDown`), авто-парность (`insertText`) — через `applyEdit` (shouldChangeText/didChangeText).
- **`MarkdownEditingCommands.swift`** (новый) — чистая логика удобств (newlineInsertion / wrapToggle / wrapMarker).
- **Типографика**: `baseFontSize` 14→15; `MarkdownHighlighter.headingFontSize` — множители (H1 ×1.8 … H6 ×1.0); `ParagraphStyling` — интерлиньяж/отступы под 15pt.

Отклонения/отложено:
- Попутно исправлен латентный баг: `ConcealableMarker.forListMarkers` использовал `^\s*` (где `\s` включает `\n`) — на всём документе жадный `\s*` мог схватить перевод строки перед пунктом после пустой строки и спрятать его. Исправлено на `^[ \t]*`. Тест эквивалентности инкрементального пути это и вскрыл.
- **Отложены «бонусы» типографики** (в объёме плана помечены опциональными): буллет-точка «•» вместо скрытого `-` (нужна reveal-aware подстановка глифа в делегате — плюс плечо плумбинга) и вертикальная полоса слева у цитат (кастомная отрисовка). Ядро плавности и остальная типографика/удобства сделаны; эти два — лёгкий следующий шаг.
