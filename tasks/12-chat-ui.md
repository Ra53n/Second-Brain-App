# 12 — Чат

## Цель
Раздел «Чат»: разговоры с любой настроенной моделью (локальной или облачной), стриминг ответов, история чатов переживает перезапуск.

## Зависимости
08 (желательно и 09 — тогда сразу проверяется локальная модель).

## Контекст
Это «просто отдельный чат со своим вторым мозгом» из требований; знание vault добавит RAG (14), инструменты — MCP (15) — проектируй точки расширения. Эталон: `ChatViewModel.swift`, `ChatStore.swift`, `PromptBuilder` в `Models.swift` MA, UI-паттерн ContentView (NavigationSplitView + сайдбар чатов).

## Объём работ
- [ ] `Chat/ChatModels.swift`: Chat (id, название, сообщения, настройки: провайдер+модель+температура), ChatMessage (роль, текст, метрики: токены/время/стоимость — порт MessageMetrics MA); Codable со снисходительным `init(from:)`.
- [ ] `Chat/ChatStore.swift`: порт ChatStore MA (Application Support, атомарно, debounce-автосейв, .corrupt.json).
- [ ] `Chat/ChatViewModel.swift` (@MainActor): CRUD чатов, отправка сообщения через роутер (функция `.chat` — либо переопределение модели per-чат), **стриминг** в UI (AsyncThrowingStream из 07/08), отмена генерации, ошибки в UI (LocalizedError → баннер у сообщения).
- [ ] `Chat/PromptBuilder.swift`: порт из MA — базовый системный промпт + секции; заготовка под `[RAG_CONTEXT]` (14) и инструменты (15).
- [ ] UI: список чатов в sidebar раздела «Чат», окно диалога (рендер markdown ответов — переиспользуй рендер из 03), поле ввода (многострочное), пикер модели в тулбаре (все доступные из ProviderRegistry, локальные помечены), автоназвание чата по первому сообщению.

## Вне объёма
RAG (14), MCP-инструменты (15), FSM-пайплайн ответов из MA (бэклог 19), сравнение моделей.

## Критерии приёмки
- Тесты: миграция чатов (порт подхода MigrationTests), PromptBuilder (сборка с/без секций), логика ViewModel с MockChatProvider (отправка, стрим по кускам, отмена, ошибка провайдера).
- Ручная проверка: диалог с облачной моделью — ответ печатается постепенно; смена модели посреди чата работает; после перезапуска история на месте; выключить сеть — понятная ошибка, чат не портится.

## Подсказки
- Стриминг + debounce-автосейв: не пиши на диск каждый токен — обновляй сообщение в памяти, Combine-debounce сохранит.
- История в API — вся переписка каждый раз (как в MA, там об этом файловый заголовок Models.swift); стратегии обрезки контекста — пока просто окно последних N сообщений с настройкой.

## Результат

Выполнено; `swift build` и `swift test` зелёные (452 теста, +17 новых).

**Что сделано** (порт паттернов MA с осознанными упрощениями):

- `Chat/ChatModels.swift` — Chat/ChatMessage/MessageMetrics/ChatConfiguration, все со снисходительным `init(from:)`; неизвестная роль → .assistant; runtime-поля (isLoading, errorText) не сериализуются. `Chat.makeTitle` — автоназвание из первой строки (порт MA).
- `Chat/ChatStore.swift` (`ChatPersistence`) — атомарная запись, битый файл → chats.corrupt.json.
- `Chat/ChatPromptBuilder.swift` — база + опциональные секции `[RAG_CONTEXT]` (заготовка 14) и `[TOOLS]` (заготовка 15); `requestMessages` — системный промпт + окно последних N (historyWindow, дефолт 20), пустые заглушки в API не уходят.
- `Chat/ChatViewModel.swift` — CRUD, отправка через роутер `.chat` с per-чат переопределением провайдера/модели (невалидное переопределение тихо падает на роутер), **стриминг** (заглушка ассистента дописывается по кускам), **отмена** (частичный ответ сохраняется, CancellationError — не ошибка), ошибки → errorText-баннер (пустая заглушка при ошибке убирается), debounce-автосейв 300 мс + немедленная запись финала + willTerminate-страховка. Точка расширения `ragContextProvider` для 14.
- UI `Chat/ChatViews.swift` — список чатов (средняя колонка, контекстное меню удаления, «+»), диалог в detail: markdown-рендер (MarkdownUI из задачи 03), автопрокрутка при стриминге, кнопка «стоп» во время генерации, многострочное поле (⌘⏎), пикер модели в тулбаре (провайдеры с .chat из реестра, локальные помечены «локально», «Авто (роутер)» — дефолт), метрики под ответом (время; токены — когда провайдер отдаёт usage).

**Отклонения от эталона MA (осознанные)**:
- В MA стриминга нет (ответ целиком) — у нас честный стриминг через `AsyncThrowingStream` протокола 07; из-за этого usage-токены в метриках обычно недоступны (стрим их не несёт) — metrics.duration есть всегда.
- История линейная, без дерева MsgNode/ветвления MA — ветвление в бэклог (19).
- Стоимость не считаем: таблиц цен в проекте нет (бэклог).

**Тесты**: ChatModelsTests (round-trip, миграция минимального JSON, неизвестная роль, карантин, runtime-поля, makeTitle), ChatPromptBuilderTests (секции, окно, пропуск пустых), ChatViewModelTests на управляемом ScriptedChatProvider (стрим по кускам + автоназвание + запись на диск, отмена с сохранением частичного ответа, ошибка провайдера с удалением пустой заглушки, пустой реестр, per-чат override, окно истории в запросе).

**Ручная проверка не выполнялась** (нужен API-ключ): диалог с облачной моделью печатается постепенно; смена модели посреди чата; история после перезапуска; выключенная сеть → понятная ошибка.
