# Задача 46: скиллы полного цикла разработки

## Цель

Семь слэш-команд, закрывающих цикл «идея → задача → план → код → проверка →
закрытие», плюс два вспомогательных (портирование из Manager Assistant и
AX-смоук UI). Флоу перестаёт быть текстом, который агент может пролистать, и
становится процедурой с чек-листами, которую пользователь запускает явно.

## Зависимости

44 (правила и флоу, на которые скиллы ссылаются), 45 (агенты, которых скиллы
вызывают).

## Объём

1. `.claude/skills/task-new/SKILL.md` — Ф1+Ф3: интервью по чек-листу
   corner-кейсов → файл `tasks/NN-slug.md` (номер = max+1) → строка в
   `00-INDEX.md` → пункт `BACKLOG.md` помечается `→ NN`.
2. `.claude/skills/task-plan/SKILL.md` — Ф2: архитектурный разбор, поиск
   переиспользуемого, список файлов и порядок работ, риски инвариантов.
3. `.claude/skills/task-run/SKILL.md` — Ф4: проверка зависимостей по INDEX
   (не выполнены → стоп), чтение задачи целиком, реализация по конвенциям,
   порядок «чистое ядро → тесты → интеграция → UI».
4. `.claude/skills/task-verify/SKILL.md` — Ф5: `swift build` + `swift test`,
   критерии приёмки по пунктам с доказательствами, AX-смоук кнопок для
   UI-задач, `git grep` секретов.
5. `.claude/skills/task-close/SKILL.md` — Ф6: `## Результат` по шаблону,
   чекбокс в INDEX, обновление ARCHITECTURE при смене решения, коммит.
6. `.claude/skills/port-from-ma/SKILL.md` — портирование подсистемы из
   Manager Assistant по таблице CONVENTIONS.md с адаптацией и тестами.
7. `.claude/skills/smoke-ui/SKILL.md` — готовые osascript-рецепты AX-смоука:
   найти окно, перечислить и нажать кнопки, прочитать дерево, типовые грабли.
8. Интеграция: таблица скиллов в CLAUDE.md; пункт 22 `BACKLOG.md` («smoke-чеклист
   как критерий приёмки») помечается закрытым через `/task-verify`; строки
   44–46 в `00-INDEX.md` и запись в «Журнал отклонений» о смене процесса.

## Вне объёма

- Хуки в `.claude/settings.json` (автоматический запуск проверок).
- Скиллы вне цикла разработки (релиз, дистрибуция, работа с vault).
- CI: проект собирается и проверяется локально.

## Критерии приёмки

- Семь `SKILL.md` с валидным frontmatter (`name`, `description`); `name`
  совпадает с именем каталога.
- Каждый скилл — процедура с нумерованными шагами и чек-листом выхода, а не
  описание намерений; шаги содержат конкретные команды и пути.
- `/task-new` прогнан вживую на реальном пункте бэклога и родил корректный файл
  задачи со строкой в INDEX.
- `/smoke-ui` прогнан вживую на установленном приложении: рецепты находят окно
  и перечисляют элементы.
- `swift build` и `swift test` зелёные.

## Результат

Сделано по плану, семь скиллов созданы в `.claude/skills/`.

- `/task-new` (Ф1+Ф3) — разведка по коду до вопросов, интервью пачкой по чек-листу
  из восьми пунктов, файл задачи по шаблону, строка в INDEX, пометка пункта бэклога.
- `/task-plan` (Ф2) — поиск существующего (список забываемых кирпичей: SafePath,
  UnifiedDiff, VaultPath, ToolSchemas, HTTPSupport…), восемь вопросов разбора,
  риски по «Частым ошибкам» модульных конфигов.
- `/task-run` (Ф4) — допуск к работе (зависимости по INDEX, чистое дерево), порядок
  «чистое ядро → тесты → интеграция → UI», правила, которые нарушают чаще всего.
- `/task-verify` (Ф5) — сборка и тесты, критерии с доказательствами, готовые grep'ы
  антипаттернов по дифу, проверка секретов, обязательный AX-смоук для UI-задач.
- `/task-close` (Ф6) — шаблон «Результата» с блоком «Важно для следующих задач»,
  индекс, документация, требования к сообщению коммита.
- `/port-from-ma` — таблица портирования, правило «портируй, а не копируй», перенос
  тестов, фиксация происхождения в заголовке файла.
- `/smoke-ui` — рецепты AX + рабочий скрипт `ax.applescript` (режимы `dump` и
  `click "<подпись>"`) рядом со SKILL.md.

Интеграция: таблица скиллов в CLAUDE.md, пункты 21 и 22 BACKLOG.md помечены
закрытыми, запись о смене процесса в «Журнале отклонений» 00-INDEX.md.

Отклонения от плана: нет по объёму, но AX-рецепты пришлось выводить экспериментально —
готовых в проекте не было, а часть общепринятых приёмов на этом приложении не работает.

Живые проверки (оба критерия приёмки):

- `/smoke-ui` прогнан на установленном приложении: `click "Встречи"` переключил раздел,
  `dump` выдал реальное дерево — список записей с датами и длительностями, пикер
  источника «Оба», чип «Транскрипция: Авто (Deepgram)».
- `/task-new` прогнан на пункте 21 бэклога: разведка нашла готовые
  `ProjectDocsIndexService.stats/reset`, интервью задало три вопроса по corner-кейсам,
  результат — `tasks/47-project-docs-index-status.md` со строкой в INDEX. Задача
  оставлена готовой к работе.

Важно для следующих задач — три факта об AX, добытых экспериментально:

1. **Приложение обязано быть активным.** В фоне `window 1` не существует: `count of
   windows` = 0 и ошибка -1719. Каждый скрипт начинается с `activate` + `delay 0.6`.
2. **`entire contents of window 1` на этом приложении возвращает пусто** — нужен ручной
   рекурсивный обход (реализован в `ax.applescript`).
3. **Подпись элемента лежит в разных свойствах:** у `AXStaticText` — в `name`/`value`,
   у кнопок тулбара — в `description`; у SwiftUI-кнопок с иконкой подписи может не быть
   вовсе (`description` вернёт локализованное «button») — ориентир — соседний
   `AXStaticText` в той же ячейке.
