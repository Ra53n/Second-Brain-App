# 03 — Markdown-редактор

## Цель
Открытая в дереве заметка редактируется и сохраняется автоматически; markdown читабельно рендерится.

## Зависимости
02.

## Контекст
Минимум для работы со вторым мозгом: правка текста без потери данных. Эталон автосохранения — debounce-паттерн MA (`ChatViewModel.init`, см. CONVENTIONS.md). Для рендера у MA есть собственный `MarkdownText.swift` (AttributedString) и подключённый пакет `swift-markdown-ui` — выбери одно (рекомендация: swift-markdown-ui для превью, NSTextView для редактирования).

## Объём работ
- [ ] `Editor/EditorViewModel.swift`: загрузка файла, отслеживание правок, автосохранение с debounce 500 мс + сохранение при потере фокуса/закрытии, атомарная запись.
- [ ] `Editor/MarkdownEditorView.swift`: редактор на NSTextView (через NSViewRepresentable) — моноширинный/обычный шрифт, подсветка заголовков/жирного/кода лёгким стилем (полноценный syntax highlight не обязателен).
- [ ] Переключатель или сплит «Редактор / Превью»; превью рендерит markdown.
- [ ] Конфликт внешнего изменения: если файл изменился на диске, пока открыт в редакторе без несохранённых правок — тихо перечитать; если правки есть — показать выбор (перечитать / сохранить свою версию рядом с суффиксом `(conflict)`), молча не перезаписывать.
- [ ] Создание новой заметки из sidebar сразу открывает её в редакторе с курсором в тексте.

## Вне объёма
Wikilinks/автокомплит (04), таблицы контента, vim-режимы, вставка изображений.

## Критерии приёмки
- Тесты: debounce-логика сохранения (через инжектируемые часы/scheduler), поведение при внешнем изменении (обе ветки), атомарность записи.
- Ручная проверка на vault пользователя: открыть заметку с кириллицей и длинным текстом, править — содержимое не теряется, внешняя правка в другом редакторе подхватывается.

## Подсказки
- НЕ используй TextEditor из SwiftUI для основного редактора — на больших файлах тормозит; NSTextView надёжнее.
- Атомарная запись: `Data.write(options: .atomic)` — как в ChatStore MA.
- FSEvents из задачи 02 уже сообщает об изменениях — подпишись, не заводи второй механизм.

## Результат

Выполнено полностью. 42 теста зелёные; ручная проверка в живом приложении: набор текста автосохраняется на диск, внешняя правка подхватывается, превью рендерится.

Что сделано (модуль `Sources/SecondBrain/Editor/`):
- `EditorViewModel.swift` — загрузка (UTF-8 + авто-детект кодировки), debounce-автосохранение 500 мс на `$text` (паттерн MA ChatViewModel), `saveNow()` при переключении файла/разделов и на `willTerminateNotification`, атомарная запись. Запись синхронная, НЕ на utility-очереди как в MA — осознанно: детекция конфликтов требует, чтобы `lastSavedText` менялся строго вместе с диском; заметки малы.
- Конфликты: диск сравнивается с `lastSavedText` (отличает эхо своей записи от внешней правки). Без локальных правок — тихое перечитывание; с правками — диалог: «Перечитать с диска» / «Сохранить мою версию рядом» → `VaultFileOperations.writeConflictCopy` («Имя (conflict).md», уникальные имена). Пока конфликт не решён, автосохранение заморожено.
- `MarkdownEditorView.swift` — NSTextView через NSViewRepresentable (не TextEditor), смарт-кавычки/тире/автозамена выключены, undo включён, автофокус (новая заметка сразу с курсором в тексте). Подсветка: `MarkdownHighlighter` (чистая логика, тестируется) — заголовки по уровням, **жирный**, `код`, ```блоки```, > цитаты; атрибуты поверх текста, содержимое не меняется.
- `EditorPane.swift` — режимы Редактор/Сплит/Превью (segmented в тулбаре), превью на swift-markdown-ui (зависимость добавлена в Package.swift, как планировала задача 01).
- ContentView: .md/.markdown/.txt открываются в редакторе, остальное — FileInfoView.

Важное отклонение/находка — **баг проводки внешних изменений**: подписка редактора на `vaultManager.root` не работает для правок только СОДЕРЖИМОГО файла (дерево Equatable-одинаково, onChange молчит). Найден живой проверкой, юнит-тесты его не ловили (звали checkExternalChange напрямую). Решение: `VaultManager.diskChangeTick` — счётчик FSEvents-срабатываний, редактор подписан на него. Регрессионный тест с реальным FSEvents добавлен. Урок следующим задачам (05, 13: инкрементальная индексация): подписывайтесь на diskChangeTick, не на root.

Мелочи для полировки (19): при тихом перечитывании курсор уходит в начало; подсветка бежит по всему документу на каждый ввод (на больших файлах можно ограничить viewport'ом).
