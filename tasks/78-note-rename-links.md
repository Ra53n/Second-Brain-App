# Задача 78: переименование заметки с обновлением ссылок

## Тип

фича

## Модель

sonnet

## Цель

Пользователь переименовывает заметку — все `[[wikilink]]`-ссылки на неё в остальном vault
должны обновиться автоматически, а не сломаться на битую ссылку (`tasks/BACKLOG.md` п.4).
`LinkIndex` уже умеет вычислять, какие файлы ссылаются на данный — не хватает операции
переименования, которая это использует, и UI-точки входа.

## Зависимости

Нет.

## Объём

1. Найти в `Sources/SecondBrain/Links/` и `Sources/SecondBrain/Vault/` существующие типы
   для вычисления backlinks (`LinkIndex` или аналог) и для файловых операций
   (`VaultFileOperations` — по инварианту №1, запись в vault только через него).
2. Реализовать операцию переименования: переименовать файл через `VaultFileOperations`,
   обновить `[[старое-имя]]` → `[[новое-имя]]` (и `[[старое-имя|alias]]` с сохранением
   alias) во всех файлах, где есть входящая ссылка по данным `LinkIndex`.
3. UI-точка входа: контекстное меню заметки (там, где уже есть другие файловые операции —
   удаление/перемещение) — «Переименовать» с обновлением ссылок.
4. Corner-кейсы: конфликт имён (целевое имя уже занято — не переименовывать, показать
   ошибку), ссылка с алиасом, битая ссылка на несуществующую заметку (не трогать).

## Вне объёма

Переименование папок (только отдельные заметки), массовое переименование по паттерну.

## Критерии приёмки

- [ ] Переименование заметки с 2+ входящими ссылками из разных файлов обновляет все ссылки,
      включая ссылки с alias.
- [ ] Переименование в уже занятое имя — явная ошибка, ничего не переименовано.
- [ ] Интеграционный тест на операцию целиком (переименование + обновление ссылок) в
      `Tests/SecondBrainTests/`.
- [ ] UI-точка входа проверена через `./scripts/ui.sh` (трассировка «меню → функция»).
- [ ] `./scripts/build.sh` и `./scripts/test.sh` зелёные.
