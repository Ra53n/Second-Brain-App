# Задача 68: `CodeRegionDetector` не защищает контент после незакрытого код-блока

## Тип

баг

## Модель

haiku

## Цель

`CodeRegionDetector` (`Sources/SecondBrain/Editor/CodeRegionDetector.swift:20-23`) не
защищает содержимое, если код-блок в markdown не закрыт (найдено тестами задачи 58,
`tasks/BACKLOG.md` п.31). Практическое следствие: редактор/парсер может интерпретировать
как разметку то, что пользователь писал как код (например, `[[wikilink]]`-подобный текст
внутри незакрытого блока), пока он не закроет тройные кавычки.

## Зависимости

Нет.

## Объём

1. `Sources/SecondBrain/Editor/CodeRegionDetector.swift:20-23` — решить осознанно: либо
   незакрытый код-блок считается открытым до конца документа (весь хвост документа —
   защищённый регион), либо до конца документа код-регионом не считается вовсе (текущее
   поведение, если оно таким и является — тогда зафиксировать это тестом как явное решение,
   а не молчаливый пробел). Решение — на исполнителе, критерий приёмки не диктует какое
   именно, только что оно есть и покрыто тестом.
2. Тест на конкретный граничный случай: документ с ` ``` ` без закрывающей пары.

## Вне объёма

Изменение синтаксиса подсветки, разбор вложенных код-блоков.

## Критерии приёмки

- [x] Поведение для незакрытого код-блока явно определено (см. п.1 «Объёма») и
      задокументировано комментарием на месте решения (почему выбрано именно так).
- [x] Новый тест воспроизводит кейс и фиксирует выбранное поведение.
- [x] `./scripts/build.sh` и `./scripts/test.sh` зелёные, число тестов не уменьшилось.

## Отчёт тестов

**Что нашёл:** в `CodeRegionDetector.swift:12-13` регэксп `^```[\\s\\S]*?^```$` требует обязательного закрытия код-блока. Если блок открыт (` ``` `) но не закрыт до конца документа, регэксп не находит совпадения вообще — содержимое остаётся незащищённым. Практическое следствие: wikilinks и другая разметка внутри такого блока интерпретируются как обычная разметка (баг из задачи 58).

**Что починил:** 
- `Sources/SecondBrain/Editor/CodeRegionDetector.swift:12-17` — изменил паттерн регэксп на `^```[\\s\\S]*?(?:^```|\\Z)`. Теперь блок, открытый тройными кавычками, считается открытым либо до закрывающей тройки, либо до конца документа (`\Z`). Добавил комментарий, объясняющий решение: незакрытый блок должен быть защищён, как в VS Code и Obsidian.
- `Tests/SecondBrainTests/CodeRegionDetectorTests.swift:17-27` — обновил тест `testUnclosedCodeBlockFenceExcludesUntilEndOfDocument` (было `testUnclosedCodeBlockFenceExcludesNothing`), теперь проверяет, что незакрытый блок ЗАЩИЩАЕТ содержимое до конца.
- `Tests/SecondBrainTests/CodeRegionDetectorTests.swift:34-49` — добавил регрессионный тест `testUnclosedCodeBlockProtectsWikilinksInsideUntilEnd`, который явно проверяет, что wikilinks внутри незакрытого блока исключены из интерпретации.

**Что проверил:**
- `./scripts/build.sh` — успех, 5.29s
- `./scripts/test.sh` — успех, 1098 тестов (было 1097, +1 новый), 0 failures
- Тесты граничных случаев: закрытый блок работает как раньше; незакрытый блок теперь защищает до конца; wikilinks внутри незакрытого блока исключены
- Смежное: инлайн-код и другие парсеры (checklistы, комментарии) не затронуты — используют `excludedRanges()` который теперь возвращает корректные диапазоны

## Результат

`CodeRegionDetector` — незакрытый код-блок теперь считается открытым до конца документа
(regex `(?:^```|\Z)`), содержимое (включая wikilink-подобный текст) защищено. `GO` с
первого круга.

Замечание ревьюера (не блокирует, вынесено в `tasks/BACKLOG.md` пункт 38): `\Z` в ICU-regex
матчит позицию перед финальным line-terminator, не абсолютный конец ввода — на документе
с trailing `\n` последний символ формально выпадает из региона. Практического вреда нет
(`\n` не парсится как разметка), но точнее было бы `\z`; граничный тест на trailing newline
не написан.
