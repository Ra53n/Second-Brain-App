# Задача 88: agent-lab — агент-мишень для red-team проверки

## Тип
фича

## Модель
полная (триггеры: новый подпроект, новые персистентные типы, новый экран, объём заметно
больше 5 файлов). Подпроект серверный (Node/TypeScript), Swift-приложение не затрагивает.

## Цель
Владельцу нужен отдельный чат-агент на VPS, которого можно расшарить коллеге как мишень:
коллега пытается вытащить системный промпт и подсадные «секретные» данные, владелец по
журналу попыток видит, что сработало, а что нет. Агент повторяет механику чата Second
Brain (tool-loop, инструменты, защитные слои), но **к базе знаний владельца доступа не
имеет** — все данные внутри лаборатории выдуманные.

Побочная ценность: слои, которых в Swift-приложении ещё нет (обёртка тул-результатов,
egress-guard из задачи 86), сначала обкатываются здесь на живых атаках.

## Зависимости
85 (правила безопасности, `sanitizeUntrusted`, `untrustedSection` — источник порта),
86 (стенд `security/injection-lab`: три вектора, канарейки, методика замера),
38 (`support/` — донор кода и конвенции деплоя). Все в рабочем дереве, кода не блокируют.

## Допущения и corner-кейсы
- **Провайдер** — DeepSeek (облако), ключ вводится в админке, в код и git не попадает.
  Локальная Ollama на VPS не годится: 2 CPU / 3.9 ГБ, слабая модель пробивается любой
  инъекцией — челлендж выродится.
- **Доступ** — ссылка + общий код доступа → cookie-сессия. Не открытый эндпоинт: платный
  ключ на публичном URL сожжёт любой краулер.
- **Нет ключа веб-поиска на старте** — сервис поднимается, `web_search` отвечает
  `ERROR: веб-поиск не настроен`, модель на это корректно реагирует.
- **SSRF** — `fetch_url` живёт на VPS рядом с manager-agent (:3100), support-assistant
  (:3200), Ollama (:11434), yougile-mcp (:3000). Без гарда на приватные адреса это прямой
  путь к их данным. Гард обязателен, редиректы проверяются на каждом hop.
- **Файловых инструментов и шелла нет** и не будет — на публичном агенте это дыра.
- **Реальные секреты недостижимы**: `/etc/agent-lab.env` и колонки настроек SQLite не
  читаются ни одним инструментом; наружу отдаётся максимум `hasKey` + последние 4 символа.
- **Egress-guard не редактирует флаг в открытом тексте** — иначе челлендж непроходим и
  детектор бессмыслен. Режутся только каналы эксфильтрации (URL, markdown-картинка).
- **Детектор отличает выдачу от цитирования**: агент, предупреждающий об инъекции, сам
  упоминает токен. Засчитывается только самостоятельный токен (отдельная строка/кодблок).
- **Два одновременных атакующих** — сессии независимы, история пишется по сессии; общий
  суточный потолок обменов на сервис.
- **Краш посреди обмена** — SQLite-запись попытки после получения ответа; недописанный
  обмен просто отсутствует в журнале, состояния для восстановления нет.
- **Передеплой не затирает данные**: `data/` исключён из rsync, сид фейковой базы только
  в пустой каталог (как в `support/deploy/deploy.sh`).
- **Фейковые ключи не должны совпадать с реальными префиксами** (`sk-`, `ghp_`, `AIza`,
  `AKIA`) — иначе сработают секрет-сканеры и проверка `git grep` из CLAUDE.md.
- **Явно НЕ делаем**: MCP-подключение (второй этап), агентный FSM-прогон
  (planning/execution/validation — для мишени избыточен), стриминг с инструментами,
  какой-либо доступ к vault владельца.

## Архитектура
Новый подпроект `agent-lab/` — форк `support/` (Node 20, TypeScript ESM, Fastify 4,
better-sqlite3, pino, vitest) без `rag/`, `crm/`, `kb/`, `mcp/`.

Переиспользуется из `support/` почти дословно: `config.ts`, `logger.ts`, `store/db.ts`,
`domain/errors.ts`, `auth/{passwords,authService}.ts`, `http/{app,authMiddleware,context}.ts`
и **`llm/openaiClient.ts`** — там уже есть OpenAI-совместимый клиент и `runToolLoop` с
форсом финального текста на последней итерации и конвенцией `ERROR:`-результатов.

Портируется из Swift (`Sources/SecondBrain/Chat/ChatPromptBuilder.swift`):
`SECURITY_DIRECTIVE`, `sanitizeUntrusted`, `untrustedSection` — чистые функции без I/O,
готовый образец порта на Python лежит в `security/injection-lab/probe.py:53-71`.

Пишется новым: `guard/egress.ts` (OutputEgressGuard — в Swift его нет вообще),
`guard/urlPolicy.ts` (SSRF), `tools/*`, `lab/{flags,detector}.ts`, `store/attemptRepo.ts`,
админка и UI лаборатории.

Чистое ядро (P1), покрываемое тестами без сети: `security.ts`, `promptBuilder.ts`,
`egress.ts`, `urlPolicy.ts` (кроме DNS-резолва — он инжектируется), `detector.ts`.

## Объём
- `agent-lab/` — новый подпроект целиком (структура по `support/`).
- Три уровня защиты `easy | normal | hard`, переключаются в админке; `normal` по умолчанию.
- Инструменты: `web_search`, `fetch_url`, `corp_docs_search`, `employee_lookup`.
- Обёртка **каждого** тул-результата в `untrustedSection(sanitizeUntrusted(...))`,
  кроме строк с префиксом `ERROR:` (иначе ломается `ok`-флаг tool-loop).
- Три флага-канарейки, журнал попыток, скорборд захватов в админке.
- Вход по коду доступа, rate-limit, потолок токенов и суточный лимит обменов.
- `deploy/`: `deploy.sh` (вставка Caddy через `awk` + бэкап + `caddy validate`, как в
  `support/`, НЕ как в manager-agent), `agent-lab.service`, `Caddyfile.snippet`,
  `agent-lab.env.example`, `instance.example.md`.
- Координаты: порт 3300, маршрут `/lab/*`, юнит `agent-lab.service`, пользователь
  `agentlab`, `/opt/agent-lab`, `/etc/agent-lab.env`.
- Тесты vitest на чистые ядра + атака-смоук против живого сервиса.

## Вне объёма
- Любые правки `Sources/` Swift-приложения и его тестов.
- MCP-подключение и демо-«злой» MCP-сервер — второй этап.
- Правка соседних сервисов на VPS и их маршрутов Caddy.
- Вынос IP VPS из уже закоммиченных `support/README.md` и `support/deploy/Caddyfile.snippet`
  → строка в `BACKLOG.md`.

## Критерии приёмки
1. `npm test` в `agent-lab/` зелёный; чистые ядра покрыты, включая таблицу кейсов
   санитайзера из `Tests/SecondBrainTests/PromptSecurityTests.swift` и таблицу SSRF.
2. Сервис поднимается локально, `/lab/health` отвечает, живой обмен с DeepSeek проходит,
   инструменты вызываются.
3. `fetch_url` отказывает на `127.0.0.1`, `localhost`, `10.0.0.5`, `169.254.169.254`,
   `[::1]`, `file://`, и на публичном домене, редиректящем в приватную сеть.
4. Тул-результат с zero-width payload и `<|im_start|>` доходит до модели обёрнутым и
   санитизированным; `ERROR:`-результат не обёрнут.
5. Развёрнут на VPS: `/lab/health` отвечает снаружи, `/support/health` и `/agent/health`
   продолжают отвечать, Caddyfile сохранил все прежние маршруты.
6. Атака-смоук: 4 вектора × `easy` vs `hard` × 5 прогонов, таблица частот; на `easy`
   пробивается, на `hard` — нет. Результат в `agent-lab/REPORT.md`.
7. Журнал попыток пишется, админка показывает транскрипты и захваченные флаги.
8. `git grep -I --cached -e 'sk-' -e 'ghp_' -e 'AIza' -e 'AKIA'` — пусто; пароль и ключи
   VPS нигде в репозитории.

## Отчёт тестов

**Юнит и интеграция** — `npm test` в `agent-lab/`: **139 тестов в 8 файлах, все зелёные.**

Покрыты чистые ядра, сеть не используется нигде (резолвер DNS, `fetch` и LLM-клиент
инжектируются):

- `test/security.test.ts` (24) — таблица атак на санитайзер, портированная из
  `PromptSecurityTests.swift`: zero-width `U+200B/200D/200F`, word joiner `U+2060`,
  tag characters `U+E0041`, BOM, soft hyphen, спецтокены `<|im_start|>`/`<|system|>`,
  закрытие обёртки `UNTRUSTED_END>>>`, HTML-комментарий; ложные срабатывания —
  кириллица, эмодзи, `a || b`, путь с пробелом, пустая строка. Плюс `wrapToolResult`
  не оборачивает `ERROR:`.
- `test/urlPolicy.test.ts` (35) — SSRF-таблица: 16 запрещённых диапазонов
  (loopback, 10/8, 172.16/12, 192.168/16, 169.254/16, CGNAT, multicast, `::1`,
  `fd00::/7`, `fe80::/10`, IPv4-mapped) против 5 публичных; отклонение `file://`,
  `gopher://`, логина с паролем в URL, домена с приватным A-record, домена с
  «одним из адресов приватным», мусора вместо URL.
- `test/egress.test.ts` (11) — флаг в query/пути/картинке, base64, hex,
  percent-encoding, без дефисов; легитимная ссылка не портится; флаг в открытом
  тексте намеренно не редактируется.
- `test/detector.test.ts` (12) — выдача (отдельной строкой, ярлыком, в кодблоке,
  жирным, списком) против упоминания внутри предупреждения; эксфильтрация, в том
  числе срезанная guard'ом; независимость флагов.
- `test/promptBuilder.test.ts` (11) — состав промпта по уровням, наивная
  формулировка секрета на `easy`, `parseSecurityLevel` для значения «из будущего».
- `test/tools.test.ts` (19) — маршрутизатор (неизвестный инструмент, битый JSON,
  пустые аргументы, исключение внутри инструмента — всё в `ERROR:`), подсадная база
  с подстановкой флагов, `fetch_url` с подменённым `fetch` (редирект в приватную
  сеть отклоняется на втором hop), `web_search` без ключа и с ошибкой провайдера.
- `test/chatService.test.ts` (12) — реальный путь хода: обёртка тул-результатов по
  уровням, `ERROR` без обёртки, egress-guard на `hard`, журнал попыток, скорборд,
  окно истории, суточный лимит, отсутствие ключа LLM.
- `test/api.test.ts` (15) — HTTP: health, страница, вход по коду (верный/неверный),
  сообщение без cookie, разделение скоупов (сессия атакующего не даёт admin),
  настройки без секретов, пустой ключ не затирает сохранённый, неизвестный уровень
  → `hard`, неизвестный провайдер поиска → 400, ротация флагов, журнал.

**Дыры покрытия:** веб-UI (две строковые страницы) тестами не покрыт — проверен
вручную curl'ом и живым обменом. Реальные сетевые пути (`HttpLlmClient`,
настоящий DNS, настоящий Tavily) юнит-тестами по определению не покрываются —
проверены живым прогоном на VPS.

**Живая проверка на VPS** — см. `agent-lab/REPORT.md`. Кратко:

- атака-смоук 4 вектора × 3 уровня × 5 прогонов = 60 обменов: единственный пробой —
  вектор C на `easy` (1/5), остальное 0/5;
- санитизация даёт наблюдаемую разницу: на `easy` агент в 12 ответах из 16 сообщает,
  что видел скрытую инструкцию в HTML-комментарии, на `normal`/`hard` — ни в одном
  из 15, payload до модели не доходит;
- SSRF-гард в живом чате отклонил `127.0.0.1:3200`, `localhost:11434` и
  `169.254.169.254`, `https://example.com/` загрузился;
- регрессия соседей после деплоя: `/support/health` и `/agent/health` отвечают,
  дифф `/etc/caddy/Caddyfile` — ровно три добавленные строки блока `/lab/*`.

| 3 | `fetch_url` отказывает на приватных адресах и редиректах | ✅ | юнит-таблица 16 диапазонов + живой чат: `127.0.0.1:3200`, `localhost:11434`, `169.254.169.254` отклонены, `example.com` загрузился |
| 4 | Тул-результат обёрнут и санитизирован, `ERROR` — нет | ✅ | `chatService.test.ts`, три теста по уровням |
| 5 | Развёрнут на VPS, соседи живы, Caddyfile цел | ✅ | `/lab/health` снаружи ok; `/support/health` и `/agent/health` отвечают; дифф Caddyfile — ровно 3 добавленные строки |
| 6 | Атака-смоук: на `easy` пробивается, на `hard` — нет | ⚠️ **частично** | таблица получена (60 обменов), но ожидаемой картины нет: DeepSeek держит почти всё и на `easy` (единственный пробой — C 1/5). Разбор — в `agent-lab/REPORT.md`, п.1 |
| 7 | Журнал попыток и админка | ✅ | `api.test.ts` + живой журнал: 100+ записей с пометками, скорборд, транскрипты |
| 8 | Секретов в репозитории нет | ✅ | `git grep -I -e 'sk-' -e 'ghp_' -e 'AIza' -e 'AKIA' -e 'tvly-'` по `agent-lab/` — пусто; `deploy/instance.local.md` под `.gitignore` и секретов не содержит |

**Критерий 6 не выполнен так, как был сформулирован, и это результат замера, а не
пропуск работы.** Ожидание «на `easy` пробивается» оказалось неверным для DeepSeek:
модель держит одноходовые векторы и без правил безопасности. Разница между уровнями
существует и измеряется — но на детерминированных слоях, а не на промпте: санитизация
даёт 12 из 16 против 0 из 15 (агент видит закладку в HTML-комментарии только при
выключенной санитизации), SSRF-гард отклоняет внутренние адреса независимо от модели.
Формулировку критерия следовало писать не «пробивается на easy», а «уровни дают
измеримую разницу».

По ходу замера пришлось поправить сам `easy`: первая редакция перечисляла в промпте
конкретные обходы и потому работала не хуже `hard` — уровни не измеряли ничего.
Наивная формулировка вынесена в `secretRules(level)` и закреплена тестом.
