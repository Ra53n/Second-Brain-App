# 04 — Wikilinks и backlinks

## Цель
Заметки связываются через `[[wikilinks]]` в Obsidian-совместимом синтаксисе: автокомплит при вводе, клик-переход, панель backlinks, парсинг frontmatter.

## Зависимости
03.

## Контекст
Связность — суть «второго мозга». Синтаксис Obsidian: `[[Имя заметки]]`, `[[Имя|алиас]]`, `[[Имя#Заголовок]]`; ссылки резолвятся по имени файла без расширения по всему vault (при дублях — кратчайший путь). Frontmatter — YAML между `---` в начале файла. Эталон стиля парсеров и их тестов: `PromptParsingTests.swift` в MA (round-trip, edge cases).

## Объём работ
- [ ] `Links/WikilinkParser.swift`: извлечение ссылок из текста (диапазоны + цель + алиас + заголовок), игнорирование код-блоков и инлайн-кода.
- [ ] `Links/FrontmatterParser.swift`: YAML frontmatter → словарь (достаточно плоских ключей: строки, числа, списки строк, даты) + сериализация обратно без потери остального текста.
- [ ] `Links/LinkIndex.swift`: индекс «кто на кого ссылается» по vault, инкрементальное обновление по FSEvents; резолв имени → файл.
- [ ] Редактор: ввод `[[` открывает автокомплит по именам заметок (fuzzy), Enter вставляет ссылку; клик (или Cmd+клик) по ссылке открывает заметку; ссылка на несуществующую заметку создаёт её (как в Obsidian).
- [ ] Панель backlinks у открытой заметки: список заметок-источников со сниппетом строки.
- [ ] Подсветка wikilinks в редакторе.

## Вне объёма
Graph view (19), переименование с обновлением всех ссылок (в 19, но LinkIndex проектируй так, чтобы это было возможно), embed `![[...]]`.

## Критерии приёмки
- Тесты парсеров: все формы ссылок, ссылки в код-блоках не считаются, кириллица/пробелы/эмодзи в именах, битый frontmatter не роняет парсер, round-trip frontmatter.
- Тесты LinkIndex: построение на temp-vault, обновление при изменении файла, резолв дублей.
- Ручная проверка на vault пользователя: его существующие ссылки резолвятся, backlinks совпадают с тем, что показывает Obsidian.

## Подсказки
- Не тащи YAML-библиотеку ради плоского frontmatter — простого парсера достаточно, но задокументируй ограничения в файловом заголовке.
- Регекс для wikilink обманчиво прост — сначала напиши тесты на `[[a|b]]`, `[[a#h|b]]`, `[[  ]]`, вложенные скобки.

## Результат

Выполнено полностью. 71 тест зелёный (29 новых). Живой vault: 1967 ссылок в 588 файлах, резолвится 1469, полное построение индекса 401 мс. UI проверен вживую: автокомплит, переход, создание несуществующей заметки, backlinks в обе стороны.

Что сделано (модуль `Sources/SecondBrain/Links/`):
- `WikilinkParser.swift` — все формы `[[цель]]`, `[[цель|алиас]]`, `[[цель#заголовок]]`, `[[цель#заголовок|алиас]]`, цели с путём; код-блоки/инлайн-код игнорируются; UTF-16-диапазоны для NSTextStorage. Не поддерживаются (сознательно): `[[#Заголовок]]` без цели, пустые `[[ ]]`.
- `FrontmatterParser.swift` — плоский YAML без библиотеки: строки/числа/даты YYYY-MM-DD/списки (инлайн и блочные). Нераспознанные строки хранятся raw и сериализуются дословно → round-trip байт-в-байт (тест). Битый frontmatter не роняет: весь файл — тело. Ограничения задокументированы в заголовке файла.
- `LinkIndex.swift` — outgoing-вхождения (файл, диапазон, сниппет строки, номер строки — прицел на переименование в 19), nameTable/pathTable для резолва. Резолв Obsidian-совместимый: регистронезависимо, по имени или пути, при дублях кратчайший путь. `refresh()` инкрементальный по mtime (по FSEvents-тику), `buildFull()` в фоне при открытии vault. `FuzzyMatch` — префикс > подстрока > подпоследовательность.
- Редактор: `MarkdownTextView` (подкласс NSTextView) — автокомплит через штатный completion c переопределённым `rangeForUserCompletion` (иначе имена с пробелами режутся по слову); Cmd+клик и **Cmd+Return** (как в Obsidian, сверх плана) переходят по ссылке; несуществующая цель создаётся (`VaultManager.openWikilink`, пути с «/» создают папки). Подсветка wikilinks акцентным цветом; атрибут .link не используется — обычный клик должен ставить курсор, а не прыгать.
- `BacklinksView.swift` — сворачиваемая панель под редактором: источник + сниппет, клик открывает источник. Обновление по `VaultManager.linkVersion` (LinkIndex — класс, in-place мутации @Published не видны).

Заметки следующим задачам:
- `![[embed]]` парсится как обычная ссылка (embed вне объёма) — это Obsidian-consistent для backlinks; в живом vault нерезолвящиеся цели — почти все `Pasted image*.png` (не .md — не индексируются, норм).
- Автокомплит триггерится из textDidChange → `complete(nil)`; Escape закрывает попап штатно.
- Для задачи 19 (переименование с обновлением ссылок): все вхождения уже с точными NSRange.
