# 32 — Пикер моделей: только доступные, реальные списки

## Цель
Выбор модели прямо из чата без похода в настройки: показываются ТОЛЬКО доступные провайдеры (есть ключ / работает рантайм), и у каждого — реальные модели: Ollama — фактически установленные (из /api/tags, без эмбеддинг-моделей), облако — актуальный кураторский список.

## Зависимости
09 (Ollama), 24 (пикер), 26 (DeepSeek/OpenRouter), 29 («Своя модель…»).

## Объём работ
- [ ] `/api/tags`: парсинг `capabilities`, фильтр `supportsChat` (эмбеддинг-модели не показываются).
- [ ] `ChatViewModel.availableModelChoices()`: доступные провайдеры → секции с моделями; `curatedChatModels` для облака.
- [ ] Пикер: секции по провайдерам с чекмарком текущей модели; недоступные скрыты; «Своя модель…» и «Добавить провайдера…» (→ вкладка «Провайдеры»); подсказка при пустом списке. Редактор «Своя модель…» тоже показывает только доступных.
- [ ] Тесты: парсинг capabilities, фильтр недоступных, кураторские списки.

## Вне объёма
- Живые списки моделей облачных API (у OpenRouter их тысячи) — кураторский список + произвольная строка покрывают кейсы.
- Автозапуск Ollama при выборе модели (бэклог п. 20).

## Критерии приёмки
- `swift build` и `swift test` зелёные.
- Вживую: в пикере только DeepSeek (ключ есть) и Ollama (сервер работает) с реальными установленными моделями; OpenAI/Gemini/OpenRouter без ключей отсутствуют.

## Результат

Сделано (2026-07-18): всё из объёма. Замена пунктов-провайдеров на секции провайдер→модели; выбор недоступного провайдера больше невозможен by design (задача 24 разрешала выбирать недоступных с причиной — новое требование пользователя строже, «нет ключа — нет модели в списке»). Ollama-модели грузятся асинхронно с кэшем в @State и обновляются по availabilityTick (новый ключ/запуск рантайма подхватываются при возврате в окно). Тесты: capabilities/supportsChat, скрытие недоступных, кураторские списки для всех облачных id. 657 тестов зелёные.
