# Задача 70: Deep-link открывает новое окно вместо навигации в существующем

## Тип

баг

## Модель

sonnet

## Цель

Каждый `secondbrain://section/...` открывает новое окно (SwiftUI-сцена), вместо того чтобы
навигировать в уже открытом окне приложения (`tasks/BACKLOG.md` п.36, обнаружено после
задачи 61 — там `ui.sh` починили закрытием лишних окон постфактум, но причину в самом
приложении явно оставили в бэклоге). Пользователь, кликающий несколько deep-link подряд
(или приложение/пайплайн, открывающие несколько ссылок), получает нарастающее число окон.

## Зависимости

Нет.

## Объём

1. Разобраться в `Sources/SecondBrain/App/` — как обрабатывается `secondbrain://` URL
   (`onOpenURL`/`Scene`), почему каждый вызов создаёт новую сцену.
2. Починить: URL должен активировать существующее окно и выполнить в нём навигацию, а не
   создавать новое (если пользователь явно не запросил новое окно — такого сценария сегодня
   нет, поэтому цель — всегда переиспользовать существующее).
3. Тест/трассировка: интеграционный тест по возможности (если логика открытия окна
   тестируема без реального AppKit-рантайма — вынести решающую часть в чистую функцию); если
   нет — обязательная трассировка «deep-link → функция» + ручная проверка через
   `./scripts/ui.sh` (открыть два разных deep-link подряд, убедиться, что окно одно).

## Вне объёма

Сама разметка `ui.sh` (уже почищена в задаче 61), новые URL-маршруты.

## Критерии приёмки

- [x] Два подряд идущих `open "secondbrain://section/..."` с разными разделами оставляют
      ровно одно окно приложения (проверено через `./scripts/ui.sh`, вывод приведён).
- [x] Трассировка «deep-link → функция» задокументирована в файле задачи или комментарием.
- [x] `./scripts/build.sh` и `./scripts/test.sh` зелёные.

## Отчёт тестов

**Что нашёл.** `Sources/SecondBrain/App/App.swift:71-75` — главная сцена объявлена как
`WindowGroup("Second Brain")`. `WindowGroup` — сцена для приложений с несколькими окнами
(документы): каждый входящий Open URL Apple Event (`open "secondbrain://…"`), не совпавший
с уже открытым экземпляром сцены, SwiftUI трактует как запрос новой сцены и создаёт новое
окно — даже когда приложение уже на переднем плане с открытым окном. Само же приложение
одно-оконное (Settings — отдельная сцена `Settings { … }`, для него сценариев множественности
нет). Симптом уже был задокументирован эмпирически в `scripts/ui.sh:73-77`
(`close_extra_windows`) как обходной костыль харнесса, причина явно оставлена в бэклоге п.36
задачи 61 — воспроизвёл тем же способом: `open` двух разных `secondbrain://section/...`
подряд → `System Events … count of windows` даёт 2 (до правки).

**Что починил.** `Sources/SecondBrain/App/App.swift:71-78` — заменил `WindowGroup("Second
Brain") { … }` на `Window("Second Brain", id: "main") { … }` (доступно с macOS 13, минимум
проекта — 14+). `Window` — сцена-синглтон: у неё всегда ровно один экземпляр; повторный Open
URL или повторный `open`/активация не создают новый экземпляр, а активируют существующий и
доставляют событие (`.onOpenURL` на `ContentView`) в него. Это правка причины (тип сцены), а
не симптома: `onOpenURL`-обработчик в `ContentView.swift:84-93` и `DeepLinkParser` не тронуты
— решение (какой раздел/вкладку открыть) как было чистой функцией, так и осталось.

**Трассировка «deep-link → функция».** `open "secondbrain://…"` → macOS Launch Services →
Apple Event Open URL → единственный экземпляр сцены `Window("Second Brain", id: "main")`
(`App.swift:74`, было `WindowGroup`) активируется вместо создания нового → SwiftUI доставляет
URL в `.onOpenURL` на `ContentView` (`ContentView.swift:84`) → `DeepLinkParser.parse(url)`
(`DeepLink.swift:35`, чистая функция, покрыта `DeepLinkTests`) → `selection = section` или
`SettingsTabRouter.open(tab, …)`.

Решение «не открывать новое окно» не вынесено в отдельную чистую функцию: это не
вычисление приложения, а тип SwiftUI-сцены (`Window` vs `WindowGroup`) — рантайм-контракт
AppKit/SwiftUI, недоступный юнит-тесту без реального оконного сервера. Единственная
надёжная проверка — ручная через `./scripts/ui.sh` (см. ниже).

**Что проверил.**
- `./scripts/build.sh` — Build complete, без новых ошибок/варнингов.
- `./scripts/test.sh` — 1100 тестов, 0 падений (совпадает с ожидаемым числом после задачи 69;
  `DeepLinkTests` — все 7 тестов зелёные, парсер не менялся).
- Live-проверка (`./install.sh`, свежая сборка `/Applications/SecondBrain.app`):
  ```
  $ open -a "/Applications/SecondBrain.app"
  $ ./scripts/ui.sh windows
  1                                     # окно приложения после старта
  $ open "secondbrain://section/meetings"
  $ ./scripts/ui.sh windows
  1                                     # было бы 2 до правки (WindowGroup плодил окно)
  $ open "secondbrain://section/chat"
  $ ./scripts/ui.sh windows
  1                                     # второй deep-link подряд — окно всё ещё одно
  $ ./scripts/ui.sh check "Чат"
  PASS  Чат                             # навигация реально произошла в существующем окне
  ```
  После проверки — `./scripts/ui.sh restart`, финально `windows` = 1 (чистое состояние).
- Соседнее поведение: `Settings { … }` — отдельная сцена, не тронута; `SettingsTabRouter`,
  `DeepLinkParser`, обработчики `.onReceive` (открытие заметки из встречи, чата из пайплайна)
  — код не менялся, тесты на них (`DeepLinkTests`, тесты `AppSection`) зелёные.

## Ограничения и бэклог

Ограничений в объёме задачи нет: `Window` — синглтон-сцена, второе главное окно приложение
больше создать не может ни при каком количестве deep-link'ов — сценария «явно запрошенное
второе окно» в продукте сегодня нет (см. цель задачи), поэтому дополнительный guard не нужен.
`scripts/ui.sh` (`close_extra_windows`, `cmd_open`) не трогал — вне объёма (п. «Вне объёма»);
костыль харнесса теперь избыточен (окна не плодятся), но его удаление — отдельная задача, не
эта правка.

## Результат

Главная сцена `App.swift` — `WindowGroup` → `Window("Second Brain", id: "main")`. Deep-link
активирует существующее окно вместо создания нового; проверено живьём (два подряд разных
deep-link → одно окно, навигация проходит), включая незадуманный ревьюером corner-кейс
(закрытие окна и повторный deep-link — окно пересоздаётся, ровно одно). `GO` с первого круга.

Устаревшие после смены типа сцены комментарии (`AppModel.swift:5`, `scripts/ui.sh`) не
трогал — вне объёма, вынесены в `tasks/BACKLOG.md` (пункт 39).
