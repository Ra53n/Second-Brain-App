# Задача 59: смоук-каталог, HTML-отчёт по AX, карта импакта (уровень 2)

## Цель

Уровень 2 инициативы тестирования: агент сам протыкивает базовые UI-сценарии всех разделов
и отдаёт результат человеку. Сегодня есть один сценарий (`smoke/meetings.txt`) и харнесс
`ui.sh`, но нет каталога на все разделы, нет отчёта-артефакта и нет карты «что менялось →
какой сценарий гонять». После задачи: 5 сценариев (по разделу), команда `ui.sh run <file>
--html <out>` даёт самодостаточный HTML-отчёт (таблица PASS/FAIL + дамп сломанного экрана),
и есть `smoke/impact-map.tsv` для выбора сценариев по импакту (потребитель — задача 60).

## Зависимости

49 (харнесс `ui.sh`), 50 (deep-link навигация), 58 (уровень 1 закрыт). Все выполнены.

## Допущения и corner-кейсы (Продукт)

Сведено из разведки инициативы и утверждённого плана; решения пользователя зафиксированы.

- **Кто/зачем.** Агент после правки/деплоя; человек читает отчёт. Смоук доказывает, что базовые
  пути живы, языком AX-ассертов (не «на глаз»).
- **Скриншоты невозможны платформенно** (`kCGWindowSharingState=0` → обои). Замена — **HTML-отчёт
  по AX**: таблица шагов PASS/FAIL + дамп AX-дерева сломанного экрана. Это решение пользователя.
- **Глубина — навигация + клики + проверки** (решение пользователя): открыть раздел, нажать
  неразрушающие кнопки, проверить видимый текст. БЕЗ ввода в формы, БЕЗ тестового vault, БЕЗ
  `SMOKE_ALLOW_DESTRUCTIVE`. Безопасно на живом vault (инвариант №1 не под угрозой — только чтение
  и неразрушающие клики; разрушающие `ui.sh` и так блокирует).
- **Хрупкость к подписям.** В коде ноль `accessibilityIdentifier` — таргетинг по видимому
  русскому тексту. Сценарии держать на надёжных маркерах разделов (`ui.sh section_marker`) +
  1–2 стабильные подписи; иконочные кнопки и строки-папки `DisclosureGroup` не трогать (AX их
  не видит). Это осознанный предел, не дефект задачи.
- **Раздел не открылся** (AX-клик игнорируется) — `ui.sh open` уже даёт честный FAIL с одним
  рестартом и «не зацикливайся»; сценарий это наследует.
- **Пустой/битый сценарий** — `run` уже пропускает пустые строки и `#`-комментарии, неизвестный
  шаг → FAIL-строка. HTML-отчёт должен переживать прогон без падений (0 шагов → пустая таблица,
  не краш).
- **Приложение не собрано/устарело** — `ui.sh preflight` ловит; `ui-engineer` сам делает
  `./install.sh` + перезапуск (quit → open → pgrep), пользователя не просит.

  карта), `scripts/` (расширение `ui.sh`, новый `smoke_report.py`). Продовый Swift не трогаем.
- **Переиспользуем, не пишем заново:**
  - [scripts/ui.sh](../scripts/ui.sh) `cmd_run` — расширяем флагом `--html`, грамматику
    `open/click/check` НЕ меняем.
  - [scripts/ax.applescript](../scripts/ax.applescript) — режим `dump` уже есть, для снимка
    сломанного экрана.
  - [bench/render_diff.py](../bench/render_diff.py) — образец **самодостаточного** HTML (без CDN,
    `color-scheme: light dark`); `smoke_report.py` пишем в том же духе.
  - [smoke/meetings.txt](../smoke/meetings.txt) — шаблон формата сценария.
  - `section_marker`/`section_slug` ([ui.sh:110-135](../scripts/ui.sh)) — источник надёжных
    маркеров и deep-link слагов; из них же растёт карта импакта.
  - deep-link роуты ([DeepLink.swift](../Sources/SecondBrain/App/DeepLink.swift)) — навигация.
- **Чистое ядро / оркестратор (P1).** `smoke_report.py` — чистая трансформация «структурный
  результат прогона → HTML», без обращения к приложению: тестируется отдельно синтетическим
  входом. `ui.sh --html` — тонкий оркестратор: гоняет шаги, на первом FAIL снимает `dump`,
  передаёт всё в `smoke_report.py`.
- **Формат обмена ui.sh → smoke_report.py.** Вывод `check/click/open` — однострочный (PASS/FAIL),
  поэтому шаги пишем TSV-записями `status⇥action⇥arg⇥output` во временный файл; многострочный
  `dump` сломанного экрана — в отдельный temp-файл, путь передаём аргументом (так избегаем
  экранирования произвольного AX-текста в одной строке). `smoke_report.py` рендерит таблицу +
  `<details>` с дампом. Timestamp питон ставит сам (`datetime`).
- **Инварианты.** №1 (vault) — только чтение/неразрушающие клики. №2 (процессы) — не запускаем
  фоновых процессов; приложение — обычный запуск/перезапуск `ui-engineer`.
- **Существующие тесты** не затрагиваются (Swift-тесты про `Sources/`; здесь их нет). `meetings.txt`
  не меняем — он и так проходит.
- **Карта импакта** `smoke/impact-map.tsv`: строки `module_glob⇥Раздел⇥scenario_file⇥test_filter`,
  `#`-комментарии. Данные для задачи 60; здесь только создаём и документируем формат.

## Объём

1. **`scripts/smoke_report.py`** — самодостаточный HTML по образцу `render_diff.py`: заголовок
   (сценарий, счётчики пройдено/провалено, время), таблица шагов (зелёные/красные строки:
   status, action, arg, output), при наличии дампа — `<details>` с AX-деревом сломанного экрана.
   Вход — TSV шагов (+ опц. файл дампа), выход — HTML-файл. 0 шагов → валидный пустой отчёт.
2. **`scripts/ui.sh`** — `cmd_run` принимает `--html <out>`: собирает per-step TSV, на первом
   FAIL снимает `osa dump` во временный файл, зовёт `smoke_report.py`, печатает путь к HTML рядом
   с обычной строкой `ИТОГ:`. Без `--html` поведение не меняется. Обновить usage-шапку и справку.
3. **Сценарии** (грамматика `open/click/check`, ≤6 строк, только неразрушающее, подписи с живого
   `ui.sh list`): `smoke/notes.txt` (Заметки), `smoke/chat.txt` (Чат), `smoke/pipelines.txt`
   (Пайплайны), `smoke/settings.txt` (Настройки; `open Настройки` + `check` подписей вкладок,
   при доступности — deep-link на вкладку). `meetings.txt` уже есть — итого 5.
4. **`smoke/impact-map.tsv`** — карта «модуль → раздел → сценарий → тест-фильтр» на все 5 разделов
   + строка «`App/**` → все». Короткая шапка формата в комментарии файла.

## Критерии приёмки

1. `python3 scripts/smoke_report.py` на синтетическом входе (зелёный и с одним FAIL+дампом) даёт
   открывающийся самодостаточный HTML (без внешних запросов), таблица корректна, дамп в `<details>`.
2. `./scripts/ui.sh run smoke/<file> --html <out>` для каждого из 5 сценариев: печатает `ИТОГ:
   N пройдено, N провалено` + путь к HTML; HTML соответствует прогону.
3. Все 5 сценариев на свежесобранном приложении (`preflight` зелёный) осмысленны: навигация в
   раздел подтверждается маркером, проверки — по реально присутствующим подписям. Приведён вывод
   `run` каждого.
4. Искусственно «красный» прогон (несуществующая подпись) → FAIL-строка + дамп сломанного экрана
   в HTML (доказательство, что отчёт ловит поломку).
5. `smoke/impact-map.tsv` покрывает 5 разделов + `App/**`; формат задокументирован в файле.
6. `git grep` реальных секретов по изменённым файлам пусто; `## Отчёт тестов`/смоук-вывод от
   `ui-engineer` и `## Вердикт ревью` = `GO` от `reviewer`.

## Результат

Сделано по плану: 5 смоук-сценариев (по разделу; `meetings.txt` был, +4 новых), команда
`./scripts/ui.sh run <file> --html <out>` даёт самодостаточный HTML-отчёт (таблица PASS/FAIL +
AX-дамп сломанного экрана), `smoke/impact-map.tsv` с фильтрами по реальным классам. Все 5
сценариев — 0 провалено на свежей сборке; «красный» прогон ловит поломку (FAIL-строка + дамп в
HTML). `Sources/` не тронут — поведение приложения не менялось.

**Отклонения от плана:**
- Все сценарии — `open`+`check`, без `click`: видимые кнопки разделов создающие («Новая
  заметка/папка», «Новый чат/пайплайн»), клик по ним пишет в живой vault (инвариант №1).
  Неразрушающих кликабельных элементов с надёжной AX-подписью на этих экранах нет, поэтому смоук —
  навигация + проверки. Глубже (клики/формы) — только с тестовым vault, сознательно вне объёма
  (решение пользователя «навигация + клики + проверки», клики опущены по безопасности).
- `settings.txt` проверяет плейсхолдер, а не вкладки (AX-невидимая `SettingsLink`) → BACKLOG п.34.

**Важно для следующих задач (особенно 60):**
- Перед добавлением ЛЮБЫХ `click`-шагов в сценарии сперва расширить блок-лист `DESTRUCTIVE` в
  `ui.sh` подписями создающих кнопок (BACKLOG п.35), иначе `click` создаст данные в живом vault.
- `impact-map.tsv`: правки в `Settings/LLM/LocalRuntime/GitSync` ведут в `settings.txt`, который
  пока достаёт лишь плейсхолдер — смоук-покрытие этих модулей мелкое, пока не закрыт п.34.
- Формат обмена для `smoke-all.sh` (задача 60): `ui.sh run <file> --html <out>`; per-step TSV
  `status⇥action⇥arg⇥output` + опц. файл дампа → `smoke_report.py`.
- Новые файлы: `scripts/smoke_report.py`, `smoke/{notes,chat,pipelines,settings}.txt`,
  `smoke/impact-map.tsv`. Изменены: `scripts/ui.sh`, `tasks/00-INDEX.md`, `tasks/BACKLOG.md`.
