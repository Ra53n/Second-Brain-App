# Задача 60: цикл прогона — smoke-all, скилл /smoke-cycle, интеграция в конвейер

## Цель

Замкнуть двухуровневое тестирование в петлю, которую агент выполняет сам после правки/PR:
одна команда прогоняет по импакту код-тесты и UI-смоук, собирает единый отчёт (текст + HTML),
при падении подсказывает вероятное место; скилл описывает суждения и три точки входа, включая
«я задеплоил фичу — обнови смоук и прогони». Уровни 1 и 2 (задачи 58, 59) уже есть — здесь их
оркестровка.

## Зависимости

58 (код-тесты, `scripts/test.sh`), 59 (смоук-каталог, `ui.sh run --html`, `smoke/impact-map.tsv`,
`smoke_report.py`). Обе выполнены.

## Допущения и corner-кейсы (Продукт)

- **Кто/зачем.** Агент (техлид) после каждого содержательного изменения/PR. Человек получает
  единый отчёт и, при падении, указание куда смотреть.
- **Выбор по импакту** (решение пользователя). Источник — `smoke/impact-map.tsv` (задача 59):
  изменённые пути `Sources/**` → разделы (сценарии) + тест-фильтры. Правок вне `Sources/` (доки,
  tasks, сами скрипты) → кода не касается: смоук не нужен, честно сообщить.
- **Широкий diff / `App/**`** — навигационное ядро, затрагивает всё → полный прогон (все сценарии
  + полный `test.sh`), не выборочный.
- **Нет изменений** (пустой diff) → сообщить «нечего гонять», выйти 0.
- **Приложение не собрано/устарело** — `ui.sh preflight` ловит; смоук-часть честно репортит
  «сборка устарела: ./install.sh», тесты всё равно гоняются (они не зависят от .app).
- **Падение.** Единый отчёт различает: упал тест (какой — из `test.sh`) vs упал сценарий (какой
  шаг/раздел). Локализация — из карты импакта: раздел S сломан → вероятные модули (обратная
  сторона карты). Не «чинит», а указывает место (шаг 3 цикла пользователя).
- **Безопасность живого vault.** Смоук — только существующие `check`-сценарии (read-only). ДО
  добавления любых `click`-шагов в каталог — сперва расширить блок-лист `DESTRUCTIVE` (BACKLOG
  п.35). В этой задаче новых кликов не вводим.
- **«Задеплоил фичу»** (шаг 5) — точка входа скилла: обновить/дописать сценарий под новую фичу,
  затем полный прогон. Дописывание сценария — по образцу задачи 59 (навигация + `check`).

## Архитектура

- **Куда ложится.** `scripts/smoke-all.sh` (механика), `.claude/skills/smoke-cycle/SKILL.md`
  (суждение), правки процесса в `.claude/skills/task-verify/SKILL.md`, `.claude/skills/task-close/SKILL.md`,
  `CLAUDE.md`. `Sources/` не трогаем.
- **Разделение «механика/суждение»** (решение пользователя, дух репо): скрипт делает
  детерминированное (diff → выбор → прогон → агрег′ация → коды выхода), скилл — недетерминированное
  (что считать импактом в спорном случае, как локализовать, как дописать сценарий).
- **Переиспуемое:** `scripts/test.sh` (`--filter`), `scripts/ui.sh run --html`, `smoke/impact-map.tsv`,
  `scripts/smoke_report.py` (все из 58/59); формат отчёта — `ИТОГ:` строки + HTML-пути; шаблон
  скилла — существующие `.claude/skills/*/SKILL.md` (frontmatter name/description + тело).
- **Чистое ядро/оркестратор.** Ядро выбора (diff+карта → множества сценариев и фильтров) —
  детерминированная функция bash, покрывается `--dry-run` без приложения. Оркестратор — запуск
  внешних скриптов и агрегация.
- **Инварианты.** №1 — смоук read-only (check-сценарии). №2 — фоновых процессов не плодим.
- **Существующие тесты/поведение** не затрагиваются: `smoke-all.sh` только зовёт готовые скрипты.

### Интерфейс `scripts/smoke-all.sh`
```
smoke-all.sh [base-ref] [--full] [--dry-run] [--out <dir>]
  base-ref  — git-ref для diff (умолчание: main; если HEAD уже main → HEAD~1)
  --full    — форсировать полный прогон (все сценарии + полный test.sh)
  --dry-run — только показать выбор (тесты/сценарии/режим), ничего не гонять (для проверки без .app)
  --out     — куда класть HTML (умолчание: каталог отчётов, напр. scratchpad/ или out/)
```
Шаги: (1) `git diff --name-only <base>` (+ working-tree); (2) отфильтровать `Sources/**`,
смапить по `impact-map.tsv` в множество сценариев + объединённый тест-фильтр; `App/**` или
широкий разброс → режим full; (3) тесты: `test.sh` (полный или `--filter <regex>`); (4) `preflight`,
затем `ui.sh run smoke/<X> --html <out>/<X>.html` по каждому сценарию; (5) единый отчёт (итоги
тестов, `ИТОГ:` по сценариям, пути HTML) + при падении строки-локализации; (6) exit≠0 при любом
падении.

## Объём

1. **`scripts/smoke-all.sh`** — по интерфейсу выше: выбор по импакту, режим full, `--dry-run` и
   `--out`, прогон `test.sh`+`ui.sh`, единый текстовый отчёт, локализация падения, коды выхода.
2. **`.claude/skills/smoke-cycle/SKILL.md`** — скилл с тремя точками входа:
   - (1-3) после правки: выбрать по импакту (`smoke-all.sh`), прогнать, при падении назвать
     место (карта) и предложить вероятную причину;
   - (4) после PR: `smoke-all.sh` → единый отчёт → **дописать/обновить сценарий** под новую фичу;
     HTML показать пользователю (`SendUserFile`, render);
   - (5) «задеплоил фичу — обнови смоук и прогони»: обновить каталог + полный прогон.
   Плюс правила безопасности (только неразрушающее; перед `click` — BACKLOG п.35) и краткий
   разбор `impact-map.tsv`.
3. **Интеграция в конвейер:** в `.claude/skills/task-verify/SKILL.md` — шаг «смоук по импакту
   через `smoke-all.sh` + приложить HTML» (согласовать с существующим §UI-смоук, не дублировать);
   в `.claude/skills/task-close/SKILL.md` — шаг «обновить/дописать сценарий под сделанное»; в
   `CLAUDE.md` — строка `/smoke-cycle` в таблице «Скиллы» и упоминание цикла в «Конвейере».

## Вне объёма

- Правка `Sources/`; новые `click`/форм-сценарии; расширение блок-листа (BACKLOG п.35);
  углубление settings (BACKLOG п.34).
- CI/GitHub Actions, git-хуки, деплой-скрипт, авто-триггер (цикл ручной — запускает агент).
- Новые UI-разделы/сценарии сверх пяти (кроме демонстрации «дописать сценарий» в скилле).

## Критерии приёмки

1. `scripts/smoke-all.sh --dry-run <base>` на синтетическом diff (правка в `Meetings/`) выбирает
   ТОЛЬКО сценарий Встреч и Meeting-тесты; на diff с `App/**` — режим full; на diff без `Sources/`
   — «нечего гонять».
2. Реальный `smoke-all.sh` (по последнему коммиту) прогоняет выбранные тесты + сценарии, печатает
   единый отчёт с итогами и путями HTML; exit-код отражает успех/провал.
3. Подставное падение (сценарий с несуществующей подписью или временно сломанный тест) → в отчёте
   видно, ЧТО упало, и строка-локализация «раздел/модуль»; HTML сломанного сценария приложен.
4. `/smoke-cycle` описывает три точки входа и правила безопасности; `task-verify`/`task-close`/
   `CLAUDE.md` ссылаются на цикл без дублирования существующих шагов.
5. `git grep` реальных секретов по изменённым файлам пусто; `## Отчёт`/смоук-вывод и `## Вердикт
   ревью` = `GO` от `reviewer`.
