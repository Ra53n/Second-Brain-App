# Задача 106: авторизация, чаты per-user, админ-логи/алерты в чате /chat/

## Тип

фича

## Модель

малая-плюс: изменения в изолированном сервисе `harness/`, порт готового каркаса из
`support/` (пользователи, сессии, изоляция). Техлид сам + `reviewer`.

## Цель

Сейчас чат `/chat/` публичный, чаты общие. Нужно: логин+пароль (регистрация), у каждого
пользователя свои чаты (изоляция), админка — логи всех пользователей и алерты (как
`gw/admin` «только перехваты»); админ — пользователь с ролью. Плюс аудит на баги.

## Зависимости

- 105 (чат /chat/) — база.

## Допущения и corner-кейсы

- Каркас авторизации портируется из `support/` (scrypt-пароли, opaque cookie-сессии, sha256
  в БД, `ownerClause`, `Principal`, CSRF `checkOrigin`) — не изобретается.
- Регистрация открытая; **первый зарегистрированный пользователь = админ** (или
  `username === HARNESS_ADMIN_USER`). Владелец регистрируется первым после деплоя.
- Чат требует входа — анонимных чатов нет; `chats.user_id NOT NULL`.
- Изоляция: чужой ресурс → пусто/404, не 403 (не раскрываем существование).
- Найден и чинится баг: `GET /chat/messages/:id` отдавал любое сообщение по UUID любому.
- Админ-эндпоинты: session с is_admin ИЛИ break-glass bearer `HARNESS_API_TOKEN`.
- Алерт сообщения (денормализован для SQL-фильтра): pwned | Critical/High | перехват
  gateway | blocked | отказ модели.
- Миграция **аддитивная** (v2 поверх v1 задачи 105): deploy БД НЕ сносит — аккаунты
  переживают редеплой. Старые анонимные чаты 105 (без владельца) v2 пересоздаёт.

## Архитектура

- Новые: `src/auth/{passwords,authService}.ts`, `src/store/usersRepo.ts`,
  `src/http/{routes.auth,auth}.ts`. `computeAlerts` — в `src/domain/chat.ts` (рядом с
  моделью сообщения).
- Схема БД `src/store/db.ts`: `users`, `user_sessions`, `chats.user_id`, `messages.alert`/
  `alert_kinds`; `foreign_keys = ON`.
- `chatsRepo`: `ownerClause`, owner-параметр во всех методах, `getMessageForOwner`, admin-
  выборки (`listAllChats`, `listAllMessages`, `adminStats`), запись alert-флагов.
- `authMiddleware`: `Principal`, `ownerScope`, `requireUser`, `requireAdmin`.
- `chatManager`/`orchestrator`: owner + запись alert при финализации.
- web: логин/регистрация overlay, `/auth/me`, logout, ссылка «Админка» для is_admin;
  админ-страница с алертами + автообновлением (порт UI `gateway/web`).
- Зависимость `@fastify/cookie`; env `SESSION_SECRET` (обязателен), `HARNESS_ADMIN_USER`.

## Критерии приёмки

1. Регистрация/логин/логаут работают; пароль хранится только scrypt-хешем; сессия в
   httpOnly signed cookie; первый пользователь — админ.
2. Чат требует входа; у каждого пользователя свои чаты; пользователь A не видит/не
   поллит/не удаляет чат и сообщение B (list/get/patch/delete/messages/poll → пусто/404).
3. Админка (роль is_admin): список пользователей, логи всех чатов/сообщений, фильтр
   «только алерты», автообновление; break-glass bearer тоже пускает.
4. Алерт помечается при pwned/Critical-High/перехвате gateway/blocked/отказе.
5. Регрессия: чат, накопление контекста, loop, security-провокации, инъекция/эксфильтрация
   работают под сессией; существующие тесты зелёные.
6. `git grep` секретов пуст; паролей/токенов/адресов VPS в диффе нет.

## Отчёт тестов

- `npm test` (vitest): **90 тестов зелёные**, typecheck чист.
  - authService/passwords: scrypt хеш/сверка, битый хеш, регистрация (первый=админ,
    HARNESS_ADMIN_USER, дубликат, короткие), **атомарность роли** (два параллельных
    первых → ровно один админ), логин, сессия/отзыв/TTL.
  - authMiddleware (HTTP-слой): requireUser (cookie пускает, аноним 401, только bearer
    не пускает на user-эндпоинт, неверный bearer 401), requireAdmin (админ пускает,
    юзер 403, break-glass bearer, аноним 401), checkOrigin (нет Origin → пропуск,
    совпал → пропуск, чужой → бросок).
  - chatsRepo: изоляция (listChats только свои; getChat/deleteChat/rename/setMode
    чужого → null/false; **getMessageForOwner чужого → null — фикс бага поллинга**;
    каскад удаления), alert-колонки + admin-выборки, `decodeKinds` (битый JSON → []),
    **миграция v1(105)→v2** (старая схема → users+user_id+alert), computeAlerts (все ветки).
  - chatManager: обычный/loop под owner, накопление контекста, **изоляция двух
    пользователей** (A не видит/не поллит/не удаляет/не пишет в чат B), канарейка→pwned→
    алерт виден в admin.
- **Живой смоук на VPS** (реальный gateway): регистрация owner(admin)+tester; накопление
  контекста («запомни 42» → «42»); изоляция (tester GET/poll чат owner → 404); админ
  видит логи всех + фильтр «только алерты» (tester-провокация → `gateway-intercept+
  refusal`, видна с username); tester→админка 403; break-glass bearer 200; аноним 401;
  logout закрывает доступ; миграция БД дала `user_version=2` и таблицы users/sessions/
  chats/messages.

## Security-вердикт

Отдельный субагент-аудит (auth/isolation). NO-GO в первом круге: (1) миграция была
переписана «на месте» — не обновляла БД задачи 105; (2) security-слой без HTTP-тестов;
(3) гонка «первый=админ». Исправлено: миграция стала аддитивной v2 (deploy БД не сносит,
аккаунты переживают редеплой; тест v1→v2); добавлены HTTP-тесты авторизации и CSRF; роль
админа решается атомарно (транзакция count+insert). Проверено: изоляция на всех
эндпоинтах (owner из сессии, чужое → 404 не 403), scrypt+timingSafe+фиктивный хеш,
sha256-сессии/TTL/отзыв, cookie httpOnly/secure/sameSite=strict/signed, checkOrigin на
мутациях, FK-каскады, SQL только в репозиториях, секретов/паролей в диффе нет (только
scrypt-хеш). **Critical/High после фиксов — нет.**

## Вердикт ревью

**GO** (после устранения NO-GO). 90 тестов, миграция аддитивна и протестирована,
security-слой покрыт, гонка админа закрыта, checkOrigin на всех мутациях. Живой смоук
на VPS подтвердил изоляцию, роли и алерты.

## Результат

Чат `/chat/` получил авторизацию: регистрация/логин/логаут (scrypt-пароли, httpOnly
signed cookie-сессии, sha256 в БД, TTL 30д, отзыв). Чаты изолированы по владельцу
(`ownerClause`, owner из сессии на каждом эндпоинте; фикс бага утечки сообщения по UUID).
Админка — по роли is_admin (первый зарегистрированный = админ, либо HARNESS_ADMIN_USER;
break-glass bearer сохранён): логи всех пользователей, список пользователей, статистика,
фильтр «только алерты» (pwned/Critical-High/перехват gateway/blocked/отказ) с
автообновлением — по образцу `gw/admin`. Каркас портирован из `support/`. Миграция
аддитивная (v2), деплой аккаунты не сносит. 90 тестов, живой смоук на VPS зелёный.

Для входа: владелец регистрируется первым на `https://<VPS_HOST>/chat/` → получает роль
админа и ссылку «админка». Секреты (SESSION_SECRET, канарейка, admin-токен) — в
`/etc/llm-harness.env`, в git плейсхолдеры.
