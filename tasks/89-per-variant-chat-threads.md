# Задача 89: раздельные треды чата тюнинга по вариантам модели

## Тип

фича

## Модель

Fable 5

## Цель

Сейчас чат тюнинга один на обе модели: переключатель «Базовая/Тюн» меняет модель под
капотом, но история, тумблеры пайплайна и статистика сессии общие — сравнить варианты
по статистике невозможно (фидбэк пользователя). Нужно: у каждого варианта свой тред —
своя история сообщений, свой набор тумблеров пайплайна, своя статистика. Переключатель
варианта переключает всё сразу; «Очистить чат» чистит только активный тред.

## Зависимости

85, 86, 87, 88 (все `[x]`).

## Допущения и corner-кейсы

- Персистентность: `TuningChatDocument` → `threads: [variant → TuningChatThread]`, где
  `TuningChatThread { messages, pipelineConfig }` + `modelVariant` (активный). P2:
  снисходительный декод, **миграция старого плоского документа**: прежние `messages`
  целиком уезжают в тред сохранённого `modelVariant` (истории не теряются; по-вариантное
  расщепление по `message.modelVariant` не делаем — user-сообщения варианта не имеют,
  пары рвать нельзя), прежний `pipelineConfig` копируется в оба треда. Тест миграции
  обязателен + round-trip нового формата.
- Незнакомый вариант в ключе треда («значение из будущего») — тред сохраняется как
  есть (round-trip без потерь), декод не падает, известные треды работают.
- Переключение варианта во время генерации невозможно (кнопки уже disabled при
  `isGenerating`) — инвариант сохраняется.
- Статистика, тумблеры, история, заглушка пустого треда — всё от активного треда.
  Заголовок панели — «Статистика сессии — Базовая/Тюн», чтобы на записи видео было
  видно, чья статистика на экране; то же в `accessibilityValue`.
- «Очистить чат» — только активный тред (подпись/тултип уточнить); отмена генерации
  как раньше.
- Батч-секция без изменений: артефакты и так по-вариантные файлы.
- Сообщения в треде «Базовая» остаются видны при переключении на «Тюн» и обратно —
  ничего не теряется, треды независимы.

## Архитектура

- `TuningChatStore`: `TuningChatThread: Codable` (messages + pipelineConfig),
  `TuningChatDocument { threads: [String: TuningChatThread]; modelVariant }`,
  миграция в `init(from:)` документа (старые ключи `messages`/`pipelineConfig` —
  `decodeIfPresent` → тред активного варианта). Ключи словаря — rawValue варианта.
- `TuningChatViewModel`: источник истины — `threads`; `messages`/`pipelineConfig` —
  проекции активного треда (computed или синхронизируемые при переключении варианта —
  выбрать при реализации, но точка записи одна); `sessionStats` от активного треда;
  `send()`/`clearChat()`/`setPipelineConfig()` работают с активным тредом; смена
  `modelVariant` — переключение проекций + `persistNow()`.
- UI (`FineTuneChatViews`): без структурных изменений — список/тумблеры/панель уже
  читают VM; добавить вариант в заголовок панели статистики и value.

## Объём

- `Sources/SecondBrain/FineTune/TuningChatStore.swift` — треды + миграция.
- `Sources/SecondBrain/FineTune/TuningChatViewModel.swift` — проекции активного треда.
- `Sources/SecondBrain/FineTune/FineTuneChatViews.swift` — заголовок панели с вариантом.
- Тесты: миграция старого документа, round-trip, независимость тредов (история/конфиг/
  статистика), очистка только активного, «вариант из будущего» в ключе.

## Вне объёма

- Сравнение двух статистик на одном экране (side-by-side) — отдельная задача при
  необходимости; батч-раннер; ядро Confidence.

## Критерии приёмки

1. Переключение «Базовая/Тюн» меняет историю, тумблеры и статистику на свои для
   варианта; обратное переключение возвращает всё без потерь.
2. Старый `finetune-chat.json` мигрирует: история в тред активного варианта, конфиг
   в оба; ничего не теряется (тест).
3. «Очистить чат» чистит только активный тред (тест: второй тред цел).
4. Заголовок панели и `accessibilityValue` включают имя варианта.
5. `./scripts/build.sh`, `./scripts/test.sh` зелёные; ревью GO.

## Отчёт тестов

Стадия тестирования (в составе coder + доводка ревью): миграция плоского документа
(история → тред активного варианта, конфиг в оба, `{}` не раздувается), round-trip
нового формата с двумя тредами, незнакомый ключ треда переживает decode и encode,
независимость тредов (send в baseline не трогает tuned — мок-провайдер), переключение
варианта туда-обратно без потерь, clearChat чистит только активный тред (память +
диск), setPipelineConfig пишет только в активный тред; по замечанию ревью добавлена
защита `didSet` при генерации (программная смена варианта отменяет прогон, ответ не
падает в чужой тред) + тест. Адаптированы decode-regression тесты и мок сервера
(health следит за isRunning процесса — после stopNow порт снова «свободен»).

Итог `./scripts/test.sh`: **1626 тестов, 0 падений, 1 пропущен** (live-harness).

## Вердикт ревью

GO (блокирующих нет). Важные закрыты до коммита: P5-защита в `didSet` (не полагаться
на disabled-кнопки), секция «Отчёт тестов», критерий 4 (AX) — задокументированный хвост
сред 85–88: смоук-сценарий готов, прогнать после выдачи разрешения Accessibility.
Мелочи (английское слово в комментарии, формулировка допущения, комментарий миграции
«из будущего») — исправлены.

## Результат

У каждого варианта модели («Базовая»/«Тюн») свой тред: история, тумблеры пайплайна и
статистика сессии раздельны; переключатель меняет весь контекст, «Очистить чат» чистит
только активный тред. Заголовок панели и AX-value включают имя варианта. Старый
`finetune-chat.json` мигрирует без потерь (история — в тред активного варианта, конфиг
в оба). Хвост: AX-смоук вкладки по `smoke/finetune.txt` после выдачи разрешения
Accessibility (как в 85–88).
