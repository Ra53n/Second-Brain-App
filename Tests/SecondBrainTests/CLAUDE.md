# Тесты — правила

1028 тестов на ~28 тыс. строк. Тесты — часть определения готовности: задача без тестов на
новую core-логику не считается выполненной.

## Что покрываем и что нет

**Покрываем:** FSM и таблицы переходов, парсеры, миграции, чанкинг и индексы,
сериализацию DTO, роутинг, классификаторы, чистые вычисления, чистую логику UI-моделей
(что показать, что предвыбрать), регрессии живых багов.

**Не покрываем:** SwiftUI-вёрстку, `NSViewRepresentable`, реальную сеть, Core Audio,
живое железо. Это проверяется смоуком (`/smoke-ui`) и честно фиксируется в «Результате»
задачи как проверенное вручную.

## Обязательные правила

1. **Ноль сети.** Реальные ответы API — в `Fixtures/`, транспорт инжектируется, LLM —
   `MockProviders`, эмбеддер — `HashingEmbedder`, SQLite — `:memory:`.
2. **Ноль зависимости от машины разработчика.** Тест не должен читать `routing.json`,
   `settings.json`, живой vault или репозиторий проекта: у другого человека они другие
   (урок задачи 33 — тесты роутинга падали из-за пользовательского конфига). Пути и
   сторы инжектируются, файлы создаются в temp-директориях и убираются за собой.
3. **Тест миграции на каждое новое persisted-поле.** Старый JSON без поля обязан грузиться
   с дефолтом. Это ловит реальные потери данных пользователя.
4. **Регрессия получает свой файл с описанием симптома** в заголовке — как
   `ConcealablesCrashRegressionTests` (номер крашлога, причина, почему так починено).
   Через полгода это единственное, что объясняет странный код.
5. **Таблицы случаев циклом** с подписью в ассерте, чтобы из отчёта было видно, какой
   случай упал: `XCTAssertEqual(actual, expected, name)`. Эталон — `ToolPermissionsTests`.
6. **Граничные значения обязательны:** пусто, один элемент, лимит, лимит+1, кириллица,
   эмодзи, битый ввод, «значение из будущего» в декодере.

## Как запускать

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift test
swift test --filter ToolPermissionsTests   # один класс
```

Полный Xcode toolchain обязателен — с Command Line Tools `swift test` не соберётся.

## Наименование

Файл `<Тема>Tests.swift` (зеркалит модуль), класс `final class ТемаTests: XCTestCase`,
метод `testЧтоИменноПроверяем` — имя описывает поведение, а не имя функции под тестом.
Заголовок файла перечисляет, что покрыто, по критериям приёмки задачи.

## Куда не лезть

Не подгоняй продовый код под тест и тест под код: если для проверки нужен доступ к
приватному состоянию — вероятно, логику надо вынести в чистую функцию (P1), а не
открывать внутренности.
