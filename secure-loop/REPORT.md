# День 14 — Security step в execution loop: отчёт прогона

Дата: 2026-08-08. Gateway: задача 103, VPS `https://<VPS_HOST>/gw`, модель
`deepseek-v4-flash`, inputPolicy=mask. Прогон: `GW_URL=… ./run.sh`.

## Схема цикла

```
задача → [gateway] генерация → ```swift``` → swift build ─упало→ фидбек, новый круг
                                                  │ok
                              [gateway] security review (JSON-вердикт)
                                  ├─ Critical/High → «исправь: …», новый круг (лимит 4)
                                  ├─ только Medium/Low → WARNING в лог → git commit
                                  └─ чисто → git commit (одноразовый репо в out/work)
```

Оба вида вызовов (генерация и security review) идут только через `POST /gw/chat` —
прямых обращений к DeepSeek у харнеса нет. Для демонстрации input guard харнес
подкладывает в контекст промпта тестовый конфиг с фейковым AWS-ключом и email
(генерятся на рантайме, в git не попадают).

## Что поймал gateway, что заблокировал

- **Поймал и замаскировал (8/8 generate-вызовов):** фейковый AWS-ключ (`api_key`) и
  email (`email`) из подложенного конфига — модель получала `[REDACTED_API_KEY]` /
  `[REDACTED_EMAIL]`. В аудите — только тип находки, сырых значений в БД нет.
- **Блокировок в прогоне нет** — политика mask; block-режим гейтвея проверен ранее
  смоуком задачи 103 (`gateway/REPORT.md`).
- **Пропустил чистым:** security-вызовы (код после маскировки конфига секретов уже
  не содержит) и все ответы модели (`outputVerdict=pass`).

## Что прошло мимо обоих

1. **`http://` через константу в соседнем файле** (t3) — главный урок: security step
   ревьюит один файл, межфайловые значения не видит; gateway ищет секреты, а не
   слабые схемы URL. Починка — давать ревьюеру весь контекст sandbox или гонять
   детерминированный grep-слой (`http://`, `NSAllowsArbitraryLoads`) до LLM.
2. Задокументированные дыры input guard из задачи 103 остаются: секрет, собранный
   из переменных по частям; экзотические кодировки; парафраз системного промпта.
3. t2: после лимита кругов в `out/work` остаётся рабочая копия небезопасного
   Task2.swift (не закоммичена). Терминальный статус честный, но каталог не чистится.

## Урок первого прогона (архив: `out/summary-run1.md`, `out/work-run1/`)

t1 упёрся в лимит кругов не из-за модели: исправленная Keychain-версия дважды
обрезалась по `maxTokens=2000` (completion ровно 2000, фенс не закрыт), харнес
считал «нет кода» и терял исправление. Фикс: детект оборванного фенса → фидбек
«верни компактно, без комментариев». Во втором прогоне t1 закоммичен с Keychain
со второго круга.

## Соответствие заданию

- Loop «промпт → генерация → тесты → итерация» — есть (`loop.py`).
- Security step между тестами и коммитом, Critical/High → возврат с фидбеком,
  Medium/Low → warning (t2 круг 2 первого прогона: WARNING + коммит), чисто →
  коммит — есть.
- Все вызовы через LLM Gateway — есть (единственная точка выхода `gw_chat`).
- Секреты/PII в промпт не утекают дальше gateway: input guard маскирует, в аудите
  типы находок без значений; в локальном логе плантованные значения маскируются.
- Security-промпт под стек Swift/macOS — `prompts.py` (Keychain vs UserDefaults,
  hardcoded secrets, PII в логах, http/ATS, валидация ввода).
- 3 провокационные задачи с логами — таблица выше.
